1. Supervised Learning

تعریف

در Supervised Learning، ما داده‌ای داریم که برای هر ورودی X، خروجی یا Label Y را هم می‌دانیم.

یعنی Dataset داریم:

$$D = \{ (x_i, y_i) \}_{i=1}^n$$

و می‌خواهیم تابعی یاد بگیریم:

$$f: X \rightarrow Y$$

که روی داده‌های جدید:

$$\hat{y} = f(x)$$

پیش‌بینی خوبی داشته باشد.

مثال Classification

تشخیص Fraud:

Transaction │ ├── amount ├── country ├── device ├── time └── ... ↓ Model ↓ P(Fraud | X) ↓ Fraud / Normal

اینجا:

X = Transaction Features Y = Fraud / Normal
مثال Regression

پیش‌بینی قیمت:

X = [size, rooms, location, age] Y = price

مدل:

$$f(X) \rightarrow Price$$
دو نوع اصلی
Classification
$$Y \in \{0, 1, ..., K\}$$

مثلاً:

Fraud / Normal Cat / Dog Spam / Not Spam
Regression
$$Y \in \mathbb{R}$$

مثلاً:

Price Temperature Revenue Demand
نکته Senior

هدف Supervised Learning صرفاً این نیست که:

Training Data را خوب fit کنیم.

هدف واقعی:

Generalization

یعنی روی نمونه‌ای از همان Distribution که مدل ندیده است خوب عمل کند.

این دقیقاً ما را به:

Bias / Variance / Generalization Error

می‌رساند.

2. Unsupervised Learning

اینجا Label نداریم.

Dataset:

$$D = \{ x_1, x_2, ..., x_n \}$$

و مدل باید ساختار موجود در X را پیدا کند.

مثال Clustering

فرض کن رفتار مشتریان را داری:

Customer ├── spending ├── frequency ├── age └── transaction_count

اما نمی‌دانی مشتری‌ها چه گروه‌هایی دارند.

می‌توانی:

K-Means

اجرا کنی:

Dataset │ ▼ K-Means │ ├── Cluster 1 → High-value customers ├── Cluster 2 → Low-value customers └── Cluster 3 → Occasional customers

مدل خودش ساختار را پیدا می‌کند.

انواع مهم Unsupervised Learning
Clustering
K-Means DBSCAN HDBSCAN GMM Hierarchical Clustering
Dimensionality Reduction
PCA SVD UMAP t-SNE
Density Estimation

یادگیری:

$$P(X)$$
Anomaly Detection

پیدا کردن نمونه‌هایی که با Distribution اصلی متفاوت‌اند.

نکته مهم

Unsupervised Learning الزاماً یعنی:

«داده بدون هیچ اطلاعاتی»

نیست.

بلکه یعنی Label صریح Y نداریم.

3. Semi-Supervised Learning

این یکی بین Supervised و Unsupervised قرار دارد.

فرض کن:

100,000 samples

داری ولی فقط:

1,000 labeled 99,000 unlabeled

داریم.

Dataset │ ┌────────┴────────┐ │ │ Labeled Unlabeled 1,000 99,000 │ │ └────────┬────────┘ ↓ Semi-Supervised
چرا مهم است؟

Label کردن داده ممکن است گران باشد.

مثلاً:

Medical Imaging Fraud Detection Legal Documents Speech Phishing URLs

ممکن است میلیون‌ها نمونه داشته باشی ولی Label کردن آنها توسط انسان هزینه‌بر باشد.

روش‌های رایج
Pseudo-Labeling

مدل روی داده بدون Label prediction می‌زند:

Unlabeled X ↓ Model ↓ P(Y|X) = 0.99 ↓ Pseudo Label = Y

بعد آن را به Training Data اضافه می‌کنیم.

Consistency Regularization

ایده:

اگر ورودی را کمی تغییر بدهیم:

X ↓ Model ↓ P(Y|X)

و:

Augmented X ↓ Model ↓ P(Y|X')

پیش‌بینی‌ها باید مشابه باشند.

نکته Senior

Semi-Supervised Learning وقتی خوب کار می‌کند که:

Unlabeled Data واقعاً از همان یا Distribution مرتبط با مسئله آمده باشد.

اگر Unlabeled Data کاملاً متفاوت باشد، ممکن است عملکرد بدتر شود.

4. Self-Supervised Learning

یکی از مهم‌ترین مفاهیم ML مدرن.

در Self-Supervised Learning، Label را خود داده تولید می‌کند.

یعنی:

Raw Data ↓ Construct Training Task ↓ Pseudo Target ↓ Train Model
مثال کلاسیک NLP

جمله:

The cat is sitting on the ___

مدل باید:

mat

را پیش‌بینی کند.

در اینجا کسی Label نزده.

خود متن Target را فراهم کرده.

مثال LLM

در Language Modeling:

$$P(x_t | x_1, ..., x_{t-1})$$

مدل Token بعدی را پیش‌بینی می‌کند.

مثلاً:

I love machine

Target:

learning
Masked Language Modeling

مثلاً:

The cat is [MASK] on the mat.

مدل باید:

sitting

را پیش‌بینی کند.

BERT از این ایده استفاده کرد.

تفاوت Semi-Supervised و Self-Supervised

خیلی مهم:

Semi-Supervised

داریم:

Labeled + Unlabeled
Self-Supervised

Label از خود داده ساخته می‌شود:

Data ↓ Automatically generated target

پس Self-Supervised معمولاً یک روش ساخت سیگنال آموزشی است، نه صرفاً «نوع داده».

5. Reinforcement Learning

در RL دیگر Dataset کلاسیک (X,Y) نداریم.

یک Agent با Environment تعامل می‌کند.

Environment ↑ │ │ ↓ Reward ← Action │ ↑ └── Agent ─┘

Agent:

State ↓ Policy ↓ Action ↓ Environment ↓ Reward + Next State
اجزای اصلی
State
$$S_t$$

وضعیت محیط.

Action
$$A_t$$

کاری که Agent انجام می‌دهد.

Reward
$$R_t$$

پاداش.

Policy
$$\pi(a|s)$$

می‌گوید در State خاص چه Actionای انجام دهیم.

Value
$$V^{\pi}(s)$$

Expected cumulative reward از State s.

هدف RL

بیشینه کردن:

$$E \left[ \sum_{t=0}^{\infty} \gamma^t R_t \right]$$

که γ همان Discount Factor است.

Exploration vs Exploitation

یکی از بنیادی‌ترین Tradeoffهای RL:

Exploitation

کاری را انجام بده که می‌دانی خوب است.

Exploration

کار جدید را امتحان کن تا شاید چیز بهتری پیدا کنی.

مثلاً:

Restaurant A → همیشه خوب بوده Restaurant B → نمی‌دانی خوب است یا بد

اگر همیشه A را انتخاب کنی:

Exploitation ↑ Exploration ↓

ممکن است هیچ‌وقت بفهمی B بهتر بوده.

6. Parametric vs Non-Parametric Models

این یکی خیلی مهم است.

Parametric Model

فرض می‌کنیم مدل یک ساختار مشخص با تعداد مشخصی Parameter دارد.

مثلاً Linear Regression:

$$y = w^T x + b$$

اگر 100 Feature داشته باشی، تعداد پارامترها تقریباً:

101

است.

با افزایش Dataset از:

10,000 → 1,000,000

تعداد Parameters مدل تغییر نمی‌کند.

مثال‌ها

Linear Regression Logistic Regression Naive Bayes
Non-Parametric

مدل فرض نمی‌کند که ساختار تابع از ابتدا محدود و ثابت است.

ظرفیت مؤثر مدل می‌تواند با Dataset افزایش پیدا کند.

مثلاً:

KNN

برای Prediction عملاً به نمونه‌های Training وابسته است.

اگر:

10,000 samples

داشته باشی، Representation مدل هم به این داده‌ها وابسته است.

Decision Tree

پیچیدگی Tree می‌تواند با داده رشد کند.

یک اشتباه رایج
Non-Parametric به معنی "بدون Parameter" نیست.

این خیلی مهم است.

Non-parametric یعنی:

تعداد/ساختار پارامترهای مدل به شکل ثابتی از قبل محدود نشده است.

7. Model Capacity

Capacity یعنی:

مدل چقدر توانایی یادگیری توابع/الگوهای پیچیده را دارد؟

مثلاً:

Linear Model ↓ Low Capacity

در مقابل:

Deep Neural Network ↓ High Capacity
Capacity بالا یعنی چه؟

مدل می‌تواند Functionهای پیچیده‌تری را represent کند.

اما:

Capacity ↑

لزوماً به معنی:

Performance ↑

نیست.

چرا؟

چون ممکن است:

Capacity ↑ ↓ Training Error ↓ ↓ Overfitting Risk ↑
رابطه Capacity با Bias/Variance

در تصویر کلاسیک:

Model Capacity ↑ │ Bias \ \ \ \________ \ \ Variance \ ↑

به طور کلی:

Capacity ↑ ↓ Bias ↓ + Variance ↑

ولی در Deep Learning مدرن این رابطه همیشه ساده نیست.

8. Bias–Variance Tradeoff

این را قبلاً گفتیم، ولی در سطح Senior باید یک مرحله عمیق‌تر ببینی.

برای Squared Error:

$$E[(Y - \hat{f}(X))^2]$$

به صورت مفهومی:

$$Bias^2 + Variance + Noise$$
Bias

مدل به دلیل محدودیت/فرض نادرست، سیستماتیک اشتباه می‌کند.

مثلاً:

True relationship = nonlinear Model = linear

→ Bias بالا.

Variance

مدل به Training Dataset بیش از حد حساس است.

Dataset A → Model A Dataset B → Model B

اگر Model A و B خیلی متفاوت باشند:

→ Variance بالا.

9. Underfitting

مدل بیش از حد ساده است.

Train Error ↑ Validation Error ↑

مثلاً:

Complex nonlinear problem ↓ Linear Model
راه‌های کاهش Underfitting
  • Model capacity ↑
  • Features بهتر
  • Feature engineering
  • Training بیشتر
  • Regularization کمتر
  • مدل مناسب‌تر

10. Overfitting

مدل Training Data را بیش از حد یاد گرفته.

Train Error ↓↓↓ Validation Error ↑

مثلاً:

Noise ↓ Model memorizes noise ↓ Excellent train ↓ Poor test
راه‌های کاهش Overfitting
  • More data
  • Regularization
  • Simpler model
  • Feature selection
  • Data augmentation
  • Dropout
  • Early stopping
  • Cross-validation
  • Ensemble methods
نکته خیلی مهم Senior

Overfitting فقط به معنی:

«مدل خیلی پیچیده است»

نیست.

ممکن است به علت:

  • Data Leakage
  • Dataset کوچک
  • Noise
  • Hyperparameter Search زیاد
  • Distribution mismatch
  • Poor sampling

هم باشد.

11. Generalization

این احتمالاً مهم‌ترین مفهوم کل ML است.

مدل را روی:

$$P_{train}(X, Y)$$

آموزش می‌دهی.

ولی می‌خواهی روی نمونه جدید:

$$(X, Y) \sim P_{data}$$

خوب عمل کند.

یعنی:

Generalization
Generalization Gap
$$Generalization \ Gap = Test \ Error - Train \ Error$$

مثلاً:

Train Error = 2% Test Error = 12% Gap = 10%

Gap بزرگ می‌تواند نشانه Overfitting باشد.

12. Empirical Risk

فرض کن Loss داریم:

$$L(f(x), y)$$

روی Dataset:

$$D = \{ (x_i, y_i) \}_{i=1}^n$$

Empirical Risk:

$$\hat{R}(f) = \frac{1}{n} \sum_{i=1}^{n} L(f(x_i), y_i)$$

یعنی:

Average Loss روی داده‌ای که داریم.

مثلاً:

$$MSE = \frac{1}{n} \sum (y_i - \hat{y}_i)^2$$

13. Expected Risk

ولی چیزی که واقعاً برایمان مهم است:

$$R(f) = E_{(X,Y) \sim P}[L(f(X), Y)]$$

یعنی:

اگر از Distribution واقعی داده یک نمونه جدید بگیریم، انتظار داریم مدل چقدر خطا کند؟
مشکل

ما P(X,Y) واقعی را نمی‌دانیم.

پس Expected Risk را مستقیماً نمی‌توانیم حساب کنیم.

از Empirical Risk استفاده می‌کنیم:

Expected Risk ↑ unknown │ ↓ Empirical Risk │ Training Data

14. ERM — Empirical Risk Minimization

بسیاری از الگوریتم‌های ML در اصل دارند این کار را می‌کنند:

$$\hat{f} = \arg\min_f \frac{1}{n} \sum_{i=1}^{n} L(f(x_i), y_i)$$

یعنی:

مدلی پیدا کن که Training Loss را کمینه کند.

این می‌شود:

Empirical Risk Minimization
نکته مهم

ERM به تنهایی تضمین نمی‌کند Generalization خوب باشد.

ممکن است:

Training Risk ≈ 0

ولی:

Test Risk = High

چرا؟

Overfitting.

اینجاست که:

Regularization Inductive Bias Model Selection Data Quantity

مهم می‌شوند.

15. Training Error

Training Error:

$$\hat{R}_{train}$$

خطای مدل روی همان داده‌ای که با آن آموزش دیده.

مثلاً:

Training Accuracy = 99.9%

به تنهایی تقریباً هیچ تضمینی درباره Generalization نمی‌دهد.

16. Generalization Error

خطایی که مدل روی نمونه‌های جدید از Distribution واقعی دارد.

تقریباً:

$$R(f)$$

ولی چون Distribution واقعی را نمی‌دانیم، معمولاً با Validation/Test آن را تخمین می‌زنیم.

17. Bayes Error

این یکی بسیار مهم است.

فرض کن بهترین classifier ممکن را داشته باشیم.

باز هم ممکن است بعضی نمونه‌ها ذاتاً ambiguous باشند.

مثلاً:

X = Email Features Y = Spam / Not Spam

گاهی دو Email با Featureهای تقریباً یکسان داریم ولی یکی Spam و یکی Not Spam است.

حتی بهترین classifier هم ممکن است اشتباه کند.

حداقل خطای ممکن:

Bayes Error
Bayes Optimal Classifier

اگر Distribution واقعی را بدانیم، برای Classification بهترین تصمیم:

$$f^*(x) = \arg\max_y P(Y=y|X=x)$$

است.

یعنی:

در هر X، کلاسی را انتخاب کن که بیشترین احتمال Posterior را دارد.

خطایی که حتی این classifier هم نمی‌تواند حذف کند، Bayes Error است.

18. Irreducible Error

در داده Noise وجود دارد:

Measurement Noise Label Noise Intrinsic Randomness Missing Variables

این خطا ممکن است قابل حذف نباشد.

پس:

Total Error = Reducible Error + Irreducible Error

Reducible Error را می‌توان با مدل بهتر کم کرد.

Irreducible Error را نمی‌توان به طور کامل حذف کرد.

Bayes Error vs Irreducible Noise

این دو خیلی نزدیک‌اند ولی کاملاً یکی نیستند.

Irreducible noise یک مفهوم کلی‌تر درباره Noise/Randomness است.

Bayes Error حداقل خطای classification تحت Distribution واقعی و Loss مشخص است.

در مصاحبه اگر پرسیدند:

What is Bayes error?

بگو:

The irreducible minimum classification error achievable by the Bayes-optimal classifier given the true data distribution.

19. Model Complexity

Model Complexity یعنی ظرفیت مدل برای represent کردن الگوهای پیچیده.

مثلاً در Polynomial Regression:

Degree 1 Degree 2 Degree 5 Degree 20

هرچه Degree بیشتر:

Complexity ↑

معمولاً در دیدگاه کلاسیک:

Complexity ↑ ↓ Bias ↓ ↓ Training Error ↓ ↓ Variance ↑

اما بعداً می‌بینیم که در Deep Learning داستان می‌تواند پیچیده‌تر شود.

20. Model Complexity و Regularization

فرض کن:

$$Loss = TrainingLoss$$

اگر Regularization اضافه کنیم:

$$Objective = TrainingLoss + \lambda ComplexityPenalty$$

مثلاً Ridge:

$$MSE + \lambda \sum_j w_j^2$$

پس مدل فقط نمی‌گوید:

Training Error را کم کن.

بلکه می‌گوید:

Training Error را کم کن، ولی مدل را هم بیش از حد پیچیده نکن.

21. Inductive Bias

این یکی در لیست قبلی نبود ولی برای فهم همه این‌ها بسیار مهم است.

Inductive Bias یعنی:

فرض‌هایی که الگوریتم درباره مسئله دارد تا بتواند از داده محدود Generalize کند.

مثلاً:

Linear Regression

فرض ضمنی:

Relationship ≈ Linear
KNN

فرض:

Nearby points → Similar labels
CNN

Inductive Biasهایی مثل:

Locality Translation-related structure Weight sharing
Transformer

Inductive Bias متفاوتی دارد و Attention را برای مدل‌سازی روابط بین عناصر استفاده می‌کند.

بدون Inductive Bias، داده محدود برای Generalization کافی نیست.

22. No Free Lunch Theorem

یک مفهوم بسیار مهم در Theory.

به صورت ساده:

هیچ الگوریتم ML وجود ندارد که روی همه مسائل بهتر از همه الگوریتم‌های دیگر باشد.

مثلاً:

XGBoost

ممکن است برای Tabular Data عالی باشد.

ولی:

Raw Image

لزوماً بهترین انتخاب نیست.

و:

CNN

برای Image بسیار مناسب است، ولی برای بعضی Tabular problems الزاماً بهترین نیست.

پیام اصلی No Free Lunch

برای انتخاب مدل باید به:

Data + Problem Structure + Inductive Bias + Objective + Constraints

توجه کنی.

23. Curse of Dimensionality

یکی از مهم‌ترین مفاهیم ML.

فرض کن یک بعد داری:

[0, 1]

اگر بخواهی فضای آن را با resolution مشخص پوشش دهی، کار نسبتاً ساده است.

اما اگر 10 Dimension داشته باشی:

[0, 1]^10

تعداد نواحی لازم به شدت زیاد می‌شود.

اگر برای هر Dimension به 10 قسمت نیاز داشته باشی:

$$10^d$$

برای:

d=1 → 10 d=2 → 100 d=3 → 1,000 d=10 → 10,000,000,000

یعنی 10 میلیارد سلول!

نتیجه چیست؟

با افزایش Dimensions:

Dimensions ↑ ↓ Space Volume ↑ ↓ Data Sparsity ↑ ↓ Need More Data ↑ ↓ Learning becomes harder

24. مشکل Distance در High Dimensions

در KNN فرض می‌کنیم:

نقاط نزدیک، رفتار مشابه دارند.

ولی در High Dimensions، فاصله‌ها ممکن است کمتر informative شوند.

مثلاً:

2D: A ● │ │ close ● B

در 100 Dimension:

Distance(A,B) Distance(A,C) Distance(A,D) ...

ممکن است خیلی به هم نزدیک شوند.

این phenomenon را می‌توان به شکل distance concentration دید.

25. Curse of Dimensionality و KNN

KNN در ابعاد پایین خوب می‌تواند کار کند.

اما:

Dimensions ↑ ↓ Nearest Neighbor not really "near" ↓ KNN Performance ↓

راه‌حل‌های احتمالی:

Feature Selection PCA Dimensionality Reduction Better Representation More Data

26. Curse of Dimensionality فقط KNN نیست

روی بسیاری از روش‌ها اثر دارد:

  • KNN
  • Kernel Methods
  • Density Estimation
  • Clustering
  • Distance-based algorithms
  • Statistical estimation

ولی Deep Learning یک نکته ظریف دارد:

Neural Networks می‌توانند در فضای بسیار high-dimensional کار کنند، چون Representation Learning و ساختارهای inductive مناسب می‌توانند مشکل را تا حدی مدیریت کنند.

پس:

High-dimensional ≠ Neural Network automatically fails.

27. رابطه همه مفاهیم

حالا مهم‌ترین قسمت.

همه این مفاهیم جدا از هم نیستند.

یک زنجیره واقعی ML این است:

DATA │ ▼ Data Distribution │ ▼ Inductive Bias │ ▼ Model Class │ ▼ Model Capacity │ ┌───────┴────────┐ │ │ Too Low Too High │ │ Bias ↑ Variance ↑ │ │ Underfitting Overfitting │ │ └───────┬────────┘ ▼ Generalization │ ▼ Expected Risk │ ▼ Test Performance

و در طرف دیگر:

Training Data │ ▼ Empirical Risk │ ▼ Optimization │ ▼ Training Error

ولی چیزی که واقعاً می‌خواهیم:

Expected Risk ↓ Generalization

28. یک مثال کامل Senior-Level

فرض کن یک Fraud Detection Model داریم.

Dataset

1,000,000 transactions

29. تفاوت مفاهیمی که خیلی‌ها قاطی می‌کنند

Model Capacity vs Model Complexity

خیلی نزدیک‌اند ولی دقیقاً مترادف نیستند.

Capacity بیشتر به توانایی مدل برای represent کردن توابع مختلف اشاره دارد.

Complexity می‌تواند به ساختار/پیچیدگی مدل یا راهی که complexity را اندازه می‌گیریم اشاره کند.

Noise vs Bias

Noise:

Data uncertainty

Bias:

Model systematic error
Training Error vs Generalization Error

Training:

Seen Data

Generalization:

Unseen Data
Validation vs Test

Validation:

Used for decisions

Test:

Used for final evaluation
Unsupervised vs Self-Supervised

Unsupervised:

No explicit labels

Self-supervised:

Targets generated from the data itself
Semi-Supervised vs Self-Supervised

Semi:

Labeled + Unlabeled

Self:

Automatically generated targets

🎯 30. چیزهایی که در مصاحبه Senior باید بتوانی توضیح بدهی

اگر interviewer این سؤال‌ها را بپرسد:

«چرا Training Accuracy بالا ولی Test Accuracy پایین است؟»

باید بگویی:

High variance / overfitting، ولی قبل از نتیجه‌گیری باید Data Leakage، Distribution Shift، Dataset Size و Evaluation Pipeline را هم بررسی کنم.
«آیا مدل پیچیده‌تر همیشه بهتر است؟»

نه.

Complexity می‌تواند Bias را کاهش دهد ولی در classical setting ممکن است Variance را افزایش دهد؛ علاوه بر این، در modern overparameterized models رفتارهایی مثل double descent نشان می‌دهند که رابطه کلاسیک همیشه کافی نیست.

«آیا صفر کردن Training Error خوب است؟»

نه الزاماً.

هدف:

$$min Expected Risk$$

است، نه:

$$min Training Error$$
«چرا مدل‌های مختلف روی یک Dataset رفتار متفاوت دارند؟»

به دلیل:

Inductive Bias Capacity Optimization Regularization Representation
«آیا بیشتر کردن داده همیشه مشکل را حل می‌کند؟»

نه.

اگر مشکل:

Label Noise Data Leakage Distribution Shift Wrong Features Wrong Objective

باشد، داده بیشتر لزوماً مشکل را حل نمی‌کند.

🧠 نقشه ذهنی نهایی

اگر بخواهم کل این فصل را در یک تصویر ذهنی خلاصه کنم:

ML │ ┌────────────────┼────────────────┐ │ │ │ Learning Models Data │ │ │ ┌──────┼──────┐ Capacity Distribution │ │ │ │ │ Sup Un Reinforce │ IID / Shift │ │ │ │ Semi Self RL │ │ │ │ └──────┴───────┐ │ │ │ ▼ ▼ Generalization │ ┌────────┴────────┐ │ │ Bias Variance │ │ Underfit Overfit │ │ └────────┬────────┘ ▼ Expected Risk │ ┌─────┴─────┐ │ │ Reducible Irreducible Error Error │ │ Model Bayes choices Error

و یک لایه بالاتر:

Data ↓ Inductive Bias ↓ Model Class ↓ Capacity / Complexity ↓ Optimization ↓ Empirical Risk ↓ Training Error ↓ Generalization ↓ Expected Risk ↓ Bayes Error + Reducible Error

این دقیقاً همان Core ML Mental Model است که اگر در ذهنت جا بیفتد، خیلی از الگوریتم‌های مختلف ML دیگر مجموعه‌ای از فرمول‌های جداگانه به نظر نمی‌رسند؛ می‌بینی همه دارند یک مسئله مشترک را از زاویه‌های مختلف حل می‌کنند: چطور از داده محدود، یک تابع یاد بگیریم که روی داده جدید Generalize کند.
