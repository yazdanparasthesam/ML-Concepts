🔍 12. Feature Engineering

حتماً. این بخش Feature Engineering یکی از مهم‌ترین تفاوت‌های بین یک ML Engineer معمولی و Senior ML Engineer است. در بسیاری از پروژه‌های tabular، کیفیت feature engineering حتی از انتخاب الگوریتم مهم‌تر است.

نکته‌ای که باید از ابتدا در ذهن داشته باشی:

Feature Engineering یعنی تبدیل داده خام به representationای که یادگیری الگو برای مدل آسان‌تر، پایدارتر و قابل‌تعمیم‌تر شود.

و نکته Senior:

Feature Engineering فقط «ساختن چند ستون جدید» نیست؛ شامل انتخاب، تبدیل، استخراج، کنترل leakage، مدیریت missing/outlier، encoding، scaling و در نهایت حفظ سازگاری دقیق train و inference است.

1. Feature چیست؟

Feature همان متغیری است که مدل برای پیش‌بینی استفاده می‌کند.

فرض کن می‌خواهیم احتمال Fraud را پیش‌بینی کنیم:

amountagecountrytransactions_1hdevicefraud
12032TR2mobile0
500045IR18web1

اینجا:

amount age country transactions_1h device

feature هستند.

و:

fraud

target است.

2. Feature Engineering دقیقاً چه کاری می‌کند؟

فرض کن فقط این feature را داریم:

amount = 1000

مدل ممکن است اطلاعات محدودی از آن بگیرد.

اما می‌توانیم بسازیم:

log_amount amount / customer_avg_amount amount_zscore amount_last_24h transaction_velocity

حالا representation بسیار غنی‌تر شده است.

3. Feature Engineering در یک Pipeline

یک pipeline حرفه‌ای می‌تواند چیزی شبیه این باشد:

Raw Data │ ├── Data Cleaning │ ├── Missing Value Handling │ ├── Outlier Handling │ ├── Feature Construction │ ├── Feature Transformation │ ├── Encoding │ ├── Feature Selection │ ├── Scaling │ ▼ Model-ready Features

اما ترتیب دقیق همیشه ثابت نیست و به نوع feature و مدل بستگی دارد.

4. چهار مفهوم مهم را از هم جدا کن

این چهار مورد خیلی با هم اشتباه می‌شوند:

Feature Selection

از featureهای موجود، تعدادی را انتخاب می‌کنیم.

Feature Extraction

اطلاعات جدید را از representation موجود استخراج می‌کنیم.

Feature Construction

feature جدید بر اساس دانش مسئله می‌سازیم.

Feature Transformation

شکل feature را تغییر می‌دهیم.

5. Feature Selection

یعنی:

انتخاب subset مناسبی از featureهای موجود.

مثلاً:

1000 features ↓ Feature Selection ↓ 80 features

بدون اینکه الزاماً feature جدیدی بسازیم.

6. چرا Feature Selection مهم است؟

دلایل مختلف:

1. کاهش overfitting

Featureهای بی‌ربط می‌توانند noise اضافه کنند.

2. کاهش computational cost
1000 features → 50 features
3. افزایش interpretability

مدل راحت‌تر توضیح داده می‌شود.

4. کاهش inference latency

در production مهم است.

5. کاهش مشکلات multicollinearity

خصوصاً در مدل‌های linear.

7. روش‌های Feature Selection

سه خانواده اصلی:

Filter Methods Wrapper Methods Embedded Methods

8. Filter Methods

قبل از training مدل، featureها را با یک معیار آماری بررسی می‌کنیم.

مثلاً:

Correlation Mutual Information Chi-square ANOVA Variance Threshold

مثلاً:

Feature A → correlation = 0.82 Feature B → correlation = 0.02

ممکن است A را نگه داریم.

9. مشکل Correlation

Correlation فقط رابطه خطی را خوب capture می‌کند.

ممکن است:

$$corr(X,Y) \approx 0$$

ولی رابطه بسیار قوی nonlinear باشد.

مثلاً:

$$Y = X^2$$

در برخی توزیع‌ها correlation می‌تواند نزدیک صفر باشد، در حالی که X اطلاعات زیادی درباره Y دارد.

پس:

$$Low\ correlation \neq useless\ feature$$

10. Mutual Information

Mutual Information می‌تواند dependencyهای غیرخطی را نیز capture کند.

به صورت مفهومی:

$$MI(X, Y)$$

اندازه می‌گیرد که دانستن X چقدر uncertainty درباره Y را کاهش می‌دهد.

مزیت:

محدود به رابطه خطی نیست.

11. Wrapper Methods

در این روش feature subset را با خود مدل ارزیابی می‌کنیم.

مثلاً:

Features ↓ Train Model ↓ Evaluate ↓ Remove/Add Features ↓ Train Again

مثال:

Recursive Feature Elimination — RFE

12. مشکل Wrapper Methods

معمولاً:

computationally expensive

هستند.

اگر:

10,000 features

داشته باشی، اجرای مدل برای subsetهای مختلف بسیار گران می‌شود.

13. Embedded Methods

Feature selection هنگام training مدل انجام می‌شود.

مثلاً:

Lasso

به دلیل L1 regularization می‌تواند بعضی ضرایب را دقیقاً صفر کند.

w1 = 0.82 w2 = 0 w3 = -0.41 w4 = 0

در نتیجه featureهای مربوط به ضرایب صفر effectively حذف می‌شوند.

همچنین:

Tree Feature Importance XGBoost feature importance LightGBM feature importance

از روش‌های embedded هستند.

14. نکته Senior: Feature Selection Leakage

فرض کن کل dataset را:

Train + Validation + Test

برمی‌داری و correlation featureها را محاسبه می‌کنی.

بعد feature selection انجام می‌دهی.

این می‌تواند:

information leakage

ایجاد کند.

روش درست:

Train ↓ Fit feature selector ↓ Transform Train ↓ Transform Validation/Test

Selector باید فقط روی training data fit شود.

15. Feature Extraction

در Feature Extraction، representation جدیدی از داده استخراج می‌کنیم.

مثلاً:

1000-dimensional data ↓ PCA ↓ 50 dimensions

مثال‌های مهم:

PCA SVD Autoencoder Embeddings TF-IDF CNN representations

16. Feature Construction

اینجا خودمان feature جدید می‌سازیم.

مثلاً:

income debt

می‌توانیم بسازیم:

$$DebtRatio = \frac{debt}{income}$$

این feature ممکن است از خود income و debt اطلاعات مفیدتری برای مدل ایجاد کند.

17. Feature Construction و Domain Knowledge

این بخش یکی از نقاط قوت Senior ML Engineer است.

مثلاً در پرداخت:

transaction_amount

به تنهایی شاید کافی نباشد.

ولی:

transactions_last_5min transactions_last_1h amount_last_24h unique_merchants_24h distance_from_previous_transaction

می‌توانند بسیار informative باشند.

این یعنی:

$$Domain\text{-}driven\ Feature\ Engineering$$

18. Interaction Features

گاهی اثر یک feature به feature دیگری وابسته است.

مثلاً:

age income

ممکن است به تنهایی کافی نباشند.

اما:

age × income

یک interaction ایجاد می‌کند.

19. مثال Interaction

فرض کن:

$$y = 3x_1 + 5x_2 + 10x_1x_2$$

اگر فقط:

x1 x2

را به یک Linear Model بدهی، بخش:

$$10x_1x_2$$

را نمی‌تواند مستقیماً یاد بگیرد.

با interaction:

x1 x2 x1*x2

می‌تواند.

20. Interaction در Tree Models

درخت‌ها خودشان می‌توانند بسیاری از interactionها را یاد بگیرند.

مثلاً:

if income > X AND age < Y → ...

بنابراین ساخت دستی interaction همیشه لازم نیست.

برای Linear Models اهمیت بیشتری دارد.

21. Polynomial Features

می‌توانیم featureهای polynomial بسازیم.

مثلاً:

x

تبدیل شود به:

x x² x³

و برای دو feature:

x1 x2

ممکن است داشته باشیم:

x1 x2 x1² x2² x1*x2

22. Polynomial Regression

مدل:

$$y = \beta_0 + \beta_1x + \beta_2x^2$$

هنوز از نظر پارامترها:

Linear in parameters

است.

یعنی Polynomial Regression الزاماً یک «مدل غیرخطی نسبت به ضرایب» نیست.

23. مشکل Polynomial Features

تعداد featureها می‌تواند بسیار سریع زیاد شود.

اگر:

n = number of features d = polynomial degree

باشد، تعداد ترکیب‌ها می‌تواند به‌شدت رشد کند.

در نتیجه:

Dimensionality ↑ Overfitting risk ↑ Memory ↑ Computation ↑

24. Binning

Binning یعنی تبدیل continuous variable به intervalهای گسسته.

مثلاً:

Age = 27

تبدیل شود به:

AgeGroup = 20-30

مثال:

0–18 19–30 31–45 46–60 60+

25. چرا Binning؟

می‌تواند:

noise را کاهش دهد nonlinear relationships را ساده کند interpretability را افزایش دهد اثر outlierها را محدود کند

اما:

اطلاعات دقیق را از دست می‌دهد.

26. Equal-Width Binning

مثلاً:

0–20 20–40 40–60 60–80 80–100

عرض intervalها برابر است.

27. Equal-Frequency Binning

هر bin تقریباً تعداد مشابهی sample دارد.

مثلاً:

20% samples → Bin 1 20% samples → Bin 2 ...

این روش با:

Quantiles

مرتبط است.

28. Binning و Tree Models

Decision Tree خودش threshold ایجاد می‌کند.

بنابراین:

manual binning

برای tree-based models معمولاً ضرورت کمتری دارد.

برای مدل‌های linear یا business rules می‌تواند مفیدتر باشد.

29. Log Transformation

اگر feature strongly right-skewed باشد:

0 1 2 3 5 10 100 10000

می‌توانیم:

$$x' = \log(x)$$

استفاده کنیم.

اگر صفر داریم:

$$x' = \log(1 + x)$$

که به آن:

log1p

می‌گوییم.

30. Log Transformation چه کاری می‌کند؟

معمولاً:

Large values → compressed Small values → relatively expanded

بنابراین skewness کاهش پیدا می‌کند.

مثلاً:

1000 → log ≈ 6.9 100000 → log ≈ 11.5

فاصله 99,000 واحدی تبدیل به فاصله بسیار کوچک‌تری می‌شود.

31. چه زمانی Log Transformation مفید است؟

برای featureهایی مثل:

income transaction amount population count website visits wealth

که distribution آنها heavy/right-skewed است.

32. Log Transformation و Zero/Negative Values

Log معمولی برای:

$$x \leq 0$$

تعریف نمی‌شود.

پس نباید کورکورانه:

np.log(x)

روی feature دارای صفر یا مقدار منفی اجرا کنی.

راه‌حل بسته به domain:

log1p(x) برای non-negative data Yeo-Johnson برای مقادیر منفی/مثبت offset مناسب، فقط با توجیه domain

33. Power Transformation

هدف:

Stabilize variance + reduce skewness + make distribution more symmetric

است.

دو روش معروف:

Box-Cox Yeo-Johnson

34. Box-Cox

Box-Cox معمولاً برای:

$$x > 0$$

است.

به شکل کلی:

$$x^{(\lambda)}$$

با transformation مناسب بر اساس λ.

اگر:

$$\lambda = 1$$

تقریباً transformation خطی است.

اگر:

$$\lambda = 0$$

به log transformation مربوط می‌شود.

35. Yeo-Johnson

مزیت مهم:

می‌تواند مقادیر zero و negative را نیز handle کند.

پس:

-10 -2 0 5 100

هم می‌توانند وارد transformation شوند.

36. Quantile Transformation

در این روش feature را بر اساس رتبه/quantile آن تبدیل می‌کنیم.

مثلاً:

Raw distribution ↓ Rank / Quantile ↓ Target distribution

Target distribution می‌تواند:

Uniform

یا:

Normal / Gaussian

باشد.

37. چرا Quantile Transformation؟

می‌تواند:

skewness را کاهش دهد outlier impact را کاهش دهد distribution را به شکل مطلوب‌تری تبدیل کند

اما:

relationship اصلی feature با target ممکن است تغییر کند.

38. مشکل Quantile Transformation

اگر روی کل dataset fit شود:

Train + Test

اطلاعات distribution test وارد transformation می‌شود.

این leakage است.

باید:

fit on train transform train transform validation transform test

باشد.

39. Encoding چیست؟

Encoding یعنی تبدیل categorical data به representation عددی.

مثلاً:

Country Iran Turkey Azerbaijan

را به representation مناسب مدل تبدیل کنیم.

40. One-Hot Encoding

مثلاً:

Country Iran Turkey Azerbaijan

تبدیل:

Iran Turkey Azerbaijan 1 0 0 0 1 0 0 0 1

مزیت:

ordering مصنوعی ایجاد نمی‌کند.

41. مشکل One-Hot

اگر:

10,000 unique categories

داشته باشی:

10,000 columns

ممکن است ایجاد شود.

در نتیجه:

memory ↑ dimensionality ↑ sparsity ↑

42. Ordinal Encoding

مثلاً:

Low → 0 Medium → 1 High → 2

برای featureهایی که واقعاً ترتیب دارند مناسب است.

مثلاً:

Low < Medium < High

اما برای:

Tehran = 0 Istanbul = 1 Baku = 2

مناسب نیست؛ چون ordering واقعی وجود ندارد.

43. Frequency Encoding

هر category را با frequency آن جایگزین می‌کنیم.

مثلاً:

Tehran → 0.50 Istanbul → 0.30 Baku → 0.20

مزیت:

dimensionality کم.

اما ممکن است categoryهای مختلف با frequency یکسان representation مشابه بگیرند.

44. Target Encoding

مثلاً برای binary target:

Tehran → fraud rate = 0.08 Istanbul → fraud rate = 0.21 Baku → fraud rate = 0.04

این روش بسیار قدرتمند است.

ولی:

بسیار مستعد target leakage است.

45. Target Encoding Leakage

غلط:

Whole Dataset ↓ Calculate target mean ↓ Encode ↓ Train/Test

چون target test وارد encoding شده است.

روش صحیح:

Train ↓ Fit target encoder ↓ Transform validation/test

و برای training predictionها، به‌خصوص در مدل‌سازی حساس، باید روش‌های cross-fitting / OOF مناسب استفاده شود.

46. Scaling

Scaling یعنی تغییر scale featureها.

مثلاً:

Age: 20–80 Income: 1,000–100,000,000

ممکن است optimizer یا distance metric تحت تأثیر قرار بگیرد.

47. چرا Scaling مهم است؟

برای مدل‌هایی مثل:

Logistic Regression Linear Regression با regularization SVM KNN K-Means PCA Neural Networks Gradient-based optimization

معمولاً مهم است.

اما برای:

Decision Tree Random Forest XGBoost LightGBM

معمولاً scaling ضروری نیست.

48. Standardization

استانداردسازی معمولاً:

$$z = \frac{x - \mu}{\sigma}$$

است.

یعنی:

Mean → 0 Std → 1
1.0
0.0
1.2
بازخورد بدهید
Original: Age = 50 Mean = 40 Std = 5 z = (50-40)/5 = 2

یعنی این sample دو standard deviation بالاتر از mean قرار دارد.

49. نکته مهم درباره Standardization

Standardization:

الزاماً distribution را Normal نمی‌کند.

این اشتباه رایج است.

ممکن است بعد از standardization:

Mean = 0 Std = 1

باشد، ولی distribution همچنان:

skewed heavy-tailed multimodal

باشد.

50. Min-Max Normalization

یکی از رایج‌ترین روش‌ها:

$$x' = \frac{x - x_{min}}{x_{max} - x_{min}}$$

در نتیجه معمولاً:

$$x' \in [0, 1]$$

قرار می‌گیرد.

51. Standardization vs Normalization

در بسیاری از منابع:

Standardization z = (x - μ) / σ
Min-Max Normalization (x - x_min) / (x_max - x_min)

نامیده می‌شود.

ولی terminology در منابع مختلف همیشه یکسان نیست.

پس در مصاحبه بهتر است:

فرمول را مشخص کنی، نه فقط اسم را.

52. مشکل Min-Max با Outlier

فرض کن:

99% data = 0–100 1 outlier = 1,000,000

Min-Max:

0–100 → tiny interval

فشرده می‌شود.

پس برای outlier-heavy data باید با دقت استفاده شود.

53. Robust Scaling

برای داده‌های دارای outlier می‌توان از:

$$x' = \frac{x - Median}{IQR}$$

استفاده کرد.

که:

$$IQR = Q_3 - Q_1$$

است.

این روش نسبت به outlierها مقاوم‌تر است.

54. Scaling و Train/Test Leakage

یکی از اشتباهات بسیار رایج:

scaler.fit(X)

روی کل dataset.

غلط.

درست:

scaler.fit(X_train) X_train_scaled = scaler.transform(X_train) X_valid_scaled = scaler.transform(X_valid) X_test_scaled = scaler.transform(X_test)

چون mean/std/min/max test نباید وارد training شوند.

55. Missing Value Handling

واقعیت data:

Age = NaN Income = NaN Country = NaN

است.

مدل‌ها همه به شکل یکسان missing را handle نمی‌کنند.

56. چرا Missing Value مهم است؟

Missingness خودش ممکن است signal باشد.

مثلاً در یک سیستم مالی:

اگر مشتری income خود را وارد نکرده باشد، ممکن است این عدم‌ورود خودش اطلاعاتی درباره رفتار کاربر داشته باشد.

بنابراین:

$$Missing \neq Always\ Random\ Noise$$

57. سه نوع Missingness

این موضوع Senior بسیار مهم است.

MCAR
Missing Completely At Random

missing بودن مستقل از data است.

MAR
Missing At Random

missing بودن به متغیرهای observed وابسته است.

MNAR
Missing Not At Random

missing بودن به مقدار خود missing variable یا عامل مشاهده‌نشده مرتبط است.

58. MCAR

مثلاً:

Random database failure

باعث شده بعضی values تصادفی از بین بروند.

تقریباً:

$$P(Missing | X, Y) = P(Missing)$$

59. MAR

مثلاً income برای بعضی گروه‌های سنی بیشتر missing باشد.

یعنی:

Age ↓ Probability of missing income

60. MNAR

مثلاً:

افراد با درآمد بسیار بالا عمداً income را ثبت نمی‌کنند.

در این حالت missing بودن خودش به مقدار واقعی income وابسته است.

این مشکل بسیار سخت‌تر است.

61. روش‌های ساده Imputation

Mean x_missing = μ Median x_missing = median(X) Mode برای categorical.

62. Mean vs Median

اگر distribution تقریباً symmetric باشد:

Mean

ممکن است مناسب باشد.

اگر outlier/skewness داشته باشیم:

Median

اغلب robustتر است.

مثلاً:

Income: 20k 22k 25k 30k 5,000,000

Mean شدیداً تحت تأثیر outlier قرار می‌گیرد.

Median معمولاً بهتر است.

63. Missing Indicator

گاهی علاوه بر imputation یک feature دیگر می‌سازیم:

income_missing = 1

مثلاً:

income = median income_missing = 1

این اجازه می‌دهد model بفهمد:

این مقدار واقعی نیست؛ imputed شده.

64. Advanced Imputation

روش‌های پیشرفته‌تر:

KNN Imputation مقادیر مشابه را پیدا می‌کند. Iterative Imputation یک feature را با استفاده از سایر featureها پیش‌بینی می‌کند. MICE Multiple Imputation by Chained Equations. Model-based Imputation مثلاً با Random Forest یا regression.

65. خطر Imputation

اگر imputer روی کل data fit شود:

Train + Validation + Test

leakage ایجاد می‌شود.

همیشه:

fit on train transform others

66. Outlier چیست؟

Observationای که نسبت به distribution معمول data بسیار غیرعادی است.

مثلاً:

Age: 20 22 25 27 29 200

200 یک outlier واضح است.

اما:

Outlier همیشه اشتباه نیست.

ممکن است:

Fraud transaction

واقعاً مقدار بسیار بزرگی داشته باشد.

67. Outlier Detection با Z-score

اگر:

$$|z| > 3$$

باشد، در برخی کاربردها observation را outlier در نظر می‌گیرند.

اما:

قانون z > 3 universal نیست.

به distribution و domain بستگی دارد.

68. IQR Method

می‌گوییم:

$$IQR = Q_3 - Q_1$$

و حدود معمول:

$$Lower = Q_1 - 1.5 IQR$$
$$Upper = Q_3 + 1.5 IQR$$

مشاهدات خارج از این محدوده:

potential outliers

هستند.

69. Outlier Handling

چند روش:

حذف Remove rows Capping / Winsorization مثلاً: x > P99 را برابر P99 قرار دهیم. Transformation مثلاً: log(x) Robust Scaling مدل‌سازی با الگوریتم robust

70. حذف Outlier همیشه درست نیست

فرض کن Fraud Detection داری.

transaction = $100,000

ممکن است outlier باشد.

اگر آن را حذف کنی:

شاید دقیقاً مهم‌ترین نمونه business را حذف کرده باشی.

پس ابتدا سؤال:

$$Is\ it\ an\ error\ or\ a\ rare\ but\ valid\ observation?$$

71. Outlier vs Anomaly

این دو دقیقاً یکی نیستند.

Outlier

از نظر آماری غیرعادی است.

Anomaly

از نظر behavior/domain غیرعادی است.

یک transaction ممکن است statistically extreme باشد ولی legitimate باشد.

72. Feature Engineering و Leakage

این یکی از مهم‌ترین نکات Senior است.

فرض کن می‌خواهی:

customer_avg_transaction

را بسازی.

اگر average را از:

کل transactionهای آینده

محاسبه کنی، اطلاعات آینده وارد feature می‌شود.

این:

$$Data\ Leakage$$

است.

73. مثال Time Leakage

فرض کن:

Transaction: 2026-01-01

را پیش‌بینی می‌کنی.

Feature:

customer_total_transactions

را از کل سال 2026 حساب کردی.

در این صورت transactionهای:

2026-02 2026-03 ...

در feature مربوط به January وارد شده‌اند.

مدل عملاً آینده را دیده است.

74. Feature Engineering باید Time-Aware باشد

در سیستم‌های temporal:

Feature at time T

باید فقط از اطلاعات:

$$t \leq T$$

استفاده کند.

و در بعضی کاربردها حتی باید:

$$t < T$$

باشد، بسته به اینکه timestamp همان event چه زمانی در دسترس بوده است.

این موضوع در:

Fraud Finance Forecasting Recommendation Predictive Maintenance

خیلی مهم است.

75. Feature Engineering برای Different Models

Linear Models

Feature engineering بسیار مهم.

مثلاً:

log polynomial interaction scaling encoding
Tree Models

نیاز کمتر به:

scaling polynomial manual nonlinear transformation

اما هنوز:

domain features aggregation temporal features categorical handling

بسیار مهم‌اند.

76. چرا Tree به Scaling نیاز ندارد؟

Decision Tree بر اساس threshold تصمیم می‌گیرد:

age < 30

اگر age را:

30

به:

0.3

تبدیل کنیم، ordering حفظ شده است.

بنابراین split تقریباً همان مفهوم را دارد.

اما KNN بر اساس distance کار می‌کند، پس scaling بسیار مهم‌تر است.

77. Feature Engineering برای KNN

فرض کن:

Age = 20–80 Income = 10,000–100,000,000

بدون scaling:

Income

distance را dominant می‌کند.

پس:

Distance

به‌شدت تحت تأثیر scale قرار می‌گیرد.

78. Feature Engineering برای Logistic Regression

فرض کن:

income age

داریم.

اگر:

income = 1,000,000 age = 30

باشد، scaling می‌تواند:

optimization را پایدارتر کند regularization را منصفانه‌تر کند convergence را بهتر کند

به خصوص وقتی L1/L2 داریم.

79. Scaling و Regularization

این نکته بسیار مهم است.

در L2:

$$\lambda \sum_j w_j^2$$

اگر featureها scaleهای بسیار متفاوت داشته باشند، ضرایب نیز scaleهای متفاوتی پیدا می‌کنند.

در نتیجه penalty روی coefficients می‌تواند عملاً رفتار نامتوازن داشته باشد.

پس:

Scaling قبل از regularized linear models معمولاً بسیار مهم است.

80. Feature Engineering و Curse of Dimensionality

Feature engineering ممکن است تعداد featureها را افزایش دهد.

مثلاً:

10 features

با polynomial degree 3 می‌شود:

ده‌ها / صدها feature

و این می‌تواند:

Dimensionality ↑

و:

Data Sparsity ↑

ایجاد کند.

پس:

$$Feature\ Engineering \neq Feature\ Explosion$$

81. Feature Selection بعد از Feature Engineering

یک pipeline حرفه‌ای می‌تواند:

Raw Features ↓ Feature Construction ↓ Feature Transformation ↓ Feature Expansion ↓ Feature Selection ↓ Model

باشد.

مثلاً:

100 raw features ↓ 500 engineered features ↓ 120 selected features ↓ Model

82. Feature Importance

بعد از feature engineering باید بدانیم کدام featureها مهم‌اند.

روش‌ها:

Linear coefficients Tree importance Permutation importance SHAP

اما:

$$Feature\ importance \neq causal\ importance$$

83. Correlated Features و Feature Importance

فرض کن:

age birth_year

هر دو اطلاعات تقریباً یکسان دارند.

ممکن است model importance را بین آنها تقسیم کند.

پس low importance یک feature لزوماً به معنی useless بودن آن نیست.

ممکن است:

اطلاعات آن توسط feature دیگری پوشش داده شده باشد.

84. Feature Engineering و Multicollinearity

در Linear Models:

income monthly_income annual_income

تقریباً اطلاعات یکسان دارند.

این می‌تواند:

Multicollinearity

ایجاد کند.

نتیجه:

coefficient instability standard errorهای بزرگ تفسیر دشوارتر

Regularization می‌تواند کمک کند.

85. Feature Construction در سیستم‌های Real-Time

در production باید به این سؤال جواب بدهی:

آیا این feature در لحظه inference قابل محاسبه است؟

مثلاً:

customer_transactions_last_1h

اگر نیاز به scan کردن 5 میلیارد رکورد داشته باشد:

feature خوب offline است ولی production feature بدی است.

86. Training-Serving Skew

یکی از مهم‌ترین مفاهیم Senior:

فرض کن training:

Python preprocessing

دارد.

اما production:

Java preprocessing

و منطق این دو کمی متفاوت است.

در نتیجه:

Training Feature Distribution ≠ Serving Feature Distribution

این:

$$Training-Serving\ Skew$$

است.

87. راه‌حل Training-Serving Skew

تا حد امکان:

Same transformation logic

را در train و inference استفاده کن.

مثلاً:

Reusable preprocessing pipeline Feature Store Shared transformation code

88. Feature Store

در سیستم‌های بزرگ می‌توان featureها را در:

Feature Store

مدیریت کرد.

مثلاً:

customer_avg_amount_24h customer_transaction_count_1h customer_risk_score

و این featureها:

Offline Store + Online Store

داشته باشند.

89. Offline vs Online Features

Offline
برای training: Historical data
Online
برای real-time inference: Low latency

مثلاً:

Fraud model

در لحظه transaction باید featureها را سریع دریافت کند.

90. Feature Freshness

Feature ممکن است:

5 seconds old

یا:

5 days old

باشد.

برای برخی سیستم‌ها freshness حیاتی است.

مثلاً:

transactions_last_5min

اگر 1 ساعت قدیمی باشد، feature دیگر ارزش زیادی ندارد.

91. Feature Drift

Feature distribution ممکن است با زمان تغییر کند.

مثلاً:

Training: average transaction = $100 Production: average transaction = $500

این:

Feature Drift

است.

92. Feature Engineering و Data Drift

در production باید monitoring داشته باشیم:

Feature Distribution ↓ Compare Train vs Production ↓ Drift? ↓ Alert

روش‌هایی مثل:

PSI KL divergence JS divergence Wasserstein distance statistical tests

می‌توانند استفاده شوند.

93. Feature Engineering و Concept Drift

تفاوت مهم:

Feature Drift
$$P(X)$$

تغییر کرده.

Concept Drift

رابطه:

$$P(Y | X)$$

تغییر کرده.

مثلاً رفتار fraudsterها عوض شده است.

حتی اگر distribution featureها ثابت باشد، رابطه feature و target می‌تواند تغییر کند.

94. یک مثال کامل Fraud Feature Engineering

Raw:

amount timestamp customer_id merchant_id country device_id

می‌توانیم بسازیم:

Temporal hour day_of_week is_weekend Velocity tx_count_5m tx_count_1h tx_count_24h Amount log_amount amount_zscore_customer amount_vs_customer_avg Merchant merchant_tx_count merchant_fraud_rate Customer customer_avg_amount customer_unique_merchants customer_unique_devices Geographic distance_from_last_transaction country_change

این‌ها معمولاً از raw featureها ارزش بیشتری دارند.

95. اما اینجا یک دام بزرگ داریم

مثلاً:

merchant_fraud_rate

اگر fraud rate را از کل dataset حساب کنیم:

future transactions

و حتی target همان transaction وارد calculation شود، leakage داریم.

باید مثلاً:

historical fraud rate up to prediction time

محاسبه شود.

96. Feature Engineering و Cross-Validation

Feature engineering باید داخل CV pipeline قرار بگیرد.

مثلاً:

Fold 1 ├── Fit Imputer ├── Fit Scaler ├── Fit Encoder ├── Feature Selection └── Train Model Fold 2 ├── Fit Imputer ├── Fit Scaler ├── Fit Encoder ├── Feature Selection └── Train Model

نه اینکه preprocessing یک بار روی کل dataset انجام شود و بعد CV کنیم.

97. Feature Engineering و Test Set

Test set را مثل:

یک محیط production ناشناخته

در نظر بگیر.

نباید:

Test ↓ Feature engineering decisions ↓ Model tuning

انجام شود.

98. ترتیب فکری درست در یک پروژه واقعی

به جای اینکه از ابتدا بگویی:

«باید log بگیرم، scaling کنم، PCA بزنم»

اول بپرس:

1. Business problem چیست؟ 2. Target چیست؟ 3. Prediction time چیست؟ 4. چه اطلاعاتی در prediction time واقعاً available است؟ 5. Data distribution چیست؟ 6. Missingness چگونه است؟ 7. Outlierها چه معنایی دارند؟ 8. Model چه assumptionsی دارد؟ 9. چه featureهایی signal دارند؟ 10. چه featureهایی leakage هستند؟

این دقیقاً mindset یک Senior ML Engineer است.

🧠 مهم‌ترین نکات Senior

اگر بخواهم کل این فصل را به سطح مصاحبه Senior خلاصه کنم، این‌ها را باید خیلی خوب بلد باشی:

1. Feature Engineering بدون کنترل Leakage خطرناک است.
Fit preprocessing on TRAIN only
2. Feature خوب یعنی featureای که در inference قابل دسترس است.
نه featureای که فقط offline می‌توانی بسازی.
3. Tree Models به scaling معمولاً نیاز ندارند.
ولی: KNN SVM Logistic Regression Neural Networks PCA اغلب از scaling سود می‌برند.
4. Correlation پایین به معنی useless بودن نیست.
ممکن است رابطه nonlinear باشد.
5. Outlier را کورکورانه حذف نکن.
اول بپرس: Data error یا rare valid event؟
6. Target Encoding بسیار قدرتمند ولی بسیار خطرناک است.
چون: Target → Feature می‌تواند leakage ایجاد کند.
7. Feature Engineering برای time-series باید causal باشد.
یعنی: Features(t) فقط از information available by t استفاده کنند.
8. Scaling با Standardization به معنی Normal Distribution نیست.
فقط: Mean = 0, Std = 1 را هدف می‌گیرد.
9. Feature Engineering می‌تواند dimensionality را منفجر کند.
خصوصاً: Polynomial Features One-Hot Encoding Interaction Features
10. بهترین Feature همیشه پیچیده‌ترین Feature نیست.
گاهی: customer_tx_count_1h از ده‌ها feature پیچیده بهتر است.
