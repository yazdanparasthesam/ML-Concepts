🧠 تفاوت Train / Validation / Test در Senior ML

حتماً. این یکی از پایه‌ای‌ترین مفاهیم ML است و اگر Train / Validation / Test را درست بفهمی، خیلی از مفاهیم مثل Cross-Validation، Hyperparameter Tuning و Overfitting هم خودبه‌خود روشن می‌شوند.

1. اول تفاوت اصلی

سه Dataset داریم:

کل داده │ ┌─────────┴─────────┐ │ │ Train Test │ ↓ Validation

یا مثلاً:

100% Dataset │ ├── 70% Train ├── 15% Validation └── 15% Test

هر کدام هدف متفاوتی دارند.

Datasetبرای چه کاری؟مدل آن را می‌بیند؟
Trainیادگیری Parameters✅ بله
Validationانتخاب مدل و Hyperparameter⚠️ برای تصمیم‌گیری دیده می‌شود
Testارزیابی نهایی❌ نباید در تصمیم‌گیری دیده شود

2. Train چیست؟

Train Dataset همان داده‌ای است که مدل با آن یاد می‌گیرد.

مثلاً Linear Regression:

$$y = wx + b$$

مدل با Training Data تلاش می‌کند:

$$w, b$$

را پیدا کند.

مثلاً:

X y ──────────────────── 10 100 20 200 30 300 40 400

مدل از این داده‌ها یاد می‌گیرد:

w ≈ 10 b ≈ 0

پس:

Train برای یادگیری Parameters است.

3. Validation چیست؟

اینجا سؤال مهم توست:

چرا اصلاً Validation لازم داریم؟

فرض کن مدل را روی Train آموزش دادی.

حالا 3 مدل داری:

Model A Model B Model C

یا یک مدل داری ولی چند Hyperparameter مختلف:

Learning Rate = 0.1 Learning Rate = 0.01 Learning Rate = 0.001

از کجا بفهمیم کدام بهتر است؟

نمی‌توانیم از Training Error استفاده کنیم.

چرا؟

چون مدل روی Training Data یاد گرفته است.

مثلاً:

Model A Train Accuracy = 95% Model B Train Accuracy = 99% Model C Train Accuracy = 100%

ممکن است فکر کنیم:

C > B > A

ولی شاید:

Validation Accuracy A = 94% B = 96% C = 82%

باشد.

چرا؟

چون C احتمالاً Overfit کرده.

4. پس Validation چه کار می‌کند؟

Validation به ما کمک می‌کند بین مدل‌ها انتخاب کنیم.

مثلاً:

Train ↓ ┌──────┼──────┐ ↓ ↓ ↓ Model A Model B Model C │ │ │ └──────┼──────┘ ↓ Validation ↓ Choose Model B

پس:

Validation برای Model Selection و Hyperparameter Tuning است.

5. Hyperparameter یعنی چه؟

مثلاً در Decision Tree:

max_depth = 3 max_depth = 5 max_depth = 10 max_depth = 20

این‌ها Parameters نیستند که مدل خودش یاد بگیرد.

ما باید انتخابشان کنیم.

پس:

Train ↓ Train model with max_depth=3 ↓ Validation Score Train ↓ Train model with max_depth=5 ↓ Validation Score Train ↓ Train model with max_depth=10 ↓ Validation Score

مثلاً:

max_depth Validation F1 ───────────────────────── 3 0.89 5 0.94 ← Best 10 0.91 20 0.84

پس انتخاب می‌کنیم:

max_depth = 5

6. پس Test چه کار می‌کند؟

حالا فرض کن بعد از Validation تصمیم گرفتی:

Model = XGBoost max_depth = 5 learning_rate = 0.05

دیگر باید یک Dataset داشته باشیم که تا این لحظه اصلاً برای تصمیم‌گیری استفاده نشده باشد.

این می‌شود:

Test Set

مثلاً:

Train ↓ Learn Parameters Validation ↓ Choose Model / Hyperparameters Test ↓ Final Evaluation

Test به ما می‌گوید:

«حالا که تمام تصمیمات را گرفته‌ای، اگر این مدل را روی داده‌ای واقعاً ندیده اجرا کنی، چقدر خوب عمل می‌کند؟»

7. یک مثال واقعی

فرض کن می‌خواهی مدل تشخیص Fraud بسازی.

100,000 تراکنش داری:

70,000 → Train 15,000 → Validation 15,000 → Test
مرحله 1 — Train

مدل را آموزش می‌دهی:

XGBoost

روی:

70,000 transactions
مرحله 2 — Validation

چند مدل را امتحان می‌کنی:

Random Forest XGBoost LightGBM Neural Network

نتیجه:

Model Validation F1 ─────────────────────────────── Random Forest 0.91 XGBoost 0.95 ← انتخاب LightGBM 0.94 Neural Network 0.92

پس:

XGBoost

را انتخاب می‌کنی.

بعد Hyperparameterها را هم انتخاب می‌کنی.

مرحله 3 — Test

حالا برای اولین بار Test را استفاده می‌کنی:

XGBoost + Best Hyperparameters ↓ Test Set ↓ F1 = 0.93

این عدد تخمین نهایی تو از Performance مدل است.

8. چرا نمی‌توانیم Test را برای Validation استفاده کنیم؟

فرض کن Test داری:

Test F1 = 0.91

بعد مدل را تغییر می‌دهی:

Model V2 Test F1 = 0.93

بعد:

Model V3 Test F1 = 0.94

بعد:

Threshold = 0.47 Test F1 = 0.95

تبریک! 😄

مدل تو ظاهراً عالی شده.

ولی یک مشکل بزرگ داری:

تو به Test Set چندین بار نگاه کردی.

پس Test دیگر واقعاً unseen نیست.

در واقع داری به Test Set Overfit می‌کنی.

9. Validation هم می‌تواند Overfit شود!

این نکته خیلی مهم است.

فرض کن 1000 مدل مختلف را روی Validation امتحان کنی:

Model 1 → Validation = 0.90 Model 2 → Validation = 0.91 ... Model 1000 → Validation = 0.97

ممکن است Model 1000 واقعاً بهترین مدل نباشد.

ممکن است به Validation Set Overfit کرده باشی.

به همین دلیل:

Train ↓ Validation ↓ Model Selection ↓ Test

داریم.

Test آخرین check مستقل است.

10. پس چرا Validation «یادگیری» نیست؟

یک تفکیک بسیار مهم:

Train

مدل Parameters را یاد می‌گیرد:

$$\theta$$

مثلاً:

Weights Biases
Validation

ما تصمیم می‌گیریم:

Which model? Which hyperparameters? Which threshold? Which features? Which architecture?
Test

فقط می‌پرسیم:

Performance نهایی چقدر است؟

11. مثال خیلی ساده مثل امتحان دانشگاه

این analogy خیلی خوب است:

Train = جزوه و تمرین

با آن یاد می‌گیری.

Validation = آزمون آزمایشی

با آن تصمیم می‌گیری کجاها ضعیفی و چه روشی بهتر است.

Test = امتحان نهایی

بعد از اینکه تصمیماتت را گرفتی، عملکرد واقعی‌ات را می‌سنجی.

Train ↓ Learn Validation ↓ Tune Test ↓ Evaluate

12. حالا K-Fold کجای این داستان است؟

این قسمت خیلی مهم است.

به جای:

Train 70% Validation 15% Test 15%

می‌توانی:

Train 85% Test 15%

داشته باشی.

بعد روی آن 85%:

5-Fold Cross Validation

انجام بدهی.

یعنی:

85% Train │ ┌─────────┼─────────┐ │ │ │ Fold 1 Fold 2 Fold 3 ... │ │ └─────────┼─────────┘ ↓ Model Selection ↓ Final Training ↓ 15% Test

در این حالت Validation به صورت داخلی توسط Cross-Validation ساخته می‌شود.

پس:

K-Fold جایگزین مفهوم Validation نیست؛ بلکه یک روش بهتر/چندباره برای ساخت Validation Splits است.

13. Pipeline حرفه‌ای ML

در پروژه واقعی معمولاً چیزی شبیه این داریم:

Raw Dataset │ ▼ Train / Test Split │ ┌───────────┴───────────┐ │ │ Train Test │ │ ▼ │ Cross Validation │ │ │ ┌────┼────┐ │ ▼ ▼ ▼ │ Fold1 Fold2 Fold3 ... │ │ │ │ │ ▼ ▼ ▼ │ Hyperparameter Tuning │ │ │ ▼ │ Best Configuration │ │ │ ▼ │ Final Training on Train │ │ │ └───────────┐ │ ▼ ▼ Final Model → Test │ ▼ Final Performance

14. یک نکته بسیار مهم: Validation فقط برای Hyperparameter نیست

Validation برای خیلی چیزها استفاده می‌شود:

Model Selection
Random Forest vs XGBoost vs Neural Network
Hyperparameter Tuning
max_depth learning_rate C lambda
Feature Selection
Feature Set A vs Feature Set B
Architecture Selection

مثلاً Neural Network:

2 layers vs 4 layers vs 8 layers
Threshold Selection

مثلاً:

threshold = 0.3 threshold = 0.5 threshold = 0.7
Early Stopping

Validation Loss را بررسی می‌کنیم تا ببینیم آیا مدل شروع به Overfit کرده یا نه.

15. یک سؤال خیلی مهم مصاحبه

اگر interviewer بپرسد:

Why do we need a validation set if we already have a training set?

جواب:

Because the training set is used to optimize the model parameters, so its performance is optimistically biased. We need an independent validation set to select models and tune hyperparameters based on their ability to generalize to unseen data.

و اگر بپرسد:

Why do we still need a test set?

جواب:

Because repeated model selection and hyperparameter tuning on the validation set can overfit to it. The test set provides a final unbiased estimate of generalization performance.

16. خلاصه‌ای که باید حفظ باشی

TRAIN ↓ Learn Parameters ↓ VALIDATION ↓ Choose Model / Hyperparameters ↓ FINAL MODEL ↓ TEST ↓ Final Generalization Estimate

یا خیلی ساده:

Train = Learn
Validation = Decide
Test = Evaluate

و ارتباطش با K-Fold:

K-Fold = چند بار Validation ساختن روی Training Data برای اینکه Model Selection و Performance Estimation نسبت به یک Split خاص کمتر حساس باشد.

اگر این چهار مفهوم را کنار هم بگذاری، کل تصویر خیلی تمیز می‌شود:

GENERALIZATION │ ┌───────────┴───────────┐ │ │ TRAINING EVALUATION │ │ Parameters Validation │ │ │ Model Selection │ │ └──────────┬────────────┘ │ Final Model │ ▼ TEST │ ▼ Final Performance
نکته کلیدی: Validation برای این نیست که «مدل را آموزش بدهد»؛ برای این است که به ما اجازه دهد درباره‌ی مدل تصمیم بگیریم، بدون اینکه از Test سوءاستفاده کنیم.
