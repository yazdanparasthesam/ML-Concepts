🏷️ 13. Categorical Features — از پایه تا Senior ML

این بخش از نظر Senior ML خیلی مهم است، چون categorical features در پروژه‌های واقعی—خصوصاً fintech، fraud detection، recommendation و customer analytics—می‌توانند هم بسیار قدرتمند باشند و هم یکی از بزرگ‌ترین منابع data leakage، overfitting و training-serving skew شوند.

1. Categorical Feature چیست؟

Categorical Feature متغیری است که مقادیر آن نماینده‌ی دسته‌ها / گروه‌ها / کلاس‌ها هستند.

مثلاً:

country

Iran Turkey Azerbaijan Germany

یا:

payment_method

card cash crypto bank_transfer

یا:

device_type

mobile desktop tablet

برخلاف featureهای continuous:

age = 35
amount = 1520.7
temperature = 23.4

categorical feature معمولاً مجموعه‌ای از categoryها دارد.

2. دو نوع مهم Categorical Feature

Nominal

ترتیب معنی‌داری ندارد.

مثلاً:

Iran Turkey Germany France

هیچ‌کدام ذاتاً بزرگ‌تر یا کوچک‌تر از دیگری نیستند.

Ordinal

ترتیب معنی‌دار است.

مثلاً:

Low Medium High

یا:

Bronze Silver Gold Platinum

اینجا:

$$Low < Medium < High$$

معنی دارد.

3. چرا نمی‌توانیم مستقیماً categorical را به مدل بدهیم؟

فرض کن:

Country:

  • Iran
  • Turkey
  • Germany

بعضی مدل‌ها نمی‌توانند مستقیماً string را پردازش کنند.

پس ممکن است بگوییم:

Iran → 0
Turkey → 1
Germany → 2

اما این کار یک مشکل مهم دارد.

مدل ممکن است تصور کند:

$$Germany > Turkey > Iran$$

در حالی که چنین ترتیبی وجود ندارد.

این مشکل پایه‌ای encodingهای ساده است.

4. One-Hot Encoding

یکی از استانداردترین روش‌ها:

Country

Iran Turkey Germany

تبدیل می‌شود به:

country_irancountry_turkeycountry_germany
100
010
001

5. چرا One-Hot خوب است؟

چون ordering مصنوعی ایجاد نمی‌کند.

مثلاً:

Iran → [1,0,0]
Turkey → [0,1,0]
Germany → [0,0,1]

هیچ مفهوم عددی:

$$Germany > Turkey$$

وجود ندارد.

6. One-Hot و Linear Models

برای مدل‌هایی مثل:

  • Logistic Regression
  • Linear Regression
  • Linear SVM

One-Hot بسیار رایج است.

مثلاً:

$$logit(p) = \beta_0 + \beta_1 I(Iran) + \beta_2 I(Turkey) + \beta_3 I(Germany)$$

7. Dummy Variable Trap

اگر intercept داشته باشیم و تمام categoryها را One-Hot کنیم، ممکن است perfect multicollinearity ایجاد شود.

مثلاً:

  • Iran
  • Turkey
  • Germany

و:

$$Iran + Turkey + Germany = 1$$

همیشه برقرار است.

پس یکی از dummyها را می‌توان حذف کرد:

  • Iran
  • Turkey

و:

Germany به عنوان reference category در نظر گرفته می‌شود.

البته بسیاری از کتابخانه‌ها این موضوع را با تنظیمات مناسب مدیریت می‌کنند.

8. One-Hot و Tree Models

Tree models هم می‌توانند با One-Hot کار کنند.

مثلاً:

  • country_iran
  • country_turkey
  • country_germany

اما مشکل:

high cardinality

است.

مثلاً:

merchant_id = 2,000,000 unique values

One-Hot یعنی میلیون‌ها column.

این معمولاً بسیار بد است.

9. مشکل اصلی One-Hot: High Cardinality

فرض کن:

merchant_id

داریم و:

$$N = 1,000,000$$

merchant مختلف داریم.

One-Hot:

$$1,000,000$$

feature تولید می‌کند.

نتیجه:

  • Memory ↑
  • Storage ↑
  • Training Cost ↑
  • Sparsity ↑
  • Overfitting Risk ↑

10. Ordinal Encoding

اگر categoryها واقعاً ترتیب داشته باشند:

  • Low
  • Medium
  • High

می‌توانیم:

Low → 0
Medium → 1
High → 2

استفاده کنیم.

اینجا ordering معنی‌دار است.

11. نکته مهم Ordinal Encoding

اگر feature:

Education:
  • High School
  • Bachelor
  • Master
  • PhD

باشد، ordinal encoding می‌تواند منطقی باشد.

اما اگر:

Browser:
  • Chrome
  • Firefox
  • Safari
  • Edge

باشد:

Chrome → 0
Firefox → 1
Safari → 2
Edge → 3

اشتباه مفهومی است.

چون:

$$Chrome < Firefox$$

معنی ندارد.

12. Label Encoding

Label Encoding معمولاً categoryها را به integer تبدیل می‌کند.

مثلاً:

Cat → 0
Dog → 1
Horse → 2

13. تفاوت Label Encoding و Ordinal Encoding

از نظر ظاهر ممکن است یکسان باشند:

A → 0
B → 1
C → 2

ولی semantic متفاوت است.

Ordinal Encoding

می‌گوییم: این categoryها واقعاً ordered هستند.

Label Encoding

اغلب صرفاً: category → integer ID

14. Label Encoding برای Target

یک کاربرد بسیار رایج Label Encoding:

target:

  • fraud
  • legitimate

تبدیل:

legitimate → 0
fraud → 1

اینجا کاملاً منطقی است.

15. مشکل Label Encoding برای Input Features

اگر:

city:
  • Tehran
  • Istanbul
  • Baku

را:

0
1
2

کنیم، مدل‌های مختلف ممکن است این اعداد را به صورت numerical interpretation ببینند.

در مدل‌های linear:

$$2 > 1 > 0$$

به طور مستقیم وارد مدل می‌شود.

بنابراین برای nominal feature معمولاً مناسب نیست.

16. Target Encoding

یکی از قدرتمندترین encodingها.

ایده:

category را با statistic مربوط به target جایگزین کنیم.

فرض کن:

merchant

داریم و target:

fraud = 0/1

مثلاً:

merchantfraud rate
A0.02
B0.15
C0.40

Target Encoding:

A → 0.02
B → 0.15
C → 0.40

17. چرا Target Encoding قدرتمند است؟

چون category را مستقیماً به:

predictive information

تبدیل می‌کند.

به جای اینکه:

  • merchant_A
  • merchant_B
  • merchant_C

داشته باشیم، یک feature داریم:

merchant_fraud_rate

18. Target Encoding برای Regression

فرض کن target:

house_price

است.

برای:

city

می‌توانیم mean target را محاسبه کنیم:

Tehran → mean price = 8B
Tabriz → mean price = 4B
Shiraz → mean price = 5B

19. بزرگ‌ترین خطر Target Encoding

🚨 Target Leakage

فرض کن:

merchant = A
fraud = 1

و می‌خواهیم encoding را بسازیم.

اگر target همان row را در محاسبه mean استفاده کنیم، target خودش مستقیماً وارد feature شده است.

یعنی:

$$X \leftarrow Y$$

و این بسیار خطرناک است.

20. مثال Leakage

فرض کن merchant فقط 2 transaction دارد:

merchantfraud
A1
A0

اگر target encoding را روی کل data حساب کنیم:

$$mean = \frac{1 + 0}{2} = 0.5$$

حالا برای row اول:

actual target = 1
encoded feature = 0.5

برای dataset بزرگ‌تر، این self-inclusion می‌تواند مدل را به شدت optimistic کند، خصوصاً برای categoryهای rare.

21. بدترین حالت Target Encoding

فرض کن merchant فقط یک record دارد:

merchantfraud
X1

Target encoding:

$$X \to 1$$

پس مدل عملاً می‌بیند:

merchant_X = 1
target = 1

این تقریباً memorization است.

22. راه‌حل: Smoothing

به جای استفاده مستقیم از:

$$\frac{\text{sum(target)}}{\text{count}}$$

از ترکیب:

  • category mean
  • + global mean

استفاده می‌کنیم.

مثلاً:

$$TE(c) = \frac{n_c \mu_c + \alpha \mu}{n_c + \alpha}$$

که:

  • n_c: تعداد samples category
  • μ_c: mean target category
  • μ: global mean
  • α: smoothing strength

است.

23. مثال Smoothing

فرض کن:

Global fraud rate = 0.10

Merchant A:

n = 100
fraud rate = 0.20

Merchant B:

n = 1
fraud rate = 1.00

بدون smoothing:

A → 0.20
B → 1.00

اما B فقط یک مشاهده دارد.

با smoothing:

A → نزدیک 0.20
B → نزدیک 0.10

یعنی:

categoryهای rare را به global mean shrink می‌کنیم.

24. Target Encoding و Cross-Fitting

برای جلوگیری از leakage در training بسیار مهم است.

ایده:

Fold 1 Encoder trained on Fold 2+3+4+5 Transform Fold 1 Fold 2 Encoder trained on Fold 1+3+4+5 Transform Fold 2

و به همین ترتیب.

یعنی هر sample:

با target خودش encode نمی‌شود.

این را می‌توان به صورت:

Out-of-Fold Encoding

دید.

25. Target Encoding در Validation/Test

فرض کن:

  • Train
  • Validation
  • Test

داریم.

Encoder فقط روی Train fit می‌شود:

Train ↓ fit target encoder ↓ Validation → transform Test → transform

نباید target validation/test برای encoding استفاده شود.

26. Target Encoding در Cross-Validation

Pipeline صحیح:

Fold │ ├── Train Fold │ ↓ │ Fit Encoder │ ↓ │ Transform Train │ └── Validation Fold ↓ Transform only

اگر encoder بیرون CV fit شود:

leakage ممکن است ایجاد شود.

27. Frequency Encoding

اینجا category را با frequency آن جایگزین می‌کنیم.

مثلاً:

CountryCountFrequency
Iran50000.50
Turkey30000.30
Germany20000.20

پس:

Iran → 0.50
Turkey → 0.30
Germany → 0.20

28. Frequency Encoding چه اطلاعاتی می‌دهد؟

در واقع:

category popularity / prevalence

را capture می‌کند.

مثلاً در fraud:

merchant_frequency

می‌تواند نشان دهد merchant چقدر common است.

29. Frequency Encoding Leakage دارد؟

معمولاً target leakage مستقیم ندارد، چون از Y استفاده نمی‌کند.

اما یک نکته مهم:

اگر frequency را از Train + Test محاسبه کنی، distribution test وارد preprocessing شده است.

این می‌تواند:

preprocessing leakage / transductive information

ایجاد کند.

روش امن:

fit frequency on train transform validation/test

30. Count Encoding

Count Encoding مشابه Frequency Encoding است، با این تفاوت که به جای:

$$\frac{\text{count(category)}}{N}$$

از:

$$\text{count(category)}$$

استفاده می‌کنیم.

مثلاً:

Iran → 5000
Turkey → 3000
Germany → 2000

31. Frequency vs Count

در یک dataset ثابت:

$$Frequency = \frac{Count}{N}$$

پس اطلاعات مشابهی دارند.

اما scale متفاوت است.

32. نکته Senior درباره Frequency/Count Encoding

فرض کن:

merchant_id

داریم.

ممکن است:

merchant_frequency

تقریباً به مدل بگوید:

این merchant چقدر معروف / پرتکرار است.

این گاهی signal بسیار خوبی است.

اما:

frequency الزاماً quality یا risk را نشان نمی‌دهد.

33. Binary Encoding

Binary Encoding برای high-cardinality categorical features طراحی شده است.

فرض کن:

Category IDs:
0
1
2
3
4

ابتدا category را به integer تبدیل می‌کنیم، سپس integer را به binary representation تبدیل می‌کنیم.

مثلاً:

0 → 000
1 → 001
2 → 010
3 → 011
4 → 100

34. مزیت Binary Encoding

اگر:

$$K$$

category داشته باشیم، تعداد binary columns تقریباً:

$$O(\log_2 K)$$

است.

در حالی که One-Hot:

$$O(K)$$

ستون می‌سازد.

35. مثال

اگر:

$$1024 \text{ categories}$$

داشته باشیم:

One-Hot:

$$1024 \text{ columns}$$

Binary Encoding تقریباً:

$$\log_2(1024) = 10$$

column ایجاد می‌کند.

36. مشکل Binary Encoding

Binary Encoding یک representation عددی/ساختاری ایجاد می‌کند که ممکن است:

semantic relationship واقعی بین categoryها نداشته باشد.

پس این encoding همیشه بهتر از One-Hot نیست.

37. Hash Encoding

در Hash Encoding از یک hash function استفاده می‌کنیم.

مثلاً:

merchant_A → hash → bucket 17
merchant_B → hash → bucket 4
merchant_C → hash → bucket 17

در نتیجه:

categoryها به تعداد محدودی bucket نگاشت می‌شوند.

38. Hash Encoding برای High Cardinality

اگر:

$$10,000,000 \text{ categories}$$

داشته باشیم، می‌توانیم مثلاً:

1000 buckets

داشته باشیم.

پس memory بسیار کمتر می‌شود.

39. Hash Collision

مشکل مهم:

A → bucket 17
C → bucket 17

دو category مختلف یک representation مشترک گرفته‌اند.

به این:

Hash Collision

می‌گوییم.

40. آیا Hash Collision همیشه بد است؟

نه.

در بسیاری از سیستم‌های large-scale، trade-off قابل قبول است:

  • Memory ↓↓↓
  • Dimensionality ↓↓↓
  • Exact category identity ↓

و مدل هنوز performance خوبی دارد.

41. Hashing Trick

Hashing Trick در سیستم‌های sparse و large-scale بسیار معروف است.

مثلاً:

  • text
  • categorical IDs
  • URLs
  • tokens

می‌توانند به فضای fixed-dimensional hash شوند.

مزیت مهم:

نیازی به ساخت vocabulary کامل نداریم.

42. Native Categorical Handling

بعضی الگوریتم‌ها categorical features را مستقیماً handle می‌کنند.

معروف‌ترین مثال:

CatBoost

که برای categorical features طراحی شده است.

43. CatBoost

CatBoost از روش‌های اختصاصی برای categorical features استفاده می‌کند و به‌خصوص:

high-cardinality categories

را بهتر از بسیاری از روش‌های naive مدیریت می‌کند.

44. ایده اصلی CatBoost برای Categorical

CatBoost از نوعی:

ordered target statistics

استفاده می‌کند.

نکته مهم آن:

ترتیب داده‌ها برای کاهش target leakage استفاده می‌شود.

یعنی به جای اینکه target statistic را از کل dataset برای یک sample بسازد، از اطلاعات قبلی/مناسب در ترتیب استفاده می‌کند.

45. چرا CatBoost مهم است؟

چون این مشکل را هدف قرار می‌دهد:

Categorical Feature ↓ Target Statistics ↓ Leakage

و سعی می‌کند encoding را به شکل leakage-aware انجام دهد.

46. LightGBM و Categorical

LightGBM نیز می‌تواند categorical features را به شکل native مدیریت کند، اما روش داخلی آن با CatBoost یکسان نیست.

در استفاده عملی باید:

  • categorical columns را درست مشخص کنی
  • category representation مناسب باشد
  • training/serving consistency حفظ شود

47. XGBoost

XGBoost در نسخه‌های جدیدتر پشتیبانی native از categorical features دارد، اما setup و رفتار آن با CatBoost و LightGBM متفاوت است.

نکته Senior: «همه tree modelها categorical را یکسان handle می‌کنند» غلط است.

یک heuristic خوب:

Low Cardinality

مثلاً:

  • gender
  • device_type
  • payment_type

معمولاً:

One-Hot
Medium Cardinality

مثلاً:

  • city
  • merchant_category

می‌توان بررسی کرد:

  • One-Hot
  • Frequency
  • Target Encoding
  • Native categorical

مثلاً:

  • merchant_id
  • customer_id
  • product_id

  • Target Encoding

50. ولی Cardinality تنها معیار نیست

این نکته Senior مهم است.

دو feature هر دو:

100 categories

دارند.

یکی:

country

است.

دیگری:

merchant_id

است.

رفتار predictive آنها کاملاً متفاوت است.

پس باید domain را هم در نظر بگیری.

51. Rare Categories

فرض کن:

merchant_id

داریم و برخی merchantها فقط یک بار دیده شده‌اند.

اگر One-Hot کنیم:

merchant_X = 1

مدل ممکن است آن را memorize کند.

52. Rare Category Grouping

می‌توان categoryهای کم‌تکرار را به:

OTHER

تبدیل کرد.

مثلاً:

A → A
B → B
C → C
D → OTHER
E → OTHER
F → OTHER

این می‌تواند:

  • dimensionality را کم کند
  • overfitting را کاهش دهد
  • model robustness را افزایش دهد

53. اما Rare ≠ Useless

یک category ممکن است count = 10 داشته باشد ولی تمام 10 مورد fraud باشند.

پس حذف آن صرفاً بر اساس frequency می‌تواند signal ارزشمند را از بین ببرد.

54. Unknown Categories

در production ممکن است category جدیدی ببینی:

Training:
A
B
C
Production:
D

مدل باید برای:

D

رفتار مشخص داشته باشد.

مثلاً:

D → UNKNOWN

55. این مسئله در One-Hot بسیار مهم است

اگر encoder فقط categoryهای train را بشناسد و production category جدید بیاید، pipeline ممکن است fail کند.

پس باید strategy داشته باشی:

handle_unknown = ignore

یا:

UNKNOWN bucket

بسته به implementation.

56. Training-Serving Skew در Encoding

فرض کن training:

Iran → 0
Turkey → 1
Germany → 2

ولی production:

Iran → 2
Turkey → 0
Germany → 1

اگر mapping ثابت نباشد، مدل کاملاً خراب می‌شود.

بنابراین:

Encoder باید fit شده و artifact آن versioned شود.

57. Category Mapping باید Persist شود

در production:

Training ↓ Fit Encoder ↓ Save Encoder ↓ Model Artifact ↓ Production ↓ Load same Encoder

نه اینکه encoder را دوباره از صفر بسازیم.

58. Target Encoding و Unknown Category

فرض کن:

Train:
A
B
C
Production:
D

برای D target statistics نداریم.

معمولاً باید fallback داشته باشیم، مثلاً:

D → global mean

یا یک smoothing strategy.

59. Target Encoding برای Multiclass

اگر:

$$Y \in \{A, B, C\}$$

باشد، می‌توان برای هر category probability مربوط به هر class را محاسبه کرد:

merchant_X:
P(class A) = 0.2
P(class B) = 0.7
P(class C) = 0.1

در نتیجه یک category می‌تواند به چند feature تبدیل شود.

60. Target Encoding برای Regression

مثلاً:

product_category

و:

target = sales

می‌توان:

$$TE(category) = E[Y \mid category]$$

را محاسبه کرد.

ولی همچنان leakage و rare-category problem داریم.

61. Target Encoding و Hierarchical Categories

گاهی category hierarchy داریم:

Country ↓ City ↓ Merchant

اگر merchant خیلی rare باشد، می‌توان اطلاعات را از hierarchy قرض گرفت.

مثلاً:

Merchant statistic ↓ City statistic ↓ Country statistic ↓ Global statistic

این نوع hierarchical smoothing می‌تواند در داده‌های sparse بسیار مفید باشد.

62. Categorical Feature و Embedding

در Deep Learning روش دیگری داریم:

category ID ↓ Embedding Layer ↓ dense vector

مثلاً:

merchant_A → [0.12, -0.83, 0.44, ...]

اگر:

embedding_dim = 32

باشد، هر category یک vector 32بعدی دارد.

63. Embedding vs One-Hot

One-Hot
Merchant A → [1,0,0,0,0,...]
Embedding
Merchant A → [0.12,-0.4,0.81,...]

Embedding می‌تواند representation فشرده و learned ایجاد کند.

64. Embedding برای High Cardinality

برای:

  • customer_id
  • product_id
  • merchant_id

در deep learning بسیار رایج است.

اما نکته مهم:

ID خودش الزاماً semantic feature نیست.

اگر customer ID فقط identifier باشد، embedding می‌تواند رفتارهای memorization ایجاد کند.

66. Temporal Leakage با Category Statistics

فرض کن:

merchant_fraud_rate

ساخته‌ای.

اگر prediction در:

t

باشد ولی fraud rate را از:

t+1

محاسبه کنی، future leakage داری.

Feature باید:

$$TE_t = E[Y_{past} \mid X]$$

باشد، نه:

$$E[Y_{future} \mid X]$$

67. Categorical Features و Cross-Validation

چون encoder قبل از CV target را دیده است.

درست:

Fold 1 Train Fold ↓ Fit Encoder ↓ Transform Validation Fold ↓ Model

و همین برای تمام folds.

Raw Data │ ▼ Train Fold │ ├── Missing Handler ├── Rare Category Handler ├── Encoder ├── Feature Selector │ ▼ Model │ ▼ Validation Fold

هر transformation که از data statistics استفاده می‌کند باید:

داخل fold fit شود.

فرض کن:

  • fraud = 1 → 1%
  • fraud = 0 → 99%

و:

داریم.

Target Encoding ممکن است برای merchantهای rare مقدارهای بسیار extreme ایجاد کند.

مثلاً:

merchant_X

در حالی که فقط دو نمونه داشته‌ایم.

اینجاست که:

smoothing + minimum support

خیلی مهم می‌شود.

75. مثال حرفه‌ای Target Encoding برای Fraud

فرض کن:

Global fraud rate = 0.02

Merchant A:

N = 10,000
fraud rate = 0.03

Merchant B:

N = 3
fraud rate = 1.00

بدون smoothing:

A → 0.03
B → 1.00

این خطرناک است.

با smoothing:

$$TE = \frac{n \mu_c + \alpha \mu}{n + \alpha}$$

Merchant B به global rate نزدیک‌تر می‌شود.

این:

Shrinkage

نام دارد.

76. Target Encoding را به شکل Bayesian هم ببین

یک نگاه عمیق‌تر:

Target Encoding با smoothing را می‌توان به مفهوم:

Bayesian shrinkage / prior

مرتبط کرد.

Global mean نقش prior را دارد و category-specific observations evidence هستند.

  • برای categoryهای کم‌نمونه: Posterior ≈ Prior
  • برای categoryهای پرتعداد: Posterior ≈ Category Statistic

این دیدگاه برای فهم اینکه چرا smoothing منطقی است، بسیار مفید است.

77. Target Encoding و Out-of-Fold

برای training dataset:

5 folds

مثلاً:

Fold 1:
encoder ← folds 2,3,4,5
transform → fold 1
Fold 2:
encoder ← folds 1,3,4,5
transform → fold 2

در نهایت:

OOF Target Encoded Features

می‌سازی.

برای validation/test:

encoder ← full training data transform validation/test

این یکی از مهم‌ترین implementation details است.

🧠 جمع‌بندی Senior

اگر در مصاحبه از تو بپرسند:

How do you handle categorical variables?

جواب Senior نباید این باشد:

"I use One-Hot Encoding."

جواب بهتر:

«اول cardinality، nominal/ordinal بودن، frequency distribution، unknown/rare categories و model family را بررسی می‌کنم. برای low-cardinality nominal features معمولاً One-Hot مناسب است؛ برای ordinal features از ordinal encoding استفاده می‌کنم. برای high-cardinality features می‌توانم target/frequency/count encoding، hashing یا native categorical handling را بررسی کنم. Target Encoding را حتماً با smoothing و leakage-safe cross-fitting/OOF strategy انجام می‌دهم و encoder را فقط روی training data fit می‌کنم. در production نیز mapping، unknown-category handling و training-serving consistency را version می‌کنم.»

و اگر بخواهی واقعاً Senior جواب بدهی، یک نکته دیگر اضافه کن:

The right categorical encoding is not selected independently of the model, validation strategy, cardinality, temporal structure, and serving constraints.

یعنی انتخاب encoding یک تصمیم isolated نیست؛ بخشی از کل ML pipeline design است.

⭐ 10 نکته‌ای که باید برای مصاحبه حفظ باشی

  1. One-Hot → مناسب nominal + low cardinality.
  2. Ordinal → فقط وقتی ordering واقعی وجود دارد.
  3. Label Encoding → بیشتر برای target یا ID-like representations؛ برای nominal input در بسیاری از مدل‌ها خطرناک است.
  4. Target Encoding → قدرتمند ولی high leakage risk.
  5. Target Encoding → smoothing برای rare categories ضروری/بسیار مفید است.
  6. OOF / Cross-Fitting برای target encoding در training بسیار مهم است.
  7. Frequency/Count Encoding → مناسب high-cardinality و بدون استفاده مستقیم از target.
  8. Hash Encoding → مناسب مقیاس بسیار بزرگ، با trade-off مربوط به collision.
  9. Native categorical models مثل CatBoost می‌توانند encoding دستی را در بسیاری از موارد غیرضروری کنند.
  10. هر encoder باید train-only fit شود و همان artifact در production استفاده شود.

و مهم‌ترین فرمول ذهنی این فصل:

Categorical Encoding = Cardinality + Semantics + Target Leakage + Model + CV + Production
