🏭 34. Production ML / MLOps — سطح Senior ML Engineer

در این بخش از ساخت مدل وارد دنیای واقعی می‌شویم.

بسیاری از ML Engineerهای Junior فقط این را بلدند:

Dataset | Train Model | Accuracy = 95%

اما در Production سؤال‌های اصلی این‌ها هستند:

این مدل چگونه دوباره train می‌شود؟
اگر داده تغییر کرد چه می‌کنیم؟
کدام نسخه مدل در Production است؟
چگونه مدل را deploy کنیم بدون downtime؟
اگر مدل خراب شد چگونه rollback کنیم؟
چگونه بفهمیم performance افت کرده؟
چگونه experimentها را reproduce کنیم؟

یک Senior ML Engineer باید کل lifecycle مدل را بفهمد:

ML Lifecycle Data | | Feature Engineering | | Training Pipeline | | Experiment Tracking | | Model Registry | | Deployment | | Monitoring | | Retraining | | Rollback

1. Training Pipeline

تعریف

Training Pipeline یعنی:

مجموعه مراحل اتوماتیک برای تولید یک مدل ML.

به جای اینکه دستی اجرا کنیم:

Python
python train.py

یک workflow داریم.

Pipeline ساده
Raw Data | v Data Validation | v Data Preprocessing | v Feature Engineering | v Train Model | v Evaluate | v Register Model
چرا Training Pipeline مهم است؟

فرض کنید امروز مدل Fraud Detection ساختید.

سه ماه بعد:

داده جدید آمده
feature جدید اضافه شده
مدل باید دوباره train شود

اگر pipeline نداشته باشید:

Engineer | Manual Steps | Errors | Different Results

با pipeline:

New Data | v Automatic Training | v Validation | v Deployment
اجزای یک Training Pipeline حرفه‌ای

2. Feature Store

یکی از مهم‌ترین مفاهیم MLOps.

مشکل چیست؟

فرض کنید:

Training:

Python Script feature: customer_age avg_transaction

Production:

API Service feature: customer_age avg_transaction

ممکن است calculation متفاوت باشد.

این مشکل:

Training-Serving Skew
Feature Store چیست؟

یک سیستم مرکزی برای مدیریت featureها.

Architecture:

Data Sources | | Feature Pipeline | | Feature Store / \ Offline Online | | Training Prediction
Offline Feature Store

برای training.

مثلاً:

Historical features:

customer_id avg_purchase_last_30_days
Online Feature Store

برای inference.

مثلاً:

در زمان درخواست:

Customer buys something | Need fraud score | Get latest features

Latency:

milliseconds.
Feature Store Responsibilities
Feature Definition

مثلاً:

average_transaction_30d = sum(transactions)/30
Feature Versioning

Feature تغییر کرد:

v1:

avg transaction 7 days

v2:

avg transaction 30 days
Feature Monitoring

بررسی:

Drift
Missing
Distribution

ابزارها:

Feast
Tecton
Vertex Feature Store
Databricks Feature Store

3. Model Registry

Model Registry یعنی:

محل مدیریت نسخه‌های مدل.

مثل Git برای مدل.

مثال:

Models Fraud_Model v1.0 accuracy: 0.91 v1.1 accuracy: 0.93 v2.0 accuracy: 0.95
Model Registry نگه می‌دارد:
Model Artifact

مثلاً:

model.pkl

یا:

model.pt
Metadata

مثل:

JSON
{ "model":"fraud", "version":"2.1", "accuracy":0.95, "dataset":"2025_data" }
Stage

معمولاً:

Development | Staging | Production

ابزارها:

MLflow Registry
AWS SageMaker Registry
Vertex AI Registry

8. Shadow Deployment

روش بسیار امن deploy.

ایده:

مدل جدید:

در کنار مدل قدیمی اجرا می‌شود.

ولی:

Output استفاده نمی‌شود.

Architecture:

User | Old Model | Production Result New Model | Shadow Result (ignored)

هدف:

مقایسه بدون ریسک.

مثلاً:

Model A:

Fraud probability: 0.1

Model B:

0.8

بررسی می‌کنیم.

13. Concept Drift

مهم‌تر از Data Drift.

یعنی:

رابطه:

X → Y

تغییر کرده.

مثال:

قبل:

Feature: High transaction Meaning: Fraud

بعد:

High transaction Meaning: Normal customer

Data همان است.

اما مفهوم تغییر کرده.

Canary:

تغییر X

Concept Drift:

تغییر رابطه X و Y

جمع‌بندی Senior Mental Model

یک ML Engineer معمولی:

Train Model Accuracy Done

یک Senior ML Engineer:

Can I reproduce it? Can I deploy it? Can I monitor it? Can I detect failure? Can I rollback? Can I retrain automatically? Can I explain why performance changed?

Production ML یعنی تبدیل یک مدل آزمایشگاهی به یک سیستم قابل اعتماد، قابل مانیتور و قابل نگهداری در مقیاس واقعی.
