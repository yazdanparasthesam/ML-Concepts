🧮 8. Regularization

1. Regularization چیست؟

Regularization مجموعه‌ای از تکنیک‌هاست که باعث می‌شود مدل:

بیش از حد روی Training Data فیت نشود و روی داده‌های جدید بهتر Generalize کند.

بدون Regularization، مدل ممکن است به جای یادگیری:

الگوهای واقعی

جزئیات خاص Training Set را هم یاد بگیرد.

مثلاً:

Training Data │ ├── True Pattern │ └── Noise / Randomness

مدل خوب:

True Pattern ──────────────► Learned Noise ─────────────────────► Ignored

مدل Overfit:

True Pattern ──────────────► Learned Noise ─────────────────────► Memorized

2. Regularization چه چیزی را کنترل می‌کند؟

ارتباط اصلی:

Regularization → Complexity → Variance → Generalization

به صورت ساده:

Regularization ↑ ↓ Effective Complexity ↓ ↓ Variance ↓ ↓ Overfitting ↓ ↓ Generalization ↑

اما این رابطه یک نکته بسیار مهم دارد:

Regularization بیش از حد هم بد است.

چون:

Regularization ↑↑↑ ↓ Model too constrained ↓ Bias ↑ ↓ Underfitting

بنابراین هدف:

Optimal Regularization

است، نه Maximum Regularization.

3. ارتباط با Bias–Variance Tradeoff

قبلاً داشتیم:

$$Expected Error \approx Bias^2 + Variance + Irreducible Error$$

Regularization معمولاً:

Variance ↓

ولی در عوض ممکن است:

Bias ↑

شود.

پس:

No / Weak Regularization │ ├── Bias ↓ └── Variance ↑ Strong Regularization │ ├── Bias ↑ └── Variance ↓

هدف پیدا کردن نقطه‌ای بین این دو است.

4. یک مثال بسیار مهم

فرض کن دو مدل داریم.

Model A
Training Error = 1% Validation Error = 20%

مدل:

High Variance

دارد.

احتمالاً Overfit است.

Model B
Training Error = 18% Validation Error = 19%

مدل:

High Bias

دارد.

احتمالاً Underfit است.

Model C
Training Error = 5% Validation Error = 7%

ممکن است تعادل خوبی داشته باشد.

5. Regularization در Objective Function

یکی از مهم‌ترین ایده‌ها:

به جای:

$$\min_{\theta} L(\theta)$$

می‌گوییم:

$$\min_{\theta} L(\theta) + \lambda \Omega(\theta)$$

که:

  • L: Loss
  • Ω: Regularization penalty
  • λ: Regularization strength

است.

6. λ چیست؟

$$\lambda$$

شدت Regularization را مشخص می‌کند.

λ کوچک
$$\lambda \rightarrow 0$$

یعنی:

تقریباً بدون Regularization
λ بزرگ
$$\lambda \uparrow$$

یعنی:

محدودیت بیشتر روی مدل

اما یک نکته بسیار مهم:

اگر λ خیلی بزرگ شود:

$$Bias \uparrow \uparrow$$

و ممکن است:

Underfitting

رخ دهد.

7. L1 Regularization

در L1:

$$\Omega(w) = ||w||_1 = \sum_{j} |w_j|$$

پس Objective:

$$J(w) = L(w) + \lambda \sum_{j} |w_j|$$

است.

8. اثر L1

L1 تمایل دارد بعضی Weightها را دقیقاً به:

$$0$$

برساند.

مثلاً:

Before:
w1 = 2.3 w2 = 0.8 w3 = 1.5 w4 = 0.02 w5 = 0.7
After L1:
w1 = 2.1 w2 = 0 w3 = 1.2 w4 = 0 w5 = 0

بنابراین:

L1 می‌تواند Sparse Model ایجاد کند.

9. چرا L1 وزن‌ها را Zero می‌کند؟

از نظر هندسی این نکته بسیار مهم است.

L1 constraint:

$$|w_1| + |w_2| \le c$$

شکل Diamond دارد:

/\ / \ / \ < > \ / \ / \/

گوشه‌های این شکل روی محورهای مختصات قرار دارند.

به همین دلیل نقطه بهینه می‌تواند روی محور قرار گیرد:

$$w_j = 0$$

10. L1 و Feature Selection

اگر Feature x_j وزن:

$$w_j = 0$$

بگیرد، آن Feature در مدل Linear عملاً contribution ندارد.

بنابراین L1 می‌تواند:

Embedded Feature Selection

انجام دهد.

11. مزایای L1

مناسب است وقتی:

  • Featureهای زیاد داریم.
  • انتظار داریم فقط subset کوچکی مهم باشد.
  • Sparse solution می‌خواهیم.
  • Feature selection برایمان مهم است.
  • مدل interpretability بیشتری می‌خواهیم.

12. مشکل L1 با Features Correlated

فرض کن:

$$X1 \approx X2 \approx X3$$

سه Feature بسیار correlated هستند.

L1 ممکن است:

X1 → weight 0 X2 → weight 0 X3 → weight 2

کند.

یا بسته به داده:

X1 → 2 X2 → 0 X3 → 0

یعنی ممکن است بین Featureهای correlated به شکل ناپایداری انتخاب کند.

13. L2 Regularization

L2:

$$\Omega(w) = ||w||_2^2 = \sum_{j} w_j^2$$

و:

$$J(w) = L(w) + \lambda \sum_{j} w_j^2$$

14. اثر L2

L2 معمولاً وزن‌ها را:

کوچک

می‌کند.

اما برخلاف L1 معمولاً آن‌ها را دقیقاً صفر نمی‌کند.

مثلاً:

Before:
10 5 3 1
After L2:
3.2 2.1 1.4 0.6

به جای:

3 0 0 0

15. چرا L2 وزن‌ها را کوچک می‌کند؟

Gradient جریمه:

$$\frac{\partial}{\partial w_j} \lambda w_j^2 = 2\lambda w_j$$

پس هرچه وزن بزرگ‌تر باشد:

Penalty بزرگ‌تر می‌شود.

مدل ترجیح می‌دهد Weightهای خیلی بزرگ نداشته باشد.

16. L2 از نظر هندسی

Constraint:

$$w_1^2 + w_2^2 \le c$$

شکل دایره دارد:

______ .-' '-. / \ | | \ / '-.______.-'

برخلاف L1 که گوشه دارد، L2 سطح smooth دارد.

17. L1 vs L2

ویژگیL1L2
Penalty\(\sum |w|\)\(\sum w^2\)
Weight → 0زیادکمتر
Sparse modelبلهمعمولاً نه
Feature selectionبلهمعمولاً نه
Smoothنه در صفربله
Correlated featuresممکن است یکی را انتخاب کندمعمولاً بینشان توزیع می‌کند
Common nameLassoRidge

18. Ridge Regression

Linear Regression با L2:

$$\min_{w} \sum_{i} (y_i - w^T x_i)^2 + \lambda ||w||_2^2$$

به آن:

Ridge Regression

می‌گوییم.

19. Lasso Regression

Linear Regression با L1:

$$\min_{w} \sum_{i} (y_i - w^T x_i)^2 + \lambda ||w||_1$$

به آن:

Lasso Regression

می‌گوییم.

20. Elastic Net

Elastic Net ترکیب:

L1 + L2

است.

$$J(w) = L(w) + \lambda (\alpha ||w||_1 + (1-\alpha)||w||_2^2)$$

21. α در Elastic Net

اگر:

$$\alpha = 1$$

تقریباً:

L1

اگر:

$$\alpha = 0$$

تقریباً:

L2

و:

$$0 < \alpha < 1$$

ترکیبی از هر دو.

22. چرا Elastic Net مهم است؟

خصوصاً زمانی که:

High-dimensional data + Correlated features

داریم.

مثلاً در:

  • Genomics
  • NLP
  • High-dimensional tabular data

Elastic Net می‌تواند نسبت به Lasso رفتار پایدارتر داشته باشد.

23. L1 vs Elastic Net

اگر Featureهای correlated زیادی داری:

Lasso
↓ ممکن است یکی را انتخاب کند و بقیه را حذف کند
Elastic Net
↓ می‌تواند گروهی از Featureهای مرتبط را حفظ کند

24. Weight Decay

Weight Decay یعنی در هر Update وزن‌ها کمی به سمت صفر کشیده شوند.

به صورت ساده:

$$w_{t+1} = (1 - \eta \lambda)w_t - \eta g_t$$

قسمت:

$$(1 - \eta \lambda)w_t$$

باعث کاهش وزن می‌شود.

25. Weight Decay vs L2

این موضوع برای Senior ML بسیار مهم است.

در Vanilla SGD با شرایط استاندارد:

L2 regularization و weight decay تقریباً معادل‌اند.

چون:

$$L(w) + \frac{\lambda}{2} ||w||^2$$

gradient می‌دهد:

$$g + \lambda w$$

و:

$$w_{t+1} = w_t - \eta(g + \lambda w_t)$$

که می‌شود:

$$w_{t+1} = (1 - \eta \lambda)w_t - \eta g$$

اما در:

Adam / adaptive optimizers

این equivalence به همان شکل برقرار نیست.

به همین دلیل:

AdamW

مهم است.

26. AdamW

AdamW:

Decoupled Weight Decay

دارد.

یعنی:

Adam adaptive gradient update + separate weight decay

این باعث می‌شود Weight Decay واقعاً مستقل از adaptive scaling اعمال شود.

27. آیا Weight Decay روی همه Parameters اعمال شود؟

نکته Senior:

در بسیاری از Transformerها و مدل‌های مدرن، معمولاً Weight Decay را روی:

  • Weightهای Linear
  • بعضی Matrixهای اصلی

اعمال می‌کنند.

ولی اغلب روی:

  • Bias
  • بعضی normalization parameters

اعمال نمی‌کنند.

چرا؟

چون Regularizing این پارامترها همیشه مفید نیست و می‌تواند رفتار مدل را بدتر کند.

28. Dropout

Dropout یکی از معروف‌ترین روش‌های Regularization در Neural Networks است.

در Training:

تعدادی از Activationها به صورت تصادفی صفر می‌شوند.

مثلاً:

Original:
● ● ● ● ● ●
Dropout:
● 0 ● 0 0 ●

29. Dropout Rate

مثلاً:

$$p = 0.2$$

یعنی 20٪ واحدها drop شوند.

30. Inverted Dropout

در پیاده‌سازی‌های مدرن معمولاً Activationهای باقی‌مانده را scale می‌کنیم.

اگر:

$$p = 0.2$$

احتمال نگه‌داشتن:

$$q = 1 - p = 0.8$$

است.

Activation:

$$h$$

اگر نگه داشته شود:

$$h' = \frac{h}{q}$$

می‌شود.

هدف:

حفظ Expected Activation

است.

31. Dropout چه کاری انجام می‌دهد؟

مدل را مجبور می‌کند که:

بیش از حد به یک مسیر یا Feature خاص وابسته نشود.

یعنی:

Feature A ↓ Feature B ↓ Prediction

را سخت‌تر می‌کند.

مدل مجبور می‌شود:

A B C D

را robustتر استفاده کند.

32. Dropout و Ensemble

یک تفسیر معروف:

Dropout تقریباً شبیه آموزش تعداد زیادی subnet مختلف است.

مثلاً:

Network │ ├── subnet 1 ├── subnet 2 ├── subnet 3 ├── subnet 4 └── ...

در inference شبکه کامل استفاده می‌شود.

به همین دلیل Dropout ارتباط مفهومی با:

Ensemble / Model Averaging

دارد.

34. Dropout زیاد

اگر:

$$p$$

بیش از حد زیاد باشد:

Too much information removed ↓ Underfitting ↓ Bias ↑

مثلاً در برخی مدل‌ها:

Dropout = 0.8

ممکن است بسیار شدید باشد.

35. Dropout و BatchNorm

ترکیب:

BatchNorm + Dropout

باید با توجه به architecture و نوع مدل ارزیابی شود.

در بسیاری از شبکه‌های مدرن، مخصوصاً برخی معماری‌های vision، استفاده از BatchNorm یا سایر normalizationها باعث شده Dropout به اندازه گذشته ضروری نباشد.

در Transformerها هم:

Dropout معمولاً هنوز استفاده می‌شود، ولی محل و مقدار آن architecture-dependent است.

36. Early Stopping

Early Stopping یک Regularization بسیار مهم است.

فرض کن:

Epoch Train Loss Val Loss 1 ↓ ↓ 5 ↓ ↓ 10 ↓ ↓ 20 ↓ ↓ 30 ↓ → 40 ↓ ↑ 50 ↓ ↑↑

در نقطه‌ای Validation شروع به بدتر شدن می‌کند.

پس Training را متوقف می‌کنیم.

37. چرا Early Stopping Regularization است؟

چون اجازه نمی‌دهد مدل:

بیش از حد روی Training Data fit شود.

در واقع Training Time را محدود می‌کنیم.

پس:

$$Effective Model Complexity \downarrow$$

38. Early Stopping و Optimization

نکته ظریف:

Early Stopping صرفاً:

«Training را زود متوقف می‌کنیم»

نیست.

بلکه یک نوع محدودیت روی Optimization Path است.

مدل ممکن است اگر به Training ادامه دهد:

Training Loss ↓ Validation Loss ↑

پس نقطه‌ای را انتخاب می‌کنیم که Generalization بهتر است.

39. Early Stopping و L2

در بعضی شرایط ساده، Early Stopping در Gradient Descent می‌تواند رفتاری شبیه یک نوع Regularization ایجاد کند.

این به این معنی نیست که:

Early stopping همیشه دقیقاً معادل L2 است.

بلکه:

هر دو می‌توانند solutionهای کم‌پیچیدگی‌تر را ترجیح دهند، اما mechanism آن‌ها متفاوت است.

40. Data Augmentation

Data Augmentation یعنی:

از داده موجود نمونه‌های جدید و معنادار تولید کنیم.

مثلاً تصویر:

Original
↓ Flip Rotate Crop Color change Noise

41. چرا Data Augmentation Regularization است؟

چون مدل مجبور می‌شود:

Invariant properties

را یاد بگیرد.

مثلاً در تشخیص گربه:

Cat

اگر کمی:

  • Rotate
  • Shift
  • Crop

شود، هنوز Cat است.

پس مدل باید:

به ویژگی‌های meaningful

وابسته شود، نه به جزئیات تصادفی.

42. Data Augmentation و Inductive Bias

این یک نکته بسیار Senior است.

وقتی می‌گویی:

Rotation برای این مسئله label را تغییر نمی‌دهد.

در واقع داری یک:

Inductive Bias

وارد مدل می‌کنی.

یعنی به مدل می‌گویی:

$$f(x) \approx f(T(x))$$

برای Transformationهای معتبر T.

43. مثال

در Object Detection:

Original: Car Rotate: Car Crop: Car Brightness: Car

پس augmentation کمک می‌کند مدل نسبت به این تغییرات invariant باشد.

44. اما Data Augmentation می‌تواند خطرناک باشد.

اگر Transformation label را تغییر دهد:

Augmentation اشتباه است.

مثلاً در Digit Classification:

6

را 180 درجه rotate کنی ممکن است دیگر:

6

نباشد.

پس:

$$Label(T(x)) = Label(x)$$

باید تقریباً معتبر باشد.

45. Data Augmentation و Distribution

یک نکته مهم:

Augmentation نباید distribution مصنوعی غیرواقعی بسازد.

مثلاً:

Real world: Brightness ∈ [0,1] Augmentation: Brightness ∈ [0,100]

ممکن است مدل را به چیزهایی عادت دهد که در Production وجود ندارند.

46. Noise Injection

Noise Injection یعنی:

به Input، Hidden Representation یا حتی بعضی Training signals نویز اضافه کنیم.

مثلاً:

$$x' = x + \epsilon$$

که:

$$\epsilon \sim \mathcal{N}(0, \sigma^2)$$

47. چرا Noise Injection Regularization است؟

مدل را مجبور می‌کند:

نسبت به تغییرات کوچک Robust باشد.

بدون Noise:

x → prediction

با Noise:

x + ε x + ε' x + ε'' ↓ similar prediction

48. Noise Injection و Smoothness

Noise Injection می‌تواند مدل را به سمت:

Smooth Function

هل دهد.

یعنی تغییر کوچک در Input باعث تغییر شدید Output نشود.

این مفهوم برای:

  • Robustness
  • Generalization
  • Stability

مهم است.

49. Noise در Weight

می‌توان حتی:

$$W' = W + \epsilon$$

استفاده کرد.

این هم نوعی stochastic regularization محسوب می‌شود.

50. Label Smoothing

Label Smoothing بیشتر در Classification استفاده می‌شود.

فرض کن سه کلاس:

Cat Dog Horse

Label معمولی:

[1, 0, 0]

با Label Smoothing:

[0.9, 0.05, 0.05]

مثلاً.

51. چرا Label Smoothing؟

مدل بدون smoothing ممکن است برای یک نمونه:

$$P(y|x) = 0.999999$$

تولید کند.

یعنی:

Overconfident

شود.

Label Smoothing این فشار را کاهش می‌دهد.

52. فرمول Label Smoothing

برای K کلاس و smoothing factor ϵ:

یک convention رایج:

$$y_k' = (1 - \epsilon)y_k + \frac{\epsilon}{K}$$

در این convention اگر label واقعی:

[1, 0, 0]

باشد:

$$\epsilon = 0.1$$

می‌دهد:

[0.9333, 0.0333, 0.0333]

توجه کن که پیاده‌سازی‌ها ممکن است smoothing mass را با convention کمی متفاوت توزیع کنند.

53. Label Smoothing چه اثری دارد؟

معمولاً:

Confidence ↓ Overconfidence ↓ Generalization ↑ Calibration ممکن است بهتر شود

اما یک نکته مهم:

Label smoothing لزوماً همیشه calibration را بهتر نمی‌کند.

باید empirically بررسی شود.

54. Label Smoothing و Cross Entropy

بدون smoothing:

$$L = - \sum_{k} y_k \log p_k$$

با smoothing:

$$L = - \sum_{k} y_k' \log p_k$$

پس target دیگر One-Hot خالص نیست.

55. Max-Norm Constraint

در Max-Norm به جای اینکه فقط penalty اضافه کنیم، مستقیماً محدودیت روی Norm وزن قرار می‌دهیم:

$$||w||_2 \le c$$

اگر Weight از حد مجاز بزرگ‌تر شود:

Projection

انجام می‌شود.

56. Max-Norm

مثلاً:

||w|| = 8 c = 5

پس Weightها scale می‌شوند تا:

$$||w|| = 5$$

شود.

57. Max-Norm vs L2

L2:
Penalty ↓ Weight بزرگ هزینه بیشتری دارد
Max-Norm:
Hard constraint ↓ Weight نمی‌تواند از حد مشخص عبور کند

پس:

L2: Soft constraint
Max-Norm: Hard constraint

60. مهم‌ترین تفاوت L1 و L2

اگر در مصاحبه بپرسند:

چرا L1 sparse می‌کند ولی L2 نه؟

جواب سطح Senior:

L1 penalty دارای مقدار مطلق است و geometry آن constraint دارای گوشه‌هایی روی coordinate axes دارد؛ بنابراین solution به‌طور طبیعی می‌تواند روی این axes قرار بگیرد و بعضی coefficients دقیقاً صفر شوند. در مقابل L2 دارای penalty smooth و geometry دایره/کره‌ای است و معمولاً coefficients را shrink می‌کند بدون اینکه دقیقاً صفرشان کند.

86. Bias Term را Regularize کنیم؟

در بسیاری از پیاده‌سازی‌ها:

چرا؟

87. Regularization در Logistic Regression

مثلاً:

$$P(y=1|x) = \sigma(w^T x + b)$$

Objective:

$$Loss + \lambda ||w||_2^2$$

معمولاً b را جدا از Weightهای feature regularize می‌کنیم یا اصلاً regularize نمی‌کنیم، بسته به implementation.

88. Regularization و SVM

در SVM هم مفهوم Regularization بسیار بنیادی است.

مثلاً:

$$\frac{1}{2} ||w||^2 + C \sum_{i} \xi_i$$

در اینجا:

Trade-off بین margin/complexity و training violations

وجود دارد.

این دقیقاً همان فلسفه:

Complexity ↔ Fit

است.

89. Regularization و Bayesian Interpretation

یک نکته خیلی پیشرفته.

L2 Regularization را می‌توان به صورت Bayesian interpretation هم دید.

اگر فرض کنیم:

$$w \sim \mathcal{N}(0, \sigma^2 I)$$

یعنی Prior Gaussian روی Weightها داریم.

Maximum A Posteriori estimation می‌تواند منجر به:

$$L(w) + \lambda ||w||_2^2$$

شود.

90. L1 و Bayesian Interpretation

L1 با:

Laplace Prior

ارتباط دارد.

$$p(w) \propto e^{-\lambda |w|}$$

پس:

L1 ↔ Laplace prior L2 ↔ Gaussian prior

این یکی از پاسخ‌های خیلی خوب برای مصاحبه Senior/Research است.

91. یک نگاه Unified

می‌توانیم Regularization را به شکل زیر ببینیم:

$$Fit Data + Preference for Simpler/Robust Solutions$$

مثلاً:

L1 → Sparse solution L2 → Small weights Dropout → Distributed robust representations Augmentation → Invariance Label Smoothing → Less overconfident predictions Early Stopping → Limited optimization complexity Max-Norm → Bounded weights

92. مهم‌ترین سؤال مصاحبه‌ای

سؤال:

چرا Regularization می‌تواند Generalization را بهتر کند، در حالی که Training Error را بدتر می‌کند؟

جواب Senior:

چون هدف Training Error کمینه کردن خطای روی نمونه‌های دیده‌شده است، در حالی که هدف اصلی ML، کاهش Expected Generalization Error است. Regularization فضای solutionهای ممکن را محدود می‌کند و از fitting جزئیات و noise موجود در Training Set جلوگیری می‌کند. در نتیجه ممکن است Training Error کمی افزایش پیدا کند، اما Variance کاهش یابد و Validation/Test Error بهتر شود. اگر Regularization بیش از حد باشد، Bias زیاد شده و Underfitting رخ می‌دهد.

93. سؤال دوم

L1 چرا Feature Selection انجام می‌دهد ولی L2 معمولاً نه؟

چون L1 دارای penalty با |w| و geometry دارای گوشه است و optimum می‌تواند روی coordinate axes قرار گیرد، بنابراین coefficients دقیقاً صفر می‌شوند. L2 smooth است و بیشتر Weightها را shrink می‌کند ولی معمولاً به صفر دقیق نمی‌رساند.

94. سؤال سوم

Weight Decay و L2 همیشه یکی هستند؟

جواب:

خیر.

در Vanilla SGD در شرایط معمول می‌توان آن‌ها را تقریباً معادل دانست، اما در adaptive optimizers مانند Adam این equivalence برقرار نیست. به همین دلیل AdamW از decoupled weight decay استفاده می‌کند.

95. سؤال چهارم

آیا Dropout همیشه Generalization را بهتر می‌کند؟

خیر.

Dropout یک hyperparameter است. اگر بیش از حد استفاده شود:

$$Bias \uparrow$$

و:

Underfitting

رخ می‌دهد.

شدت مناسب آن باید با Validation/CV تعیین شود.

96. سؤال پنجم

آیا Data Augmentation همیشه خوب است؟

خیر.

Augmentation باید transformationهایی ایجاد کند که:

$$P(y|T(x))$$

با مسئله واقعی سازگار باشند.

اگر augmentation label semantics را تغییر دهد یا distribution غیرواقعی ایجاد کند، می‌تواند عملکرد را خراب کند.

97. سؤال ششم

آیا Early Stopping واقعاً Regularization است؟

بله، معمولاً به عنوان نوعی Regularization در نظر گرفته می‌شود، چون Optimization را قبل از اینکه مدل بیش از حد Training Data را fit کند متوقف می‌کند. همچنین در برخی مسائل ساده می‌تواند رفتار مشابهی با shrinkage داشته باشد، اما دقیقاً معادل L2 در همه شرایط نیست.

98. سؤال هفتم

Regularization Bias را زیاد می‌کند یا Variance را؟

در چارچوب کلاسیک:

$$Regularization \rightarrow Bias \uparrow, Variance \downarrow$$

اما هدف پیدا کردن نقطه‌ای است که مجموع خطای Generalization حداقل شود.

99. نقشه ذهنی نهایی

REGULARIZATION │ ┌──────────────────┼──────────────────┐ │ │ │ PENALTY STOCHASTIC DATA │ │ │ ┌───┴────┐ ┌───┴────┐ Augmentation │ │ │ │ L1 L2 Dropout Noise │ │ │ └──────┐ │ │ └──── Elastic Net │ OTHER METHODS │ ┌───────────┼───────────┐ │ │ │ Early Stop Label Smooth Max-Norm

و ارتباط اصلی:

Regularization │ ▼ Effective Complexity │ ┌─────────┴─────────┐ ▼ ▼ Bias ↑ Variance ↓ │ │ └─────────┬─────────┘ ▼ Generalization │ ┌──────┴──────┐ ▼ ▼ Underfit Overfit if too much if too little

🎯 جمع‌بندی Senior

اگر بخواهم کل این فصل را در یک جمله خلاصه کنم:

Regularization یعنی وارد کردن یک ترجیح یا محدودیت در فرآیند یادگیری تا مدل به‌جای حفظ کردن جزئیات خاص Training Data، solutionهایی را یاد بگیرد که روی داده‌های ندیده بهتر Generalize می‌کنند.

و مهم‌تر از حفظ کردن فرمول‌ها، باید بتوانی این زنجیره را توضیح بدهی:

$$Regularization \rightarrow Effective Complexity \rightarrow Bias/Variance \rightarrow Overfitting/Underfitting \rightarrow Generalization$$

و در سطح Senior، باید بتوانی با توجه به نوع داده و مشکل مدل انتخاب کنی:

Sparse high-dimensional features → L1 / Elastic Net Correlated features → L2 / Elastic Net Deep Neural Network overfitting → Weight Decay / Dropout / Augmentation / Early Stopping Computer Vision → Augmentation / Weight Decay / Mixup / CutMix Overconfident classifier → Label Smoothing + Calibration analysis Exploding weights → Max-Norm / Weight Decay + investigate LR/optimization Adaptive optimizer → AdamW rather than treating L2 and weight decay as identical

نکته نهایی و خیلی مهم: Regularization را نباید «هرچه بیشتر بهتر» دید. مسئله واقعی همیشه پیدا کردن نقطه‌ای است که Bias و Variance، Training Fit و Generalization، و Complexity و Robustness بهترین trade-off را داشته باشند.
