📐 14. Dimensionality Reduction

حتماً. این بخش Dimensionality Reduction از مباحثی است که برای سطح Senior باید فقط تعریف الگوریتم‌ها را بلد نباشی؛ باید بفهمی چه چیزی را حفظ می‌کنند، چه چیزی را از بین می‌برند، چه زمانی باعث leakage می‌شوند، چه زمانی برای visualization مناسب‌اند، و چه تفاوتی با feature selection دارند.

📐 14. Dimensionality Reduction

فرض کن dataset ما این شکلی است:

$$X \in \mathbb{R}^{n \times d}$$

که:

  • n = تعداد samples
  • d = تعداد features

مثلاً:

100,000 samples
10,000 features

یعنی:

$$X \in \mathbb{R}^{100000 \times 10000}$$

مشکلات:

  • memory زیاد
  • training کند
  • noise زیاد
  • overfitting
  • visualization سخت
  • فاصله‌ها در فضای high-dimensional عجیب می‌شوند
  • بعضی مدل‌ها با تعداد feature زیاد بدتر می‌شوند

اینجاست که:

Dimensionality Reduction

مطرح می‌شود.

1. Dimensionality Reduction چیست؟

هدف این است که:

$$X \in \mathbb{R}^d$$

را به:

$$Z \in \mathbb{R}^k$$

تبدیل کنیم که:

$$k \ll d$$

مثلاً:

10,000 features ↓ PCA ↓ 100 components

پس:

$$10,000 \to 100$$

اما نکته مهم:

ما الزاماً featureهای اصلی را حذف نمی‌کنیم؛ ممکن است featureهای جدیدی بسازیم. این تفاوت بسیار مهم است.

2. سه مفهوم را از هم جدا کن

سه مفهوم مهم داریم:

Feature Selection

از featureهای موجود، تعدادی را انتخاب می‌کنیم.

Feature Extraction

از featureهای موجود، featureهای جدید می‌سازیم.

Dimensionality Reduction

تعداد dimensions را کاهش می‌دهیم.

بنابراین:

$$\text{Feature Selection} \neq \text{Feature Extraction}$$

و:

Dimensionality Reduction می‌تواند با Feature Extraction انجام شود.

3. Feature Selection

فرض کن:

x = [
    age,
    income,
    height,
    weight,
    country,
    device,
    transaction_amount,
    ...
]

اگر 100 feature داشته باشیم و فقط 20 تای آن را نگه داریم:

100 ↓ 20 original features

هیچ feature جدیدی ایجاد نکرده‌ایم.

مثلاً:

  • age
  • income
  • transaction_amount

همان featureهای اصلی هستند.

4. Feature Extraction

اینجا feature جدید می‌سازیم.

مثلاً:

  • age
  • income
  • debt

را ترکیب کنیم:

$$z_1 = 0.3 \cdot \text{age} + 0.5 \cdot \text{income} - 0.2 \cdot \text{debt}$$

حالا:

z₁ یک feature جدید است.

5. PCA دقیقاً چه کار می‌کند؟

PCA:

Principal Component Analysis

یکی از مهم‌ترین روش‌های linear dimensionality reduction است.

ایده اصلی:

جهت‌هایی را پیدا می‌کند که بیشترین variance داده را توضیح می‌دهند.

6. Intuition مربوط به PCA

فرض کن داده‌ها تقریباً این شکلی باشند:

• • • • •

در فضای دوبعدی، اطلاعات اصلی تقریباً روی یک خط قرار دارد.

پس به جای:

  • X₁
  • X₂

می‌توانیم یک محور جدید بسازیم:

PC₁

و بیشتر اطلاعات را حفظ کنیم.

7. Principal Component چیست؟

Component جدید به صورت linear combination ساخته می‌شود:

$$PC_1 = w_1 X_1 + w_2 X_2 + \cdots + w_d X_d$$

یا:

$$z_1 = X w_1$$

که:

w₁ جهتی است که بیشترین variance را capture می‌کند.

8. PCA Componentها

PCA چند محور جدید پیدا می‌کند:

$$PC_1, PC_2, \dots, PC_d$$

که:

$$Var(PC_1) > Var(PC_2) > \dots > Var(PC_d)$$

و componentها orthogonal هستند.

9. چرا PCها orthogonal هستند؟

در PCA componentها عمود بر هم هستند.

یعنی:

$$w_i^T w_j = 0 \quad \text{برای} \quad i \neq j$$

این باعث می‌شود componentها اطلاعات خطی تکراری را تا حد ممکن جدا کنند.

10. PCA و Covariance Matrix

یکی از روش‌های کلاسیک PCA:

ابتدا داده را center می‌کنیم:

$$X_c = X - \mu$$

سپس covariance matrix:

$$\Sigma = \frac{1}{n-1} X_c^T X_c$$

را محاسبه می‌کنیم.

بعد eigenvalue/eigenvectorهای آن را پیدا می‌کنیم.

11. Eigenvector در PCA

Eigenvectorها جهت componentها هستند.

اگر:

$$\Sigma v = \lambda v$$

آنگاه:

  • v = eigenvector
  • λ = eigenvalue

هرچه eigenvalue بزرگ‌تر باشد:

variance بیشتری در آن direction وجود دارد.

پس:

Largest eigenvalue ↓ PC1 ↓ Second largest ↓ PC2

12. Explained Variance

یکی از مهم‌ترین مفاهیم PCA:

Explained Variance

است.

مثلاً:

  • PC1 → 60%
  • PC2 → 20%
  • PC3 → 10%
  • PC4 → 5%
  • PC5 → 3%
  • PC6 → 2%

پس cumulative:

  • PC1 = 60%
  • PC1+PC2 = 80%
  • PC1..3 = 90%
  • PC1..4 = 95%

می‌توانیم مثلاً 95% variance را حفظ کنیم.

13. Explained Variance Ratio

فرمول:

$$EVR_i = \frac{\lambda_i}{\sum_j \lambda_j}$$

و cumulative:

$$CEVR_k = \sum_{i=1}^k EVR_i$$

14. انتخاب تعداد Components

سه روش رایج:

روش 1 — Threshold
  • 95%
  • 99%

مثلاً:

CEVR ≥ 0.95
روش 2 — Fixed dimension

مثلاً:

100 → 20
روش 3 — Performance-based

چند مقدار مختلف را امتحان کن:

  • 10 components
  • 20 components
  • 50 components
  • 100 components

و validation performance را مقایسه کن.

15. نکته بسیار مهم

⚠️ بیشترین explained variance الزاماً به معنی بهترین predictive performance نیست.

ممکن است target information در variance پایین dataset باشد.

مثلاً:

  • PC1 → 80% variance
  • PC2 → 10%
  • PC3 → 5%
  • PC4 → 3%
  • PC5 → 2%

ولی target بیشتر با PC5 مرتبط باشد.

پس:

High Variance ≠ High Predictive Power

16. PCA بدون Scaling

فرض کن:

  • age: 20-60
  • income: 10,000-1,000,000

income variance بسیار بزرگ‌تری دارد.

PCA ممکن است عمدتاً تحت تأثیر income قرار بگیرد.

پس معمولاً:

StandardScaler ↓ PCA

استفاده می‌شود.

17. آیا همیشه باید Standardize کنیم؟

نه.

اگر scaleها معنای واقعی دارند و نمی‌خواهی feature با variance کوچک را از نظر importance نادیده بگیری، ممکن است scaling نخواهی.

بنابراین:

Scaling یک تصمیم domain/model-dependent است.

18. PCA روی Sparse Data

PCA معمولی معمولاً matrix را dense می‌کند.

اگر data خیلی sparse باشد، مثلاً:

TF-IDF

این می‌تواند مشکل memory ایجاد کند.

اینجا:

Truncated SVD

بسیار مهم است.

19. SVD

Singular Value Decomposition:

$$X = U \Sigma V^T$$

که:

  • U = left singular vectors
  • Σ = singular values
  • V^T = right singular vectors

20. تفاوت Eigen Decomposition و SVD

PCA را می‌توان با eigen decomposition covariance matrix انجام داد.

اما SVD مستقیماً روی:

$$X$$

کار می‌کند.

این در عمل معمولاً:

  • numerical stableتر
  • و برای داده‌های بزرگ مناسب‌تر است

21. Truncated SVD

در SVD کامل:

X ↓ U Σ Vᵀ

تمام components را داریم.

اما در Truncated SVD فقط:

$$k$$

component اول را نگه می‌داریم:

$$X \approx U_k \Sigma_k V_k^T$$

که:

$$k \ll d$$

22. Truncated SVD و NLP

یکی از کاربردهای کلاسیک:

Documents ↓ TF-IDF ↓ Sparse Matrix ↓ Truncated SVD ↓ Low-dimensional representation

این ایده در:

Latent Semantic Analysis (LSA)

مشهور است.

24. Kernel PCA

PCA فقط روابط:

Linear

را می‌بیند.

فرض کن داده:

••• • • • • • • •••

باشد.

در فضای اصلی، structure غیرخطی است.

Kernel PCA می‌تواند ابتدا داده را به فضای feature غیرخطی implicit ببرد:

$$x \to \phi(x)$$

و سپس PCA انجام دهد.

25. Kernel Trick

به جای محاسبه مستقیم:

$$\phi(x)$$

از kernel استفاده می‌کنیم:

$$K(x_i, x_j) = \phi(x_i)^T \phi(x_j)$$

مثلاً:

RBF Kernel
$$K(x, x') = e^{-\gamma \|x - x'\|^2}$$

26. Kernel PCA چه زمانی مفید است؟

وقتی:

structure داده nonlinear باشد.

اما هزینه محاسباتی آن می‌تواند زیاد باشد.

برای:

$$n$$

sample، kernel matrix:

$$n \times n$$

داریم.

پس:

$$O(n^2)$$

memory فقط برای kernel matrix می‌تواند مشکل‌ساز شود.

27. t-SNE

t-SNE:

t-distributed Stochastic Neighbor Embedding

بیشتر برای:

Visualization

است.

مثلاً:

28. ایده اصلی t-SNE

t-SNE سعی می‌کند:

همسایه‌های نزدیک در فضای high-dimensional در فضای low-dimensional نیز نزدیک باقی بمانند.

یعنی local structure را حفظ می‌کند.

29. t-SNE چه چیزی را خوب حفظ می‌کند؟

Local Neighborhoods

مثلاً اگر:

  • A نزدیک B
  • A نزدیک C

باشد، t-SNE سعی می‌کند:

A B C

را نزدیک نگه دارد.

30. t-SNE چه چیزی را خوب حفظ نمی‌کند؟

Global distances

اگر دو cluster در t-SNE خیلی دور باشند، الزاماً نمی‌توان گفت:

این دو cluster در فضای اصلی دقیقاً همین‌قدر دور بوده‌اند.

31. یک اشتباه بسیار رایج

⚠️ این:
Cluster A Cluster B

در t-SNE

به این معنی نیست که:

A و B ذاتاً دو گروه واقعی و جدا هستند.

t-SNE می‌تواند ساختارهای cluster-like ایجاد کند.

پس:

t-SNE is visualization, not proof of clustering

این قابلیت آن را برای pipelineها جذاب‌تر می‌کند.

اما هنوز باید leakage، stability و downstream performance را بررسی کرد.

41. Autoencoder

Autoencoder یک neural network است که سعی می‌کند:

$$X \to Z \to \hat{X}$$

را یاد بگیرد.

ساختار:

Input │ ▼ Encoder │ ▼ Latent Space │ ▼ Decoder │ ▼ Reconstruction

42. Encoder

Encoder:

$$z = f_\theta(x)$$

است.

مثلاً:

100 features ↓ 64 ↓ 32 ↓ 10

پس:

Latent representation = 10 dimensions

43. Decoder

Decoder:

$$\hat{x} = g_\phi(z)$$

است.

هدف:

$$\hat{x} \approx x$$

است.

44. Loss Autoencoder

مثلاً:

$$L = \|x - \hat{x}\|^2$$

یا:

$$MAE(x, \hat{x})$$

پس شبکه یاد می‌گیرد representationای بسازد که بتواند input را reconstruct کند.

45. چرا Autoencoder Dimensionality Reduction است؟

چون:

X ↓ Encoder ↓ Z

داریم و:

$$\dim(Z) \ll \dim(X)$$

مثلاً:

$$1000 \to 32$$

46. تفاوت PCA و Autoencoder

PCA:

$$Z = WX$$

یعنی transformation خطی.

Autoencoder:

$$Z = f_\theta(X)$$

می‌تواند nonlinear باشد.

پس:

$$PCA \subset \text{Linear Representation}$$

ولی:

$$Autoencoder \to \text{Nonlinear Representation}$$

47. Autoencoder و PCA

یک نکته مهم مصاحبه‌ای:

یک autoencoder خطی با معماری مناسب و MSE می‌تواند subspace مشابه PCA را یاد بگیرد.

پس PCA را می‌توان یک baseline بسیار مهم برای autoencoder دانست.

48. انواع Autoencoder

Undercomplete Autoencoder

latent dimension کمتر از input:

1000 → 32

برای dimensionality reduction مناسب است.

Overcomplete Autoencoder

latent dimension بزرگ‌تر یا مساوی input.

ممکن است بدون regularization فقط identity function یاد بگیرد:

f(x) ≈ x

پس الزاماً dimensionality reduction نیست.

49. Denoising Autoencoder

به جای reconstruct کردن input تمیز از input تمیز:

Clean X ↓ Add Noise ↓ Noisy X ↓ Encoder ↓ Decoder ↓ Reconstruct Clean X

هدف:

robust representation

50. Variational Autoencoder

VAE فقط یک vector deterministic نمی‌سازد.

بلکه distribution یاد می‌گیرد:

$$q(z \mid x)$$

و latent space ساختار probabilistic دارد.

VAE بیشتر برای:

  • generative modeling
  • representation learning
  • latent space learning

است.

51. آیا VAE فقط Dimensionality Reduction است؟

نه.

VAE اساساً:

Generative Model

است.

اما latent representation آن می‌تواند برای dimensionality reduction استفاده شود.

54. ارتباط PCA و SVD

63. Dimensionality Reduction و Leakage

⚠️ یکی از مهم‌ترین نکات Senior.

فرض کن:

  • Train
  • Validation

داری.

غلط:

Train + Validation ↓ PCA ↓ Split

چون PCA statistics را از validation دیده است.

تمام transformationهایی که از داده statistics یاد می‌گیرند باید داخل CV fit شوند.

67. آیا PCA باید قبل از Train/Test Split انجام شود؟

خیر، اگر PCA از data statistics استفاده می‌کند.

روش صحیح:

Train → Fit(PCA)

سپس:

Validation/Test → Transform(PCA)

68. PCA و Supervised Learning

PCA کاملاً unsupervised است.

یعنی target را نمی‌بیند:

$$PCA(X)$$

نه:

$$PCA(X, Y)$$

69. مشکل PCA در Classification

فرض کن:

  • Class A
  • Class B

جهت variance بالا لزوماً directionی نیست که کلاس‌ها را جدا کند.

ممکن است:

  • PC1 → 95% variance

ولی:

  • Class information → PC10

باشد.

پس کاهش ابعاد با PCA ممکن است predictive signal را حذف کند.

70. PCA و LDA

برای همین، روش‌هایی مثل:

Linear Discriminant Analysis

می‌توانند supervised dimensionality reduction انجام دهند.

LDA به جای صرفاً variance:

class separability

را در نظر می‌گیرد.

پس:

$$PCA : \text{maximize variance}$$

ولی:

$$LDA : \text{maximize class separability}$$

71. PCA و Noise Reduction

اگر noise عمدتاً در directions با variance پایین باشد:

PC1 PC2 PC3 ↓ signal PC50 PC51... ↓ noise

حذف componentهای آخر می‌تواند denoising انجام دهد.

اما این تضمین‌شده نیست.

چون:

low variance ≠ noise

72. Curse of Dimensionality و Dimensionality Reduction

در ابعاد بالا:

  • فاصله‌ها کمتر informative می‌شوند
  • nearest neighborها مشکل پیدا می‌کنند
  • data sparsity افزایش می‌یابد
  • حجم داده مورد نیاز افزایش می‌یابد

Dimensionality reduction می‌تواند در بعضی مسائل این مشکل را کاهش دهد.

اما:

dimensionality reduction cure-all نیست.

73. PCA و Distance

PCA transformation هندسی مهمی دارد.

اگر تمام componentها را نگه داری، transformation orthogonal است و Euclidean distances حفظ می‌شوند.

اما وقتی:

$$d \to k$$

و componentها را حذف می‌کنی:

بعضی اطلاعات و فاصله‌ها از بین می‌روند.

74. Reconstruction Error

برای PCA می‌توان:

$$X \to Z \to \hat{X}$$

داشت.

خطای reconstruction:

$$\|X - \hat{X}\|^2$$

هرچه component کمتر:

  • Compression ↑
  • Reconstruction Error ↑

معمولاً.

75. Trade-off اصلی PCA

$$Compression \leftrightarrow Information Loss$$

مثلاً:

$$1000 \text{ dimensions} \to 10 \text{ dimensions}$$

compression عالی است ولی ممکن است اطلاعات زیادی از دست برود.

76. انتخاب تعداد Component با Reconstruction

می‌توانی بررسی کنی:

  • k=10 → error 30%
  • k=20 → error 15%
  • k=50 → error 5%
  • k=100 → error 1%

و تصمیم بگیری.

77. اما Reconstruction Error کافی نیست

⚠️ چون ممکن است:
low reconstruction error

داشته باشی ولی:

poor classification performance

بنابراین در supervised task باید downstream metric را نیز بررسی کنی.

78. Dimensionality Reduction و Trees

این نکته خیلی مهم است.

PCA معمولاً برای:

  • Linear Models
  • KNN
  • SVM
  • Neural Networks

ممکن است مفید باشد.

اما برای:

  • Decision Tree
  • Random Forest
  • XGBoost
  • LightGBM
  • CatBoost

اغلب dimensionality reduction ضرورت ندارد.

چرا؟

چون treeها feature interactions و feature selection را به شکل متفاوتی handle می‌کنند.

79. PCA و Tree Model

مثلاً:

100 features ↓ PCA ↓ 20 PCs ↓ XGBoost

ممکن است performance بدتر شود.

چرا؟

چون PC₁ دیگر یک feature interpretable نیست و splitهای tree روی ترکیبات خطی انجام می‌شوند.

در بعضی datasets مفید است، اما default نیست.

80. PCA برای KNN

KNN بر اساس distance است:

$$d(x_i, x_j)$$

در high-dimensional space مشکل distance concentration داریم.

PCA می‌تواند:

noise dimensions ↓ remove

کند.

در نتیجه KNN گاهی بهتر می‌شود.

اما باید با CV آزمایش شود.

81. PCA برای SVM

SVM مخصوصاً وقتی:

$$d \gg n$$

باشد، می‌تواند از dimensionality reduction سود ببرد.

ولی Kernel SVM خودش می‌تواند بسیار expensive باشد.

پس trade-off مهم است.

82. PCA برای Neural Networks

در deep learning معمولاً neural network خودش representation learning انجام می‌دهد.

پس PCA قبل از network همیشه لازم نیست.

ولی برای:

  • tabular high-dimensional
  • noisy data
  • compression
  • preprocessing

می‌تواند مفید باشد.

83. Autoencoder vs PCA

اگر داده پیچیده و nonlinear باشد:

PCA ↓ linear manifold

ممکن است کافی نباشد.

Autoencoder:

X ↓ nonlinear encoder ↓ latent Z

می‌تواند representation پیچیده‌تری یاد بگیرد.

اما هزینه:

  • training
  • hyperparameter tuning
  • stability
  • interpretability

بیشتر است.

84. t-SNE vs UMAP

اگر سؤال مصاحبه:

t-SNE or UMAP?

t-SNE

وقتی:

مهم است.

UMAP

وقتی:

89. اگر در مصاحبه بپرسند PCA چگونه کار می‌کند؟

یک جواب Senior:

PCA داده را به یک فضای جدید orthogonal projection می‌کند که در آن componentها بر اساس مقدار variance مرتب شده‌اند. ابتدا داده معمولاً center/standardize می‌شود، سپس covariance structure از طریق eigendecomposition یا SVD بررسی می‌شود. بزرگ‌ترین eigenvalueها جهت‌هایی با بیشترین variance را مشخص می‌کنند و با نگه‌داشتن top-k components می‌توان dimensionality را کاهش داد. انتخاب k را نباید صرفاً بر اساس explained variance انجام داد؛ در supervised tasks باید downstream validation performance و احتمال حذف predictive signal را هم بررسی کرد.

90. اگر بپرسند PCA چرا ممکن است بد باشد؟

جواب:

PCA unsupervised است و target را نمی‌بیند؛ بنابراین componentهایی که variance بالایی دارند الزاماً predictive signal بیشتری ندارند. همچنین interpretability کاهش می‌یابد، sparse data ممکن است با PCA معمولی مشکل memory داشته باشد، و اگر preprocessing/PCA قبل از cross-validation fit شود می‌تواند leakage ایجاد کند.

91. اگر بپرسند چرا Truncated SVD برای NLP؟

جواب:

چون TF-IDF/document-term matrices معمولاً بسیار sparse و high-dimensional هستند و PCA استاندارد به دلیل centering می‌تواند sparse matrix را dense کند. Truncated SVD بدون نیاز به centering مستقیم روی sparse matrix کار می‌کند و با نگه‌داشتن top singular components یک latent low-dimensional representation می‌سازد؛ این همان ایده‌ای است که در LSA استفاده می‌شود.

92. اگر بپرسند t-SNE برای production مناسب است؟

جواب:

معمولاً نه به عنوان preprocessing عمومی. t-SNE عمدتاً visualization-oriented است، stochastic و computationally expensive است، global geometry را به‌خوبی حفظ نمی‌کند و handling داده‌های جدید محدودتر است. برای visualization عالی است، ولی برای production feature transformation معمولاً PCA، Truncated SVD، UMAP یا learned embeddings گزینه‌های عملی‌تری هستند.

93. اگر بپرسند UMAP بهتر است یا t-SNE؟

جواب Senior:

بستگی به objective دارد. t-SNE برای visualization local neighborhoods بسیار قوی است، در حالی که UMAP معمولاً scalability و preservation ساختار global را بهتر trade-off می‌کند و transform کردن داده جدید را نیز بهتر پشتیبانی می‌کند. ولی هیچ‌کدام universally superior نیستند و باید stability و downstream objective بررسی شود.

🧠 95. Mental Model برای Senior ML

وقتی dataset high-dimensional دیدی، این سؤال‌ها را به ترتیب از خودت بپرس:

1. آیا واقعاً باید dimension را کم کنم؟

نه اینکه صرفاً چون 500 features دارم، فوراً PCA بزنم.

2. آیا feature selection بهتر نیست؟

اگر interpretability مهم است: Selection ممکن است بهتر باشد.

3. آیا داده sparse است؟

اگر TF-IDF یا Bag of Words یا Huge categorical space است: Truncated SVD / hashing را بررسی کن.

4. آیا structure nonlinear است؟

اگر بله: UMAP / Kernel PCA / Autoencoder را بررسی کن.

5. آیا فقط visualization می‌خواهم؟

پس: t-SNE / UMAP

6. آیا target دارم؟

اگر supervised هستی: فقط explained variance را معیار انتخاب قرار نده. Downstream metric مهم است.

7. آیا leakage ایجاد می‌کنم؟

هر transformationی که از data یاد می‌گیرد:

  • Scaling
  • Imputation
  • PCA
  • SVD
  • Target Encoding
  • Feature Selection
  • UMAP

باید با دقت داخل train/CV fit شود.
