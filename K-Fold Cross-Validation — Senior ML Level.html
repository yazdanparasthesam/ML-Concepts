🧠 K-Fold Cross-Validation — Senior ML Level

حتماً. K-Fold Cross-Validation را اگر بخواهی برای سطح مصاحبه‌ی ML Engineer واقعاً خوب بلد باشی، باید فقط تعریفش را حفظ نکنی؛ باید بدانی چرا استفاده می‌شود، دقیقاً چطور کار می‌کند، چه زمانی نباید استفاده شود، تفاوتش با Stratified/Group/TimeSeries چیست، و Leakage در CV چطور اتفاق می‌افتد.

1. اصلاً چرا Cross-Validation داریم؟

فرض کن 10,000 رکورد داری.

اگر این کار را انجام بدهی:

Train = 80% Validation = 20%

ممکن است اتفاقی Validation Set خیلی آسان یا خیلی سخت انتخاب شود.

مثلاً:

Split 1 → Accuracy = 91% Split 2 → Accuracy = 86% Split 3 → Accuracy = 94%

پس Performance ما به نحوه Split کردن داده حساس است.

Cross-Validation می‌گوید:

بیایید چندین بار Train/Validation Split انجام بدهیم و Performance را روی همه‌ی آن‌ها بررسی کنیم.

هدف اصلی این است که تخمین قابل‌اعتماد‌تری از عملکرد مدل روی داده‌ی ندیده داشته باشیم.

2. K-Fold دقیقاً چیست؟

فرض کن:

K = 5

داده را به 5 قسمت تقسیم می‌کنیم:

Dataset ───────────────────────────── Fold 1 | Fold 2 | Fold 3 | Fold 4 | Fold 5

حالا 5 بار مدل را Train می‌کنیم.

Round 1
Train: Fold 2 + 3 + 4 + 5 Valid: Fold 1
Round 2
Train: Fold 1 + 3 + 4 + 5 Valid: Fold 2
Round 3
Train: Fold 1 + 2 + 4 + 5 Valid: Fold 3
Round 4
Train: Fold 1 + 2 + 3 + 5 Valid: Fold 4
Round 5
Train: Fold 1 + 2 + 3 + 4 Valid: Fold 5

در نتیجه هر sample دقیقاً یک بار در validation قرار می‌گیرد و در 4 بار دیگر در training استفاده می‌شود. این همان K-Fold استاندارد است.

3. بعد چه کار می‌کنیم؟

فرض کن F1 هر Fold این باشد:

Fold 1 → 0.91 Fold 2 → 0.94 Fold 3 → 0.89 Fold 4 → 0.93 Fold 5 → 0.92

میانگین:

$$CV_{score} = \frac{0.91 + 0.94 + 0.89 + 0.93 + 0.92}{5}$$

یعنی:

$$CV_{score} = 0.918$$

پس می‌گوییم:

Mean CV F1 = 0.918

ولی فقط Mean مهم نیست.

Standard Deviation هم مهم است:

Mean F1 = 0.918 Std = 0.018

یعنی Performance بین Foldها نسبتاً پایدار بوده.

اگر داشته باشیم:

Fold 1 → 0.99 Fold 2 → 0.72 Fold 3 → 0.95 Fold 4 → 0.68 Fold 5 → 0.91

Mean شاید هنوز قابل‌قبول به نظر برسد، ولی Variance بین Foldها زیاد است و باید علتش را بررسی کنیم.

4. K را چند بگذاریم؟

مقادیر رایج:

K = 5 K = 10

مثلاً:

KFold(n_splits=5)
K کوچک

مثلاً:

K = 2

هر مدل فقط روی 50٪ داده Train می‌شود.

پس:

  • Training data کمتر
  • تخمین ممکن است Bias بیشتری داشته باشد
  • محاسبات کمتر
K بزرگ

مثلاً:

K = 20

هر مدل روی تقریباً 95٪ داده Train می‌شود.

ولی:

  • مدل را 20 بار Train می‌کنی
  • Computational Cost بالا می‌رود
  • ممکن است برآوردها به هم وابسته‌تر شوند.
K = N

این حالت می‌شود:

Leave-One-Out Cross-Validation (LOOCV)

یعنی:

N samples ↓ N models

هر بار یک sample validation است.

5. مهم‌ترین نکته: K-Fold به معنی Test Set نیست

این اشتباه خیلی رایج است.

فرض کن:

100,000 samples

بهتر است:

80% Train 20% Test

و فقط روی 80٪:

5-Fold CV

انجام دهیم.

یعنی:

Dataset │ ┌────────┴────────┐ │ │ Train 80% Test 20% │ │ 5-Fold CV FINAL │ EVALUATION │ Model Selection Hyperparameter Tuning

Test Set را تا پایان دست‌نخورده نگه می‌داریم.

این همان چیزی است که باعث می‌شود Test Set برای final evaluation اعتبار داشته باشد.

6. K-Fold چه مشکلی را حل می‌کند؟

فرض کن فقط یک Validation Split داشته باشیم:

Train ████████████████████ Validation █████

ممکن است نتیجه به این Split خاص وابسته باشد.

K-Fold:

Fold 1 → Score Fold 2 → Score Fold 3 → Score Fold 4 → Score Fold 5 → Score ↓ Mean + Std

پس تخمین Performance معمولاً کمتر وابسته به یک Split خاص می‌شود.

7. ولی K-Fold همیشه درست نیست!

این قسمت برای مصاحبه خیلی مهم است.

اگر Classification داری:

معمولاً به جای KFold ساده، بهتر است از:

Stratified K-Fold

استفاده کنی.

فرض کن:

Normal = 950 Fraud = 50

یعنی:

95% / 5%

StratifiedKFold تلاش می‌کند این نسبت کلاس‌ها را در Foldها تقریباً حفظ کند.

مثلاً:

Fold 1 → 95% / 5% Fold 2 → 95% / 5% Fold 3 → 95% / 5% Fold 4 → 95% / 5% Fold 5 → 95% / 5%

این مخصوصاً برای Imbalanced Classification مهم است.

8. KFold vs StratifiedKFold

KFold

فقط داده را تقسیم می‌کند.

from sklearn.model_selection import KFold kf = KFold( n_splits=5, shuffle=True, random_state=42 )
StratifiedKFold

Class Distribution را هم در نظر می‌گیرد.

from sklearn.model_selection import StratifiedKFold skf = StratifiedKFold( n_splits=5, shuffle=True, random_state=42 )

برای Classification معمولاً:

Classification ↓ StratifiedKFold

انتخاب طبیعی‌تری است، مخصوصاً وقتی کلاس‌ها نامتوازن‌اند.

9. یک نکته ظریف درباره Stratification

Stratification الزاماً یک «بهبود آماری عمومی» نیست.

هدف اصلی آن این است که مشکلات عملی Split در Classification، مخصوصاً با کلاس‌های نادر، کاهش پیدا کند.

حتی scikit-learn اشاره می‌کند که Stratification می‌تواند variability بین Foldها را ظاهراً کمتر نشان دهد.

پس:

Stratification ≠ تضمین بهتر بودن مدل

بلکه:

Stratification = Split مناسب‌تر برای حفظ نسبت کلاس‌ها.

10. Regression چه؟

برای Regression معمولاً:

KFold

مناسب است.

چون Target پیوسته است:

12.3 15.7 18.2 ...

و مفهوم Class Ratio مثل Classification نداریم.

البته در مسائل خاص ممکن است نیاز به روش‌های خاص‌تر برای تقسیم‌بندی Target داشته باشی.

11. Group K-Fold

این یکی خیلی مهم است.

فرض کن Dataset پزشکی داری:

Patient A → 100 samples Patient B → 100 samples Patient C → 100 samples

اگر Random K-Fold انجام بدهی، ممکن است:

Patient A ├── Train └── Validation

یعنی اطلاعات یک بیمار هم در Train و هم Validation وجود دارد.

این می‌تواند باعث Data Leakage شود.

راه‌حل:

GroupKFold

یعنی:

Patient A → فقط Train Patient B → فقط Train Patient C → فقط Validation

هیچ Group مشترکی بین Train و Validation وجود ندارد.

مثال‌های Group:

Patient ID User ID Customer ID Device ID Company ID Transaction Account Subject ID

12. یک مثال خیلی مهم برای Fraud Detection

فرض کن:

User A ├── Transaction 1 ├── Transaction 2 ├── Transaction 3 └── Transaction 4

اگر:

Transaction 1 → Train Transaction 2 → Validation

باشد، ممکن است مدل User-specific patternها را یاد بگیرد.

اگر هدف تو این است که:

روی Userهای کاملاً جدید Generalize کنیم

باید:

Group = User ID

و از:

GroupKFold

استفاده کنی.

13. StratifiedGroupKFold

حالا اگر همزمان:

Class Imbalance + Groups

داشته باشی:

User A → Fraud/Normal User B → Fraud/Normal User C → Fraud/Normal

می‌توانی از:

StratifiedGroupKFold

استفاده کنی.

هدف:

Class distribution + Group separation

را همزمان تا حد امکان رعایت کند.

14. Time Series: اینجا KFold معمولی خطرناک است

فرض کن:

2022 → 2023 → 2024 → 2025 → 2026

اگر Random KFold انجام دهی:

2025 → Train 2024 → Validation

مدل ممکن است از آینده برای پیش‌بینی گذشته استفاده کند.

این یک نوع Temporal Leakage است.

برای Time Series معمولاً:

TimeSeriesSplit

مناسب‌تر است.

مثلاً:

Fold 1: Train: 2022 Valid: 2023 Fold 2: Train: 2022 + 2023 Valid: 2024 Fold 3: Train: 2022 + 2023 + 2024 Valid: 2025

یعنی Train همیشه در گذشته و Validation در آینده است. scikit-learn هم توضیح می‌دهد که KFold کلاسیک برای داده‌های time-dependent می‌تواند برآورد غیرواقعی ایجاد کند و TimeSeriesSplit برای این حالت طراحی شده است.

15. TimeSeriesSplit با Gap

در بعضی مسائل حتی این هم کافی نیست:

Train | Validation

ممکن است داده‌های خیلی نزدیک به مرز زمانی به هم وابسته باشند.

می‌توانیم داشته باشیم:

Train | GAP | Validation

مثلاً:

Train ████████████ Gap ██ Validation ████

در scikit-learn TimeSeriesSplit پارامتر gap دارد که تعدادی sample را بین انتهای Train و Validation حذف می‌کند.

این در مسائل مالی و Forecasting می‌تواند بسیار مهم باشد.

16. K-Fold و Preprocessing؛ اینجا یک دام بسیار مهم داریم 🚨

فرض کن:

scaler.fit_transform(X)

را روی کل Dataset انجام بدهی و بعد K-Fold اجرا کنی.

اشتباه است.

چون Validation Fold در محاسبه:

Mean Std Min Max

دخالت کرده است.

یعنی Validation اطلاعاتش وارد Training Pipeline شده.

17. روش درست

باید در هر Fold:

Fold │ ├── Train │ ↓ │ Fit Scaler │ └── Validation ↓ Transform

نه:

Whole Dataset ↓ Fit Scaler ↓ KFold

در scikit-learn معمولاً این کار را با Pipeline انجام می‌دهیم.

مثلاً:

from sklearn.pipeline import Pipeline from sklearn.preprocessing import StandardScaler from sklearn.linear_model import LogisticRegression pipeline = Pipeline([ ("scaler", StandardScaler()), ("model", LogisticRegression()) ])

بعد Pipeline را داخل Cross-Validation می‌دهیم.

این باعث می‌شود preprocessing داخل هر training fold fit شود.

18. Feature Selection هم همین مشکل را دارد

این اشتباه است:

Whole Dataset ↓ Feature Selection ↓ KFold

چون Validation اطلاعاتی در Feature Selection وارد کرده.

درست:

Fold │ ├── Train │ ↓ │ Feature Selection │ ↓ │ Model │ └── Validation

یعنی هر چیزی که از Data یاد می‌گیرد باید فقط روی Training Fold fit شود.

این قانون طلایی CV است:

Anything that learns from data must be fitted inside the CV training fold.

19. Hyperparameter Tuning با K-Fold

مثلاً XGBoost داری:

learning_rate max_depth n_estimators

می‌توانی:

max_depth = 3 → 5-Fold CV → Mean F1 = 0.91 max_depth = 5 → 5-Fold CV → Mean F1 = 0.94 max_depth = 8 → 5-Fold CV → Mean F1 = 0.92

پس:

max_depth = 5

انتخاب می‌شود.

20. اما یک مشکل مهم‌تر: Test Leakage

فرض کن 100 بار Hyperparameterها را با Test Set امتحان کنی:

Test ↓ Try model ↓ Try another model ↓ Change threshold ↓ Try another parameter

در نهایت Test Set دیگر واقعاً unseen نیست.

برای همین:

Train ↓ CV ↓ Hyperparameter Selection ↓ Final Model ↓ Test

ساختار سالم‌تری است.

21. Nested Cross-Validation

اگر بخواهی خیلی حرفه‌ای‌تر عمل کنی، می‌رسی به:

Nested CV

دو حلقه داریم.

OUTER CV ┌─────────────────┐ │ │ │ INNER CV │ │ │ │ Hyperparameter │ │ Tuning │ │ │ └─────────────────┘
Outer Loop

برای ارزیابی مدل.

Inner Loop

برای انتخاب Hyperparameters.

مثلاً:

Outer Fold 1 │ └── Inner CV ├── LR=0.01 ├── LR=0.001 └── LR=0.0001 Outer Fold 2 │ └── Inner CV ├── LR=0.01 ├── LR=0.001 └── LR=0.0001

این روش مخصوصاً برای unbiased model evaluation همراه با hyperparameter selection مفید است.

22. Repeated K-Fold

یک بار 5-Fold:

Fold 1 Fold 2 Fold 3 Fold 4 Fold 5

ممکن است هنوز به Random Split خاصی وابسته باشیم.

می‌توانیم چند بار تکرارش کنیم:

Repeat 1 5-Fold Repeat 2 5-Fold Repeat 3 5-Fold

مثلاً:

from sklearn.model_selection import RepeatedKFold cv = RepeatedKFold( n_splits=5, n_repeats=3, random_state=42 )

پس:

5 folds × 3 repeats = 15 evaluations

RepeatedKFold دقیقاً همین ایده را پیاده می‌کند و برای هر تکرار Splitهای متفاوتی ایجاد می‌کند.

23. K-Fold و Bias–Variance

این قسمت به بحث قبلی‌مان وصل می‌شود.

K-Fold کمک می‌کند تخمین Performance ما نسبت به یک Split خاص کمتر حساس باشد.

اما خود K هم یک Tradeoff دارد:

K ↑ │ ├── Training data per fold ↑ ├── Computational cost ↑ └── Fold estimates become more correlated

در مقابل:

K ↓ │ ├── Training data per fold ↓ └── Computational cost ↓

پس انتخاب K هم یک تصمیم عملی/آماری است.

24. آیا CV جلوی Overfitting را می‌گیرد؟

نه، مستقیماً نه.

Cross-validation بیشتر برای:

Model Evaluation Model Selection Hyperparameter Tuning

است.

مثلاً ممکن است یک مدل روی CV خیلی خوب باشد ولی به دلیل انتخاب مکرر مدل‌ها و Hyperparameterها روی CV، خودت به CV هم Overfit کنی.

به همین دلیل Test Set مستقل یا Nested CV مهم می‌شود.

25. K-Fold در Deep Learning

در Deep Learning هم می‌توانی K-Fold انجام بدهی:

Fold 1 → Train Neural Network Fold 2 → Train Neural Network Fold 3 → Train Neural Network Fold 4 → Train Neural Network Fold 5 → Train Neural Network

اما هزینه بسیار بالاست.

اگر:

1 training = 2 hours

و:

5-fold

تقریباً حداقل:

10 hours

زمان می‌برد.

برای همین در Deep Learning معمولاً:

Train / Validation / Test

استفاده می‌شود، مگر اینکه Dataset کوچک باشد یا ارزیابی دقیق‌تر ارزش هزینه را داشته باشد.

26. K-Fold در پروژه Phishing Detection خودت

برای مسئله Classification تو، اگر Dataset مستقل و IID باشد، چیزی شبیه:

Original Dataset │ ├───────────────┐ │ │ Train 80% Test 20% │ │ │ │ Stratified K-Fold │ │ │ ┌────┼────┐ │ │ │ │ │ Fold1 Fold2 ... │ │ │ ↓ │ Model Selection │ │ │ └───────┐ │ ↓ ↓ Final Model → Test

و اگر مثلاً:

5-Fold

باشد:

Fold 1 → F1 = 0.961 Fold 2 → F1 = 0.967 Fold 3 → F1 = 0.959 Fold 4 → F1 = 0.964 Fold 5 → F1 = 0.968

گزارش حرفه‌ای‌تر:

CV F1 = 0.964 ± 0.004

نه فقط:

F1 = 0.964

27. یک نکته بسیار مهم درباره مدل نهایی

بعد از اینکه با CV بهترین Hyperparameter را پیدا کردی، معمولاً مدل نهایی را روی کل Training Set با همان Hyperparameters آموزش می‌دهی:

CV ↓ Best Hyperparameters ↓ Train final model on ALL training data ↓ Evaluate ONCE on Test

یعنی لازم نیست مدل نهایی فقط روی Fold خاصی که بهترین Score را گرفته آموزش داده شود.

29. در یک نگاه: کدام را انتخاب کنم؟

Dataset │ ┌─────────┴─────────┐ │ │ Time Series? No │ │ YES ↓ │ Classification? TimeSeriesSplit │ │ YES │ NO ↓ ↓ StratifiedKFold KFold │ │ Group dependency? │ YES ↓ StratifiedGroupKFold

اگر Time Series باشد، Random KFold نزن.

اگر User/Patient/Device/Account چند رکورد دارد و می‌خواهی روی Groupهای جدید Generalize کنی، GroupKFold را در نظر بگیر.

اگر Classification نامتوازن داری، StratifiedKFold.

اگر هر دو را داری:

StratifiedGroupKFold.

30. سؤال‌های مصاحبه‌ای خیلی مهم

اگر برای Senior ML Engineer آماده می‌شوی، این‌ها را باید بتوانی جواب بدهی:

Q1: Why do we use K-Fold Cross-Validation?
To obtain a more robust estimate of model generalization performance and reduce dependence on a single train-validation split.
Q2: Why StratifiedKFold?
To preserve approximately the same class distribution across folds, especially useful for classification and imbalanced datasets.
Q3: Why not KFold for time series?
Because random splitting can put future observations in the training set while evaluating on past observations, causing temporal leakage.
Q4: Why GroupKFold?
When samples within the same group are correlated, to ensure the same group doesn't appear in both training and validation folds.
Q5: Where should StandardScaler be fitted?
Inside each training fold, never on the entire dataset before cross-validation.
Q6: Does Cross-Validation eliminate overfitting?
No. It provides a better evaluation/model-selection procedure, but the model or hyperparameter search can still overfit the CV process.
Q7: What is Nested CV?
An outer loop estimates generalization performance while an inner loop performs model/hyperparameter selection.

⭐ مهم‌ترین چیزی که باید از K-Fold در ذهنت بماند

سه قانون طلایی:

  1. معمولی:
    KFold
  2. Classification:
    StratifiedKFold
  3. Group/Time-dependent data:
    GroupKFold / StratifiedGroupKFold
    TimeSeriesSplit

و مهم‌تر از همه:

Cross-validation فقط Split کردن داده نیست؛ کل Training Pipeline باید داخل هر Fold اجرا شود.

یعنی:

Fold │ ├── Preprocessing ├── Feature Engineering ├── Feature Selection ├── Resampling ├── Model Training └── Validation

اگر مثلاً قبل از K-Fold روی کل Dataset StandardScaler، Feature Selection، PCA یا SMOTE اجرا کنی، ممکن است Data Leakage ایجاد کنی و CV Score تو بیش از حد خوش‌بینانه شود.
