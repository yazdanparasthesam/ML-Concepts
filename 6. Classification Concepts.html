2. Decision Boundary

حالا سؤال مهم:

مدل چگونه تصمیم می‌گیرد یک نمونه متعلق به Class 0 یا Class 1 است؟

فرض کن دو Feature داریم:

x1 = income x2 = age

مدل یک تابع یاد می‌گیرد:

$$f(x)$$

که Score تولید می‌کند.

مثلاً:

$$P(Y=1|X=x)$$

اگر:

$$P(Y=1|X) \ge 0.5$$

بگوییم:

Class 1

و اگر:

$$P(Y=1|X) < 0.5$$

بگوییم:

Class 0

مرزی که این دو ناحیه را جدا می‌کند:

Decision Boundary

است.

Decision Boundary در Logistic Regression

در Logistic Regression:

$$z = w^T x + b$$

و:

$$p = \sigma(z)$$

که:

$$\sigma(z) = \frac{1}{1 + e^{-z}}$$

است.

اگر Threshold = 0.5 باشد:

$$p = 0.5$$

زمانی رخ می‌دهد که:

$$z = 0$$

پس:

$$w^T x + b = 0$$

این همان Decision Boundary است.

نکته Senior

Decision Boundary الزاماً همیشه خطی نیست.

Logistic Regression

معمولاً:

Linear Boundary

می‌تواند:

Non-linear

باشد.

4. Classification Threshold

مدل احتمال می‌دهد:

0.91 0.72 0.63 0.48 0.12

ولی سیستم باید تصمیم binary بگیرد.

Threshold این تبدیل را انجام می‌دهد:

$$\hat{y} = \begin{cases} 1 & p \ge t \\ 0 & p < t \end{cases}$$

مثلاً:

$$t = 0.5$$
Threshold = 0.5 یک قانون طبیعی نیست!

این یکی از نکات بسیار مهم Senior است.

بسیاری فکر می‌کنند:

Binary Classification یعنی Threshold = 0.5.

نه.

Threshold=0.5 فقط یک convention رایج است.

Threshold باید بر اساس:

  • Cost
  • Precision
  • Recall
  • Business constraints
  • Capacity
  • Risk
  • Calibration

انتخاب شود.

فرض کن مدل این Probabilityها را می‌دهد:

اگر:

Threshold = 0.5

پنج نمونه Positive می‌شوند.

ولی اگر:

Threshold = 0.8

فقط سه نمونه Positive می‌شوند.

بنابراین Threshold مستقیماً روی:

TP FP TN FN

اثر دارد.

Threshold پایین

اگر Threshold را پایین بیاوری:

More samples → Positive

معمولاً:

Recall ↑ FP ↑ Precision ممکن است ↓
Threshold بالا

اگر Threshold را بالا ببری:

Fewer samples → Positive

معمولاً:

Precision ↑ Recall ↓ FP ↓ FN ↑

البته رفتار دقیق به توزیع Scoreها وابسته است و نباید آن را یک قانون ریاضی مطلق برای هر دیتاست دانست.

7. Cost-Sensitive Classification

حالا وارد بخش خیلی مهم Senior می‌شویم.

فرض کن:

False Positive cost = $5 False Negative cost = $500

یعنی:

از دست دادن Fraud صد برابر گران‌تر از False Alarm است.

پس نمی‌توانیم بگوییم:

FP = FN

چون Business چنین چیزی نمی‌گوید.

Cost Matrix

مثلاً:

Actual / PredictionNegativePositive
Negative05
Positive5000

پس:

$$Cost(FP) = 5$$

و:

$$Cost(FN) = 500$$
Expected Cost

می‌توانیم هزینه را به شکل:

$$TotalCost = C_{FP} FP + C_{FN} FN$$

محاسبه کنیم.

و Threshold را طوری انتخاب کنیم که:

$$Threshold^* = \arg\min_{t} TotalCost(t)$$

شود.

این یک روش بسیار Business-oriented است.

8. Threshold به Cost وابسته است

اگر:

$$C_{FN} \gg C_{FP}$$

باشد، معمولاً می‌خواهیم:

Recall بالا

داشته باشیم.

در نتیجه Threshold پایین‌تر می‌تواند منطقی باشد.

اگر:

$$C_{FP} \gg C_{FN}$$

باشد:

Precision بالا

مهم‌تر می‌شود و Threshold بالاتر می‌تواند مناسب‌تر باشد.

9. یک نکته بسیار مهم درباره Threshold و Probability

اگر Probabilityها واقعاً calibrated باشند، در حالت ساده‌ی Binary Classification و با فرض هزینه‌های مشخص، threshold به Costها مرتبط می‌شود.

اگر:

  • \(C_{FP}\) = هزینه FP
  • \(C_{FN}\) = هزینه FN

و هزینه درست بودن صفر باشد، threshold تصمیم Bayes به شکل:

$$t^* = \frac{C_{FP}}{C_{FP} + C_{FN}}$$

درمی‌آید.

مثلاً:

$$C_{FP} = 5$$

و:

$$C_{FN} = 500$$

پس:

$$t^* = \frac{5}{505} \approx 0.0099$$

یعنی اگر Probability واقعاً calibrated باشد، حتی احتمال حدود 1٪ هم ممکن است برای اقدام Positive توجیه اقتصادی داشته باشد.

اما این فرمول ساده همیشه مستقیماً قابل استفاده نیست؛ چون در دنیای واقعی:

  • هزینه‌ها ممکن است context-dependent باشند.
  • ظرفیت بررسی انسانی محدود باشد.
  • هزینه TP/TN صفر نباشد.
  • Probabilityها calibrated نباشند.
  • چند نوع action داشته باشیم.
  • Base rate و sampling scheme متفاوت باشد.

برای همین در Production معمولاً threshold را با Validation Data و Cost/Constraint واقعی انتخاب می‌کنیم.

11. Class Weight

به جای تغییر داده‌ها، به خطاهای یک Class وزن بیشتری می‌دهیم.

مثلاً:

class_weight = { 0: 1, 1: 10 }

یعنی اشتباه روی Class 1 ده برابر مهم‌تر است.

در Loss چه اتفاقی می‌افتد؟

فرض کن Binary Cross Entropy داریم:

$$L = -[y \log p + (1-y) \log(1-p)]$$

با Class Weight:

$$L = -w_y [y \log p + (1-y) \log(1-p)]$$

در نتیجه خطاهای Class اقلیت بیشتر روی Gradient اثر می‌گذارند.

مثال
Class 0 → weight = 1 Class 1 → weight = 20

مدل بیشتر تلاش می‌کند:

Class 1 را درست یاد بگیرد.
مزیت Class Weight

نیازی نیست:

Dataset را Duplicate کنیم

پس:

  • داده جدید مصنوعی تولید نمی‌کنیم.
  • حجم Dataset تغییر نمی‌کند.
  • معمولاً ساده و پایدار است.
محدودیت Class Weight

Class Weight:

مشکل Overlap واقعی بین کلاس‌ها را حل نمی‌کند.

اگر دو Class واقعاً از نظر Featureها بسیار مشابه باشند، وزن بیشتر معجزه نمی‌کند.

همچنین weighting می‌تواند Probability calibration را تغییر دهد؛ پس اگر Probability واقعی نیاز داری، بعد از weighting باید Calibration را بررسی کنی.

14. SMOTE

SMOTE:

Synthetic Minority Over-sampling Technique

است.

به جای Duplicate کردن دقیق نمونه‌ها، نمونه Synthetic تولید می‌کند.

ایده SMOTE

فرض کن یک Minority sample داریم:

$$x_i$$

و یکی از Neighborهایش:

$$x_j$$

SMOTE نمونه جدید را تقریباً به شکل:

$$x_{new} = x_i + \lambda(x_j - x_i)$$

می‌سازد.

که:

$$\lambda \in [0, 1]$$

است.

مثال ساده

فرض کن:

x_i = (2, 4) x_j = (4, 8)

اگر:

$$\lambda = 0.5$$

آنگاه:

$$x_{new} = (2,4) + 0.5[(4,8) - (2,4)]$$

می‌شود:

$$(3,6)$$

یعنی یک نمونه جدید در فضای Feature ساخته می‌شود.

چرا SMOTE بهتر از Duplicate است؟

چون:

Duplicate: A A A A

ولی SMOTE:

A A' A'' A'''

نمونه‌های جدیدی در اطراف Minority ایجاد می‌کند.

15. مشکل مهم SMOTE

SMOTE فرض می‌کند:

Interpolation بین Minority samples منطقی است.

اما همیشه درست نیست.

اگر:

Minority + Majority

شدیداً overlap داشته باشند، SMOTE ممکن است:

Synthetic samples را در ناحیه Majority ایجاد کند.

در نتیجه Classification سخت‌تر می‌شود.

16. SMOTE روی چه داده‌ای مناسب است؟

SMOTE اساساً برای:

Feature space عددی

طراحی شده است.

برای Categorical Features ساده نمی‌توانی کورکورانه interpolation انجام دهی.

مثلاً:

Gender = Male Gender = Female

میانگین گرفتن معنی ندارد.

برای داده‌های mixed-type، روش‌هایی مانند:

SMOTENC

وجود دارند.

22. Precision-Recall Tradeoff

رابطه:

$$Precision = \frac{TP}{TP + FP}$$

و:

$$Recall = \frac{TP}{TP + FN}$$

وقتی Threshold را پایین می‌آوری:

More Positive predictions

معمولاً:

Recall ↑ FP ↑ Precision ↓

وقتی Threshold را بالا می‌بری:

Fewer Positive predictions

معمولاً:

Precision ↑ Recall ↓

25. Calibration

حالا می‌رسیم به یکی از مهم‌ترین مفاهیم Senior.

فرض کن مدل می‌گوید:

P = 0.8

این باید چه معنی داشته باشد؟

اگر مدل calibrated باشد:

بین تمام نمونه‌هایی که مدل برایشان P≈0.8 داده، تقریباً 80٪ باید واقعاً Positive باشند.

این یعنی:

$$P(Y=1|P(X)\approx0.8) \approx 0.8$$

گفته.

28. Probability Calibration

اگر مدل calibrated نیست، می‌توانیم یک مدل Calibration روی خروجی آن یاد بگیریم.

ساختار:

Features ↓ Base Model ↓ Raw Score / Probability ↓ Calibration Model ↓ Calibrated Probability
نکته مهم

Calibration باید روی داده‌ای انجام شود که برای Fitting مدل اصلی استفاده نشده است، یا با روش‌های cross-validation مناسب انجام شود.

اگر:

Train Base Model ↓ Calibrate on same Train predictions

کنی، calibration ممکن است optimistic/overfit شود.

29. Platt Scaling

Platt Scaling یک روش معروف Calibration است.

معمولاً Logistic Regression را روی Score مدل اصلی Fit می‌کنیم:

$$P(y=1|s) = \sigma(As + B)$$

که:

  • s = raw model score
  • A,B = پارامترهای calibration

است.

ایده Platt

مدل اصلی می‌گوید:

Score = 2.7

Platt Scaling یاد می‌گیرد:

Score 2.7 ↓ Probability ≈ 0.82
Platt Scaling چه زمانی خوب است؟

وقتی رابطه:

Score → Probability

تقریباً smooth و sigmoid-like باشد.

مزیت

تعداد پارامترهای بسیار کمی دارد:

A B

پس نسبتاً:

Low variance

است.

محدودیت

اگر calibration relationship پیچیده باشد:

Logistic sigmoid ممکن است کافی نباشد.

30. Isotonic Regression

Isotonic Regression

است.

به جای فرض sigmoid، یک تابع:

Monotonic non-decreasing

یاد می‌گیرد.

یعنی اگر:

$$s_1 < s_2$$

45. آیا تغییر Threshold Decision Boundary را تغییر می‌دهد؟

در بسیاری از مدل‌ها بله، مرز نهایی Classification در Feature Space جابه‌جا می‌شود، حتی اگر پارامترهای مدل تغییر نکرده باشند.

مثلاً Logistic Regression:

$$P(Y=1|X) = \sigma(w^T x + b)$$

برای Threshold t:

$$\sigma(w^T x + b) = t$$

و بنابراین:

$$w^T x + b = \log \frac{t}{1-t}$$

پس تغییر Threshold، موقعیت مرز تصمیم را تغییر می‌دهد.

اما:

w,b مدل ثابت می‌مانند.

52. نکته Senior: Production Drift

فرض کن امروز:

Fraud prevalence = 1%

ولی شش ماه بعد:

Fraud prevalence = 5%

$$P(X|Y)$$

  • Prevalence monitoring
  • Threshold monitoring

را در Production در نظر بگیری.
