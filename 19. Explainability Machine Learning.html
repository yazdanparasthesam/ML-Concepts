🧠 19. Explainability در Machine Learning

حتماً. Explainability / Interpretability از مباحثی است که برای سطح Senior ML باید فراتر از «SHAP چیست؟» بلد باشی. باید بدانی هر روش چه چیزی را توضیح می‌دهد، چه فرضی دارد، چه چیزی را تضمین نمی‌کند، چه زمانی ممکن است گمراه‌کننده باشد، و Global و Local را چگونه از هم جدا کنیم.

1. Explainability چیست؟

فرض کن مدل Fraud Detection داریم:

Customer ↓ ML Model ↓ Fraud = 1 Probability = 0.93

حالا دو سؤال کاملاً متفاوت داریم:

سؤال اول

چرا این مشتری خاص Fraud تشخیص داده شد؟

این می‌شود:

Local Explainability
سؤال دوم

مدل ما معمولاً بر اساس چه ویژگی‌هایی Fraud را تشخیص می‌دهد؟

این می‌شود:

Global Explainability

2. Explainability vs Interpretability

این دو اصطلاح گاهی به جای هم استفاده می‌شوند، ولی می‌توان یک تفاوت مفهومی در نظر گرفت.

Interpretability

مدل ذاتاً قابل فهم است.

مثلاً:

Linear Regression Decision Tree Rule-based Model
Explainability

ممکن است مدل black-box باشد، ولی روش‌هایی برای توضیح prediction آن داشته باشیم.

مثلاً:

XGBoost Neural Network Transformer

و سپس:

SHAP LIME Permutation Importance

استفاده کنیم.

3. چرا Explainability مهم است؟

در ML واقعی فقط accuracy مهم نیست.

مثلاً در:

Banking Fraud Detection Credit Scoring Healthcare Insurance Security HR

باید بدانیم:

چرا مدل این تصمیم را گرفته؟
مثال Fraud

مدل می‌گوید:

Fraud probability = 0.97

ولی business می‌پرسد:

چرا؟

ممکن است جواب:

New device +0.31 High amount +0.25 Unusual country +0.18 Velocity +0.15

باشد.

این information برای analyst بسیار ارزشمند است.

4. دو محور اصلی Explainability

تقریباً همه روش‌هایی که گفتی را می‌توان در این دو دسته دید:

Explainability │ ├── Global │ └── Local

5. Global Explainability

Global یعنی:

رفتار کلی مدل روی dataset چیست؟

مثلاً:

چه featureهایی معمولاً بیشترین تأثیر را روی prediction دارند؟

مثلاً:

transaction_amount ██████████ transaction_velocity ████████ device_age ██████ country_risk █████ account_age ███

این جواب سؤال:

What features generally drive Fraud predictions?

است.

6. Local Explainability

Local یعنی:

چرا مدل برای یک نمونه خاص این prediction را داده است؟

مثلاً:

Transaction #12345 Fraud probability = 0.94 Top reasons: + Amount unusually high + New device + High transaction velocity + Unusual location

این جواب سؤال:

Why is this customer classified as Fraud?

است.

7. Feature Importance

ساده‌ترین روش explainability.

ایده:

به هر feature یک importance score بدهیم.

مثلاً Random Forest:

Feature Importance -------------------------------- Age 0.25 Income 0.21 TransactionAmount 0.18 DeviceAge 0.12 Country 0.08

8. Feature Importance در Tree Models

در tree-based models معمولاً importance بر اساس کاهش impurity محاسبه می‌شود.

مثلاً:

Root | |-- TransactionAmount | +-- DeviceAge

اگر split مربوط به TransactionAmount impurity را زیاد کاهش دهد، importance آن بالا می‌رود.

9. Mean Decrease in Impurity

برای درخت:

$$Importance(j) = \sum_{t} \Delta I_t$$

که:

j = feature t = split ΔIt = کاهش impurity

است.

برای Random Forest معمولاً importance درخت‌ها aggregate می‌شود.

10. مشکل Feature Importance

Feature importance به این معنی نیست که:

feature علت prediction است.

مثلاً:

Feature A importance = 0.8

به این معنی نیست:

اگر A را تغییر دهیم، prediction حتماً تغییر می‌کند.

و حتی:

A علت واقعی Fraud است.

ممکن است صرفاً correlation یا proxy باشد.

11. Correlated Features

یکی از مشکلات مهم:

income annual_income monthly_income

اگر این‌ها highly correlated باشند، importance ممکن است بین آنها پخش شود.

مثلاً:

income 0.30 annual_income 0.15 monthly_income 0.10

در حالی که اگر یکی حذف شود، importance دیگری افزایش پیدا می‌کند.

پس feature importance در حضور correlation باید با احتیاط تفسیر شود.

12. Permutation Importance

یکی از روش‌های مهم‌تر.

ایده:

یک feature را shuffle کن و ببین performance چقدر خراب می‌شود.

13. مثال

مدل:

AUC = 0.92

حالا transaction_amount را shuffle می‌کنیم:

AUC = 0.74

پس:

$$Importance \approx 0.92 - 0.74 = 0.18$$

14. الگوریتم Permutation Importance

برای feature j:

مرحله 1

Performance اصلی:

$$S_{original}$$
مرحله 2

Feature j را shuffle کن:

$$X_j^{perm}$$
مرحله 3

Performance جدید:

$$S_{perm}$$
مرحله 4

Importance:

$$I_j = S_{original} - S_{perm}$$

15. چرا Permutation Importance جالب است؟

چون:

model-agnostic

است.

یعنی لازم نیست model حتماً tree باشد.

می‌توانی برای:

XGBoost Random Forest Neural Network SVM Logistic Regression

استفاده کنی.

16. مشکل Permutation Importance

Correlation.

فرض کن:

X1 ≈ X2

و model از هر دو استفاده می‌کند.

اگر X1 را shuffle کنیم:

Performance: 0.92 → 0.91

پس می‌گوییم:

X1 importance = low

اما ممکن است X2 همان information را نگه داشته باشد.

پس:

low permutation importance لزوماً به معنی useless بودن feature نیست.

17. نکته مهم Senior-Level

Permutation importance باید روی:

validation/test data

و نه training data به شکل ساده و بدون توجه به overfitting محاسبه شود.

اگر model روی train بیش از حد fit شده باشد، importance روی train می‌تواند misleading باشد.

18. Partial Dependence Plot — PDP

PDP برای فهم رابطه:

$$Feature \rightarrow Prediction$$

است.

مثلاً:

وقتی transaction amount افزایش پیدا می‌کند، مدل به طور متوسط چقدر احتمال Fraud را تغییر می‌دهد؟

19. مثال PDP

فرض کن:

Transaction Amount ↓ Fraud Probability

PDP ممکن است نشان دهد:

Amount Fraud Probability 0-100 0.02 100-500 0.05 500-1000 0.15 1000-5000 0.40 >5000 0.75

پس رابطه را می‌بینیم.

20. PDP چگونه کار می‌کند؟

فرض کن feature موردنظر:

$$X_j$$

است.

برای مقدار z:

$$PD(z) = E_{X_{-j}} [f(z, X_{-j})]$$

یعنی:

feature موردنظر را روی مقدار خاصی ثابت می‌کنیم و روی سایر featureها average می‌گیریم.

21. مثال

Dataset:

Age | Income | Amount | Fraud

می‌خواهیم effect Amount را ببینیم.

برای:

Amount = 1000

برای همه افراد:

Amount = 1000

قرار می‌دهیم.

بعد prediction می‌گیریم.

میانگین predictionها:

Average Fraud Probability = 0.18

بعد:

Amount = 2000

و دوباره prediction.

22. مشکل مهم PDP

PDP فرض می‌کند featureهای موردنظر و سایر featureها را می‌توانیم به شکل مناسب ترکیب کنیم.

اما اگر:

Age = 10 Income = $1M

ترکیب غیرواقعی باشد، PDP ممکن است روی نقاطی حساب کند که در data وجود ندارند یا بسیار نامحتمل‌اند.

23. Correlated Features و PDP

مثلاً:

Age YearsOfExperience

correlated هستند.

اگر PDP فقط Age را تغییر دهد ولی YearsOfExperience را ثابت نگه دارد، ممکن است ترکیب‌های غیرواقعی ایجاد کند.

پس:

PDP در حضور featureهای highly correlated می‌تواند misleading شود.

24. ICE Plot

ICE:

Individual Conditional Expectation

است.

PDP:

average behavior

را نشان می‌دهد.

ICE:

behavior برای هر individual

را نشان می‌دهد.

25. تفاوت PDP و ICE

فرض کن 1000 customer داریم.

PDP
1000 customers ↓ Average ↓ One curve
ICE
Customer 1 → curve Customer 2 → curve Customer 3 → curve ... Customer 1000 → curve

26. چرا ICE مهم است؟

ممکن است PDP نشان دهد:

Amount ↑ Fraud ↑

ولی واقعیت:

Customer A → strong positive effect Customer B → almost no effect Customer C → negative effect

باشد.

PDP این heterogeneity را ممکن است پنهان کند.

ICE آن را نشان می‌دهد.

28. SHAP

حالا مهم‌ترین روش explainability مدرن:

SHAP

مخفف:

SHapley Additive exPlanations

است.

ریشه آن در:

Shapley Values

از Game Theory است.

29. ایده SHAP

فرض کن prediction نهایی:

Fraud probability = 0.90

SHAP می‌خواهد بگوید:

هر feature چقدر prediction را نسبت به baseline تغییر داده است؟

مثلاً:

Baseline = 0.20 Amount +0.25 NewDevice +0.18 Velocity +0.15 Country +0.08 Age -0.01 -------------------------------- Prediction ≈ 0.90

30. SHAP Formula

فرمول Shapley value:

$$\phi_i = \sum_{S \subseteq N \setminus \{i\}} \frac{|S|!(n - |S| - 1)!}{n!} [f(S \cup \{i\}) - f(S)]$$

لازم نیست در مصاحبه همیشه فرمول را بنویسی، ولی باید مفهوم آن را بفهمی.

31. معنی فرمول SHAP

برای feature i:

contribution آن feature را در تمام coalitionهای ممکن بررسی می‌کنیم.

یعنی:

Feature i ↓ Add it to different feature subsets ↓ Measure prediction change ↓ Weighted average ↓ SHAP value

32. SHAP Additivity

یکی از ویژگی‌های مهم:

$$f(x) = \phi_0 + \sum_i \phi_i$$

که:

φ0 = baseline φi = contribution feature i

است.

33. مثال

فرض کن:

Base prediction = 0.30

و:

Amount +0.25 DeviceAge +0.20 Velocity +0.15 Country +0.10 Income -0.05

پس:

$$0.30 + 0.25 + 0.20 + 0.15 + 0.10 - 0.05 = 0.95$$

Prediction:

0.95

34. SHAP برای Local Explainability

مثلاً customer شماره 123:

Prediction = Fraud

SHAP:

Feature Contribution High amount +0.31 New device +0.22 High velocity +0.18 Foreign country +0.12 Old account -0.04

این دقیقاً جواب:

Why is this customer classified as Fraud?

است.

35. SHAP برای Global Explainability

اگر SHAP absolute values را روی dataset aggregate کنیم:

$$Mean(|\phi_i|)$$

می‌توانیم importance کلی feature را به دست آوریم.

مثلاً:

Feature Mean |SHAP| Amount 0.31 Velocity 0.25 DeviceAge 0.18 Country 0.12 AccountAge 0.07

این می‌تواند برای سؤال:

What features generally drive Fraud predictions?

استفاده شود.

36. SHAP Summary Plot

یکی از معروف‌ترین visualizationها:

Feature A ••••••••••• Feature B ••••••• Feature C •••• Feature D •••

محور x:

SHAP value

باشد.

سمت راست:

prediction را افزایش می‌دهد.

سمت چپ:

prediction را کاهش می‌دهد.

37. SHAP یک مزیت مهم نسبت به Feature Importance دارد

Feature importance می‌گوید:

این feature مهم است.

SHAP می‌تواند بگوید:

این feature برای این نمونه prediction را به این سمت برد.

یعنی:

Global: Feature X is important. Local: Feature X increased THIS prediction by +0.27.

38. SHAP Dependence Plot

می‌توانیم ببینیم:

Feature value ↓ SHAP value

مثلاً:

Transaction Amount ↑ ↓ SHAP ↑

یعنی مقدار بیشتر Amount معمولاً contribution مثبت به Fraud دارد.

39. SHAP Interaction

SHAP را می‌توان برای interaction هم استفاده کرد.

مثلاً:

Amount + New Device ↓ Much higher Fraud risk

ممکن است:

Amount alone → moderate effect New Device alone → moderate effect Both together → very high effect

این interaction بسیار مهم است.

40. SHAP و Feature Correlation

اینجا یک نکته Senior-level بسیار مهم داریم.

اگر:

X1 X2

highly correlated باشند، attribution بین آنها می‌تواند ambiguous شود.

مثلاً:

AnnualIncome MonthlyIncome

ممکن است SHAP contribution بین این دو تقسیم شود.

پس:

SHAP همیشه causal explanation نیست.

41. SHAP ≠ Causality

اگر SHAP بگوید:

Age → +0.20

به این معنی نیست:

اگر سن customer را تغییر دهیم، Fraud probability حتماً 0.20 افزایش می‌یابد.

SHAP:

model behavior

را توضیح می‌دهد.

نه:

causal mechanism

را.

این یکی از مهم‌ترین نکات مصاحبه است.

42. LIME

روش معروف دیگر:

LIME

مخفف:

Local Interpretable Model-agnostic Explanations

است.

ایده:

اطراف یک sample خاص، model پیچیده را با یک model ساده approximate کنیم.

43. ایده LIME

فرض کن:

Black-box Model

داریم.

برای customer خاص x:

x ↓ Generate nearby samples ↓ Black-box predictions ↓ Fit simple interpretable model ↓ Explanation

44. مثال LIME

مدل اصلی:

XGBoost

نمونه:

Customer #123

LIME اطراف این customer sampleهای مشابه ایجاد می‌کند:

Customer A Customer B Customer C ...

بعد prediction مدل اصلی را می‌گیرد.

سپس یک model ساده مثلاً:

Linear Model

را روی neighborhood fit می‌کند.

45. چرا LIME Local است؟

چون مدل ساده فقط برای:

neighborhood اطراف یک sample

fit می‌شود.

بنابراین:

LIME explanation for Customer A

ممکن است با:

LIME explanation for Customer B

کاملاً متفاوت باشد.

46. LIME Model-Agnostic است

می‌تواند روی:

XGBoost Random Forest Neural Network SVM

کار کند، چون فقط:

input → prediction

را نیاز دارد.

47. مشکل LIME

LIME به نحوه sampling حساس است.

مثلاً:

Neighborhood definition Sampling strategy Distance metric Kernel width

می‌توانند explanation را تغییر دهند.

پس ممکن است:

Run 1 → Feature A important Run 2 → Feature B important

شود.

49. Counterfactual Explanation

یکی از جذاب‌ترین روش‌ها:

به جای اینکه بگوییم چرا prediction این شد، بگوییم چه چیزی باید تغییر کند تا prediction عوض شود.

50. مثال Credit

مدل:

Loan = Rejected

Counterfactual می‌گوید:

اگر: Income: $40K → $50K و Debt: $20K → $12K آنگاه: Loan = Approved

51. Counterfactual سؤال متفاوتی می‌پرسد

SHAP:

Why did this happen?

Counterfactual:

What would need to change for the outcome to change?

52. مثال Fraud

Prediction:

Fraud

Counterfactual:

If transaction amount < $500 and device age > 30 days → Non-Fraud

53. Counterfactual و Actionability

این موضوع بسیار مهم است.

همه featureها قابل تغییر نیستند.

مثلاً:

Age

قابل تغییر نیست.

ولی:

Debt Income Transaction Amount

ممکن است قابل تغییر باشند.

پس counterfactual باید:

actionable

باشد.

54. Counterfactual Constraints

یک counterfactual خوب باید constraints داشته باشد.

مثلاً:

Age → immutable Gender → immutable Transaction history → immutable Income → mutable Debt → mutable

55. Counterfactual Optimization

می‌توانیم مسئله را به شکل:

$$\min_{x'} d(x, x')$$

حل کنیم، به شرط اینکه:

$$f(x') = desired outcome$$

باشد.

یعنی:

کمترین تغییر ممکن را پیدا کن که outcome را عوض کند.

56. مشکل Counterfactual

ممکن است counterfactual از نظر mathematical درست باشد ولی در دنیای واقعی impossible باشد.

مثلاً:

Age = 35 → 25

یا:

Income = $40K → $1M overnight

پس:

feasibility و actionability بسیار مهم‌اند.

60. یک نکته بسیار مهم: Explanation ≠ Truth

این را همیشه در ذهن داشته باش.

اگر مدل بگوید:

Feature X → important

به این معنی نیست:

X causes Y

بلکه:

X is used by the model to produce Y

است.

61. Explainability vs Causality

سه سؤال متفاوت داریم:

Correlation

X مرتبط با Y است؟

Prediction

آیا X برای پیش‌بینی Y مفید است؟

Causality

اگر X را تغییر دهیم، آیا Y تغییر می‌کند؟

SHAP و LIME عمدتاً سؤال دوم را جواب می‌دهند.

نه الزاماً سوم را.

62. Feature Importance vs Permutation Importance

Feature Importance

اغلب:

importance داخلی مدل

است.

مثلاً tree impurity.

Permutation Importance

افت performance وقتی feature را خراب می‌کنیم.

پس permutation به performance model مرتبط‌تر است.

63. Feature Importance vs SHAP

Feature Importance
Feature X = important
SHAP

پس SHAP جهت و magnitude contribution را نیز نشان می‌دهد.

SHAP

65. ICE vs PDP

PDP

Average behavior

ICE

Individual behavior

heterogeneous feature effects

داریم.

66. Explainability در Production

Senior ML فقط notebook نمی‌سازد.

مثلاً برای Fraud:

Transaction ↓ Model ↓ Fraud Probability ↓ SHAP / Explanation ↓ Decision Engine ↓ ┌──────────────┬───────────────┐ │ Low Risk │ High Risk │ │ Allow │ Review/Block │ └──────────────┴───────────────┘

67. Explanation Logging

در production بهتر است برای decisionهای حساس log کنیم:

model_version prediction probability threshold top_features explanation_version timestamp

مثلاً:

model_version = fraud-v42 prediction = fraud probability = 0.94 top_reasons: - transaction_amount - device_age - velocity

این برای:

Audit Debugging Compliance Customer support

مهم است.

68. Explainability Drift

یک نکته پیشرفته:

ممکن است performance مدل ثابت بماند ولی explanation تغییر کند.

مثلاً:

Q1 Amount → dominant Q4 Device → dominant

پس:

model behavior drift

ممکن است قبل از performance degradation قابل مشاهده باشد.

این برای monitoring جالب است.

69. Stability of Explanations

اگر یک sample بسیار کوچک تغییر کند:

x

و explanation کاملاً تغییر کند:

SHAP: A → +0.3 x + ε SHAP: B → +0.4

باید بررسی کنیم که آیا explanation پایدار است یا نه.

Explainability خودش باید:

validated

شود.

70. Correlated Features — دام بسیار مهم

فرض کن:

X1 = Annual Income X2 = Monthly Income

هر دو تقریباً یک information دارند.

مدل ممکن است از یکی استفاده کند.

روش‌های explainability ممکن است contribution را:

X1 = 70% X2 = 30%

یا:

X1 = 30% X2 = 70%

نشان دهند.

این الزاماً به معنی تفاوت واقعی importance نیست.

71. Data Leakage و Explainability

اگر feature leakage داشته باشیم:

Post-transaction investigation_result

ممکن است مدل آن را بسیار مهم نشان دهد.

SHAP هم احتمالاً می‌گوید:

investigation_result → HUGE contribution

ولی explanation خوب نیست؛ چون:

feature از آینده آمده است.

پس explainability جایگزین:

data validation leakage detection causal reasoning

نیست.

72. Explainability و Fairness

مثلاً model loan approval:

Prediction ↓ SHAP ↓ Feature contributions

ممکن است بفهمیم model از یک feature proxy استفاده می‌کند.

مثلاً:

ZIP Code

ممکن است proxy برای ویژگی‌های حساس باشد.

پس explainability می‌تواند در:

fairness audit

کمک کند.

73. اما یک هشدار

اگر SHAP نشان دهد:

ZIP_CODE → +0.25

نباید فوراً نتیجه بگیریم:

discrimination ثابت شده.

باید:

causal analysis fairness metrics subgroup analysis policy context

را نیز بررسی کنیم.

74. مدل‌های ذاتاً Interpretable

گاهی بهترین explainability این است که اصلاً black-box نسازیم.

مثلاً:

Linear Regression
$$y = \beta_0 + \beta_1 x_1 + \beta_2 x_2$$
Logistic Regression
$$logit(p) = \beta_0 + \beta_1 x_1 + \beta_2 x_2$$
Decision Tree
if income > X and debt < Y approve

این‌ها inherently interpretableتر هستند.

75. Explainability Trade-off

گاهی:

Interpretability ↑

ممکن است:

Model complexity ↓

شود.

اما این قانون مطلق نیست.

مثلاً:

یک Gradient Boosting model + SHAP

می‌تواند هم performance بالا داشته باشد و هم explanation ارائه کند.

76. Model-Agnostic vs Model-Specific

Model-Agnostic

به model داخلی نیاز ندارد.

مثلاً:

LIME Permutation Importance
Model-Specific

از structure مدل استفاده می‌کند.

مثلاً:

TreeSHAP Tree feature importance

77. TreeSHAP

برای tree-based models روش بسیار سریع‌تر و دقیق‌تری نسبت به محاسبه brute-force SHAP دارد.

برای:

XGBoost LightGBM CatBoost Random Forest Decision Trees

بسیار کاربردی است.

78. Kernel SHAP

نسخه model-agnostic SHAP است.

می‌تواند برای black-box model استفاده شود ولی معمولاً computationally expensiveتر است.

79. Deep SHAP

برای deep learning از approximationهایی استفاده می‌کند که برای neural networks مناسب‌تر هستند.

80. Explainability Stack حرفه‌ای

Why was this customer classified as Fraud?

SHAP / LIME / Counterfactual

What features generally drive Fraud predictions?

جواب:

Global Explainability

Permutation Importance / SHAP aggregation / Feature Importance / PDP

What happens to fraud probability as transaction amount increases?
→ PDP

سؤال:

Does this relationship hold for every customer?
→ ICE

سؤال:

What minimal change would make this customer non-fraud?
→ Counterfactual

سؤال:

Which features are important globally?
→ Feature Importance / Permutation Importance / Mean |SHAP|

Does feature X cause fraud?

و مهم‌ترین اصل Senior-level:

Explainability tells you how the model behaves; it does not automatically tell you why the real world behaves that way.

یعنی اگر SHAP بگوید transaction_amount مهم‌ترین feature است، نتیجه درست این نیست که «مبلغ تراکنش علت Fraud است»؛ نتیجه درست این است که «مدل برای predictionهای خود به مبلغ تراکنش اتکا می‌کند». این تفاوت بین model explanation و causal explanation یکی از مهم‌ترین نکات این بخش است.
