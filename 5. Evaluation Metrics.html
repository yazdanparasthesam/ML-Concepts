📈 5. Evaluation Metrics — Senior ML Level

قبل از ورود به Metricها یک اصل بسیار مهم:

هیچ Metricای ذاتاً بهترین نیست. Metric باید متناسب با نوع مسئله، Distribution داده، هزینه خطاها و Business Objective انتخاب شود.

مثلاً مدلی با:

Accuracy = 99.5%

ممکن است فوق‌العاده باشد.

یا ممکن است کاملاً بی‌ارزش باشد.

همه‌چیز به مسئله بستگی دارد.

1. Confusion Matrix — پایه‌ی تمام Classification Metrics

قبل از Metrics باید این چهار مورد را کاملاً بلد باشی.

فرض کن:

Positive = Fraud Negative = Normal

Confusion Matrix:

Predicted Positive Predicted Negative
Actual Positive TP FN
Actual Negative FP TN
TP — True Positive

واقعاً Positive بوده و مدل هم Positive گفته.

Actual = Fraud Prediction = Fraud
TN — True Negative

واقعاً Negative بوده و مدل هم Negative گفته.

Actual = Normal Prediction = Normal
FP — False Positive

واقعاً Negative بوده ولی مدل Positive گفته.

Actual = Normal Prediction = Fraud

به آن:

Type I Error

هم می‌گوییم.

FN — False Negative

واقعاً Positive بوده ولی مدل Negative گفته.

Actual = Fraud Prediction = Normal

به آن:

Type II Error

هم می‌گوییم.

2. Accuracy

فرمول:

$$Accuracy = \frac{TP + TN}{TP + TN + FP + FN}$$

یعنی:

چه درصدی از کل Predictionها درست بوده‌اند؟
مثال
TP = 80 TN = 900 FP = 50 FN = 20

پس:

$$Accuracy = \frac{80 + 900}{1050} \approx 93.3\%$$
مشکل مهم Accuracy

فرض کن:

Fraud = 1% Normal = 99%

مدل:

Always predict Normal

می‌گوید.

آنگاه:

$$Accuracy = 99\%$$

ولی:

$$Recall_{Fraud} = 0$$

پس مدل برای Fraud Detection عملاً بی‌فایده است.

چه زمانی Accuracy مناسب است؟

وقتی:

  • Classes نسبتاً balanced هستند.
  • هزینه FP و FN تقریباً مشابه است.
  • همه خطاها اهمیت مشابه دارند.

مثلاً یک Classification ساده با Class Distribution متعادل.

3. Precision

فرمول:

$$Precision = \frac{TP}{TP + FP}$$

سؤال Precision:

از بین چیزهایی که مدل Positive اعلام کرده، چند درصد واقعاً Positive بوده‌اند؟
مثال

مدل 100 تراکنش را Fraud اعلام کرده:

80 واقعی Fraud 20 واقعی Normal

پس:

$$Precision = \frac{80}{100} = 80\%$$
Precision بالا یعنی چه؟

یعنی:

وقتی مدل Positive می‌گوید، معمولاً درست می‌گوید.

پس Precision با False Positive مرتبط است.

چه زمانی Precision مهم است؟

وقتی FP هزینه زیادی دارد.

مثلاً:

سیستم Block کردن تراکنش

اگر مدل اشتباهی تراکنش سالم را Block کند:

Customer frustration Lost revenue Support cost

بالا می‌رود.

پس Precision اهمیت زیادی دارد.

4. Recall

فرمول:

$$Recall = \frac{TP}{TP + FN}$$

که به آن:

  • Sensitivity
  • True Positive Rate
  • TPR

هم می‌گوییم.

سؤال Recall:

از بین تمام Positiveهای واقعی، مدل چند درصد را پیدا کرده؟
مثال

100 Fraud واقعی داریم:

90 را پیدا کرده 10 را از دست داده

پس:

$$Recall = 90\%$$
Recall بالا یعنی چه؟

یعنی:

مدل Positiveهای واقعی را کمتر از دست می‌دهد.

پس Recall با:

FN

مرتبط است.

چه زمانی Recall مهم است؟

وقتی FN خیلی پرهزینه است.

مثلاً:

تشخیص بیماری

اگر بیمار واقعی را سالم اعلام کنیم:

False Negative

ممکن است عواقب جدی داشته باشد.

پس:

Recall مهم‌تر از Precision می‌شود.

5. Specificity

فرمول:

$$Specificity = \frac{TN}{TN + FP}$$

که:

True Negative Rate

هم نامیده می‌شود.

سؤال Specificity

از بین تمام Negativeهای واقعی، مدل چند درصد را درست Negative تشخیص داده؟
رابطه با FPR
$$FPR = \frac{FP}{FP + TN}$$

بنابراین:

$$Specificity = 1 - FPR$$
مثال پزشکی

اگر 1000 فرد سالم داریم و مدل:

950 → correctly healthy 50 → incorrectly sick

آنگاه:

$$Specificity = 95\%$$
Precision vs Specificity

خیلی مهم:

Precision

بین Predictionهای Positive:

$$TP / (TP + FP)$$
Specificity

بین Actual Negativeها:

$$TN / (TN + FP)$$

پس این دو با هم یکی نیستند.

6. F1 Score

F1 میانگین هارمونیک Precision و Recall است:

$$F1 = 2 \cdot \frac{Precision \times Recall}{Precision + Recall}$$
چرا میانگین هارمونیک؟

چون اگر یکی از Precision و Recall خیلی پایین باشد، F1 هم پایین می‌آید.

مثلاً:

Precision = 0.99 Recall = 0.10

F1:

$$F1 \approx 0.18$$

پس نمی‌توانی با Precision خیلی بالا ضعف Recall را پنهان کنی.

چرا Arithmetic Mean نه؟

Arithmetic Mean:

$$(0.99 + 0.10) / 2 = 0.545$$

که ممکن است گمراه‌کننده باشد.

Harmonic Mean رفتار سخت‌گیرانه‌تری دارد.

7. F1 چه چیزی را اندازه می‌گیرد؟

ترکیبی از:

Precision + Recall

اما یک نکته مهم:

F1 هیچ توجه مستقیمی به TN ندارد.

این برای مسائل Imbalanced مهم است.

ممکن است F1 خوب باشد ولی Specificity ضعیف باشد.

8. Fβ Score

F1 در واقع یک حالت خاص از Fβ است.

فرمول:

$$F_{\beta} = (1 + \beta^2) \cdot \frac{Precision \cdot Recall}{\beta^2 Precision + Recall}$$
β چه کار می‌کند؟
β > 1

Recall اهمیت بیشتری پیدا می‌کند.

مثلاً:

F₂

یعنی Recall اهمیت بیشتری دارد.

β < 1

Precision اهمیت بیشتری پیدا می‌کند.

مثلاً:

F₀.₅

یعنی Precision مهم‌تر است.

مثال

در Fraud Detection:

اگر:

Miss کردن Fraud خیلی خطرناک است.

می‌توانی:

F₂

را بررسی کنی.

اگر:

False Positive بسیار گران است.

می‌توانی:

F₀.₅

را بررسی کنی.

9. Macro F1

فرض کن 3 کلاس داریم:

A B C

برای هر کلاس یک F1 داریم:

$$F1_A, F1_B, F1_C$$

Macro F1:

$$MacroF1 = \frac{F1_A + F1_B + F1_C}{3}$$

یعنی همه کلاس‌ها وزن برابر دارند.

چرا Macro F1 مهم است؟

اگر:

Class A = 90% Class B = 9% Class C = 1%

باشد، Macro F1 اجازه نمی‌دهد Class A به‌تنهایی Metric را dominate کند.

10. Micro F1

در Micro averaging ابتدا تمام:

TP FP FN

را بین کلاس‌ها جمع می‌کنیم.

بعد:

$$Precision_{micro} = \frac{\sum TP}{\sum TP + \sum FP}$$

و:

$$Recall_{micro} = \frac{\sum TP}{\sum TP + \sum FN}$$

سپس F1.

چه زمانی Micro F1 مهم است؟

وقتی می‌خواهی:

عملکرد کلی در سطح تمام نمونه‌ها

را اندازه بگیری.

در Multi-Class Single-Label classification، یک نکته مهم:

Micro F1 معمولاً با Accuracy برابر می‌شود.

11. Weighted F1

F1 هر کلاس را محاسبه می‌کنیم، اما به اندازه Support هر کلاس وزن می‌دهیم.

$$WeightedF1 = \sum_{c} w_c F1_c$$

که:

$$w_c = \frac{Support_c}{N}$$

است.

تفاوت سه F1
Metricکلاس‌ها
Macro F1همه برابر
Micro F1نمونه‌ها به‌طور جمعی
Weighted F1متناسب با تعداد نمونه‌های هر کلاس
یک مثال مهم

فرض کن:

Class A → 900 samples → F1=0.95 Class B → 90 samples → F1=0.60 Class C → 10 samples → F1=0.10
Macro F1
$$(0.95 + 0.60 + 0.10) / 3 = 0.55$$

این نشان می‌دهد مدل روی کلاس‌های اقلیت ضعیف است.

Weighted F1

به A وزن بیشتری می‌دهد، پس احتمالاً عدد خیلی بالاتر خواهد بود.

12. ROC Curve

ROC بین:

TPR

و:

FPR

را در Thresholdهای مختلف رسم می‌کند.

یعنی:

$$TPR = \frac{TP}{TP + FN}$$

و:

$$FPR = \frac{FP}{FP + TN}$$
ROC چه چیزی را نشان می‌دهد؟

رفتار مدل را در Thresholdهای مختلف.

مثلاً:

Threshold = 0.9 Threshold = 0.8 Threshold = 0.7 ... Threshold = 0.1

در هر Threshold:

TPR FPR

محاسبه می‌شود.

13. ROC-AUC

AUC:

Area Under the ROC Curve

است.

به‌صورت شهودی:

احتمال اینکه مدل یک Positive را بالاتر از یک Negative رتبه‌بندی کند.

این یک interpretation بسیار مفید برای AUC است.

مقادیر

تقریباً:

AUC = 1 → Ranking عالی
AUC = 0.5 → مثل Random
AUC < 0.5 → مدل بدتر از Random؛ گاهی با برعکس‌کردن Score می‌توان از آن استفاده کرد، ولی باید علت بررسی شود.

14. ROC-AUC Threshold Independent است؟

تا حد زیادی:

AUC از یک Threshold خاص مستقل است.

اما این به معنی مستقل بودن از همه تصمیمات نیست.

ROC-AUC عملکرد Ranking را روی Thresholdهای مختلف خلاصه می‌کند.

15. مشکل ROC-AUC در Imbalanced Data

فرض کن:

Positive = 0.1% Negative = 99.9%

ممکن است:

$$ROC - AUC = 0.99$$

داشته باشی.

ولی در ناحیه Precision برایت مهم است، مدل عملکرد چندان خوبی نداشته باشد.

چرا؟

چون FPR ممکن است ظاهراً کوچک باشد، ولی وقتی تعداد Negativeها بسیار زیاد است، همین FPR کوچک می‌تواند تعداد زیادی FP تولید کند.

16. PR Curve

Precision-Recall Curve بین:

Precision

و:

Recall

در Thresholdهای مختلف رسم می‌شود.

برای Rare Positive Classes بسیار مهم است.

17. PR-AUC

Area Under Precision-Recall Curve.

به‌خصوص برای:

Rare events Fraud detection Medical diagnosis Anomaly detection

بسیار مفید است.

18. ROC-AUC vs PR-AUC

ROC-AUC

مناسب برای نگاه کلی به:

TPR vs FPR
PR-AUC

تمرکز بیشتر روی:

Positive class Precision vs Recall
یک نکته Senior خیلی مهم

در Classification شدیداً Imbalanced:

PR-AUC معمولاً تصویری informativeتر از عملکرد کلاس مثبت می‌دهد.

اما:

این به معنی بی‌ارزش بودن ROC-AUC نیست.

بهتر است متناسب با Business Objective هر دو را در صورت لزوم بررسی کنی.

19. Baseline در PR-AUC

یک نکته ظریف:

در Binary Classification، baseline مربوط به PR Curve به prevalence کلاس مثبت وابسته است.

مثلاً:

Positive prevalence = 1%

یک classifier تصادفی در مقیاس Precision/Recall حدوداً حول همان prevalence رفتار می‌کند.

بنابراین:

$$PR - AUC = 0.10$$

در یک مسئله با prevalence برابر 1٪ ممکن است بسیار بهتر از baseline باشد، حتی اگر عدد ظاهراً کوچک به نظر برسد.

20. Log Loss

در Binary Classification:

$$LogLoss = - \frac{1}{N} \sum_{i} [y_i \log p_i + (1 - y_i) \log(1 - p_i)]$$

در واقع همان Mean Binary Cross Entropy است.

Log Loss چه چیزی را اندازه می‌گیرد؟

نه فقط درست/غلط بودن.

بلکه:

Quality of predicted probabilities
مثال

فرض کن Target=1.

Model A
P=0.51
Model B
P=0.99

هر دو اگر Threshold=0.5 باشد درست‌اند.

اما Log Loss به Model B پاداش بیشتری می‌دهد.

ولی اگر B اشتباه کند:

True y=1 P=0.01

Loss بسیار بزرگ می‌شود.

پس Log Loss به:

Confident Wrong Predictions

شدیداً حساس است.

21. Log Loss و Calibration

این دو به هم مرتبط‌اند.

مدلی که Probabilityهای خوبی تولید می‌کند:

P=0.8

باید واقعاً تقریباً:

80%

موفقیت داشته باشد.

Log Loss یک معیار مناسب برای کیفیت Probabilityهای پیش‌بینی‌شده است، ولی:

Log Loss به تنهایی یک تضمین کامل برای Calibration نیست.

22. Matthews Correlation Coefficient — MCC

MCC یکی از Metrics بسیار خوب برای Binary Classification، مخصوصاً در Imbalanced Data است.

فرمول:

$$MCC = \frac{TP \cdot TN - FP \cdot FN}{\sqrt{(TP + FP)(TP + FN)(TN + FP)(TN + FN)}}$$
دامنه MCC
$$-1 \le MCC \le 1$$
+1 → Prediction کامل.
0 → تقریباً no better than random / no association.
-1 → کاملاً معکوس.
چرا MCC جالب است؟

برخلاف F1:

هم Positive و هم Negative را در نظر می‌گیرد.

پس برای Imbalanced Classification می‌تواند بسیار informative باشد.

23. MCC و Accuracy

ممکن است:

Accuracy = 99%

داشته باشی، ولی:

MCC ≈ 0

اگر مدل تقریباً همیشه یک کلاس را پیش‌بینی کند.

به همین دلیل MCC برای بعضی مسائل شدیداً Imbalanced بسیار مفید است.

24. Cohen's Kappa

Cohen's Kappa می‌خواهد:

Agreement مدل و Ground Truth را بعد از درنظرگرفتن Agreement ناشی از شانس اندازه بگیرد.

فرمول:

$$\kappa = \frac{p_o - p_e}{1 - p_e}$$

که:

  • \(p_o\) = observed agreement
  • \(p_e\) = expected agreement by chance
مثال

اگر:

Observed Agreement = 90%

ولی به علت توزیع کلاس‌ها:

Chance Agreement = 80%

آنگاه:

$$\kappa = \frac{0.9 - 0.8}{1 - 0.8} = 0.5$$

پس 90٪ Accuracy الزاماً به معنی Agreement فوق‌العاده نیست.

دامنه Kappa

معمولاً:

1 → Perfect agreement 0 → Chance-level agreement <0 → Worse than chance
نکته مهم Kappa

Kappa تحت Class Imbalance می‌تواند رفتار غیر-intuitive داشته باشد.

بنابراین در کاربردهای Imbalanced نباید آن را بدون بررسی Distribution تفسیر کرد.

25. Balanced Accuracy

برای Binary:

$$BalancedAccuracy = \frac{Sensitivity + Specificity}{2}$$

یعنی:

$$BalancedAccuracy = \frac{TPR + TNR}{2}$$
چرا Balanced Accuracy؟

در Dataset نامتوازن:

99% Negative 1% Positive

Accuracy می‌تواند گمراه‌کننده باشد.

Balanced Accuracy به هر کلاس وزن برابر می‌دهد.

مثال

فرض کن:

Recall Positive = 80% Specificity = 90%

پس:

$$BalancedAccuracy = \frac{0.8 + 0.9}{2} = 85\%$$
Balanced Accuracy vs Macro Recall

در Binary/Multi-Class، Balanced Accuracy بسیار نزدیک/مرتبط با میانگین Recall کلاس‌هاست؛ در Multi-Class معمولاً:

$$BalancedAccuracy = \frac{1}{C} \sum_{c=1}^{C} Recall_c$$

پس در Multi-Class به Macro Recall مربوط می‌شود.

26. Top-K Accuracy

در Multi-Class Classification.

فرض کن مدل:

Cat = 0.40 Dog = 0.30 Horse = 0.20 Bird = 0.10

Target:

Horse

Top-1:

Cat

→ اشتباه.

Top-3:

Cat Dog Horse

→ درست.

Top-K Accuracy

اگر Label واقعی در بین K Prediction اول باشد:
Correct

مثلاً:

Top-5Accuracy

در ImageNet بسیار رایج بود/است.

چه زمانی Top-K مفید است؟

وقتی:

چند Prediction برتر برای سیستم قابل قبول‌اند.

مثلاً:

  • Image classification
  • Recommendation
  • Search suggestion
  • Large-scale classification
یک نکته مهم

Top-K Accuracy برای همه Businessها مناسب نیست.

اگر باید:

فقط یک تصمیم نهایی بگیری

Top-1 یا Metricهای threshold-based مهم‌ترند.

بخش Regression Metrics

حالا برویم سراغ Regression.

27. MAE

$$MAE = \frac{1}{N} \sum |y_i - \hat{y}_i|$$

سؤال:

Prediction به‌طور متوسط چند واحد با مقدار واقعی فاصله دارد؟
مثال

اگر:

MAE = 10

و Target بر حسب تومان باشد، یعنی:

به‌طور متوسط 10 واحد خطا داریم.

این Metric قابل‌تفسیر است.

28. MSE

$$MSE = \frac{1}{N} \sum (y_i - \hat{y}_i)^2$$

واحدش مربع می‌شود.

اگر Target:

USD

باشد:

$$USD^2$$

پس از نظر Interpretability ضعیف‌تر از MAE است.

ولی:

Outlierها را بیشتر جریمه می‌کند.

29. RMSE

$$RMSE = \sqrt{\frac{1}{N} \sum (y_i - \hat{y}_i)^2}$$

مزیت مهم:

واحد RMSE با Target یکی است.

مثلاً:

RMSE = $20
MAE vs RMSE
MAE → Robust‌تر
RMSE → Outlier-sensitive

اگر خطای بزرگ بسیار مهم باشد:

RMSE مناسب‌تر است.

30. رابطه MAE و RMSE

برای خطاهای finite:

$$RMSE \ge MAE$$

و اگر همه Absolute Errors برابر باشند، برابر می‌شوند.

31. R²

فرمول:

$$R^2 = 1 - \frac{SS_{res}}{SS_{tot}}$$

که:

$$SS_{res} = \sum (y_i - \hat{y}_i)^2$$

و:

$$SS_{tot} = \sum (y_i - \bar{y})^2$$

است.

R² چه می‌گوید؟

به‌صورت شهودی:

مدل نسبت به یک baseline که همیشه Mean را پیش‌بینی می‌کند، چقدر Variation را توضیح می‌دهد؟
مثال
$$R^2 = 0.8$$

یعنی در یک تفسیر استاندارد، مدل نسبت به predicting the mean، حدود 80٪ از Sum of Squared Error/variation criterion را بهبود داده است.

اما جمله:

«مدل دقیقاً 80٪ از واقعیت را توضیح می‌دهد»

ممکن است oversimplification باشد.

32. آیا R² همیشه بین 0 و 1 است؟

نه.

این یک نکته مهم مصاحبه است.

می‌تواند:

$$R^2 < 0$$

شود.

اگر مدل از baseline mean prediction بدتر باشد.

33. R² با Correlation² یکی است؟

در Linear Regression with an intercept در بعضی شرایط:

$$R^2 = r^2$$

ولی به‌صورت عمومی نباید این دو را یکی فرض کنی.

34. Adjusted R²

مشکل R²:

با اضافه کردن Feature جدید، R² روی Training Data معمولاً کاهش پیدا نمی‌کند؛ حتی اگر Feature مفید نباشد.

Adjusted R² یک penalty برای تعداد Predictors دارد.

فرمول:

$$Adjusted R^2 = 1 - (1 - R^2) \frac{n - 1}{n - p - 1}$$

که:

  • n = number of observations
  • p = number of predictors
چه زمانی Adjusted R² مفید است؟

وقتی می‌خواهی مدل‌های Regression با تعداد Featureهای متفاوت را مقایسه کنی.

اما:

این Metric جایگزین Validation/CV نیست.

35. MAPE

$$MAPE = \frac{100}{N} \sum \left| \frac{y_i - \hat{y}_i}{y_i} \right|$$
مزیت MAPE

Relative error می‌دهد.

مثلاً:

MAPE = 10%

یعنی خطای نسبی متوسط تقریباً 10٪.

مشکل بسیار مهم MAPE

اگر:

$$y = 0$$

باشد، تقسیم بر صفر داریم.

و اگر y خیلی نزدیک صفر باشد:

MAPE می‌تواند بسیار بزرگ و ناپایدار شود.

مشکل دیگر MAPE

MAPE نسبت به Positive/Negative بودن Target و جهت خطا رفتار خاصی دارد و در داده‌هایی که Target می‌تواند صفر یا نزدیک صفر باشد انتخاب خوبی نیست.

36. sMAPE

برای کاهش بعضی مشکلات MAPE، از:

Symmetric Mean Absolute Percentage Error

استفاده می‌شود.

یک فرم رایج:

$$sMAPE = \frac{100}{N} \sum \frac{|y - \hat{y}|}{(|y| + |\hat{y}|) / 2}$$

معادل:

$$sMAPE = \frac{200}{N} \sum \frac{|y - \hat{y}|}{|y| + |\hat{y}|}$$

بسته به Convention.

چرا sMAPE؟

Denominator از هر دو مقدار واقعی و Prediction استفاده می‌کند.

ولی:

اسم «symmetric» به این معنی نیست که تمام مشکلات asymmetry را کاملاً حل کرده است.

هنوز در نزدیکی صفر باید با احتیاط تفسیر شود و Definitions مختلف sMAPE در منابع وجود دارند.

37. MSLE

$$MSLE = \frac{1}{N} \sum (\log(1 + y) - \log(1 + \hat{y}))^2$$

معمولاً برای Targetهای:

Non-negative Right-skewed

مفید است.

چرا Log Transform؟

اگر Target:

10 100 1000 100000

باشد، MSE خطاهای بزرگ را بسیار dominate می‌کند.

MSLE فضای Log را بررسی می‌کند.

پس بیشتر به Relative Differences حساس می‌شود تا Absolute Differences.

مثال

فرق:

10 → 20

و:

1000 → 2000

از نظر نسبت تقریباً مشابه‌اند:

$$\times 2$$

MSLE این نوع تفاوت را بهتر منعکس می‌کند.

38. محدودیت MSLE

به دلیل:

$$\log(1 + y)$$

Target باید معمولاً:

$$y \ge 0$$

باشد.

برای Targetهای منفی مناسب نیست.

39. RMSLE

$$RMSLE = \sqrt{\frac{1}{N} \sum (\log(1 + y) - \log(1 + \hat{y}))^2}$$

مثل RMSE است ولی در فضای Log.

40. MAE vs MSE vs RMSE

MetricRobustnessOutlierUnit
MAEزیادکمتر حساسOriginal
MSEکمبسیار حساسSquared
RMSEکمحساسOriginal

41. MAPE vs sMAPE vs MSLE/RMSLE

MAPE

برای:

Relative percentage error

اما مشکل:

y ≈ 0
sMAPE

برای:

Relative error با denominator متقارن‌تر

اما همچنان مشکلات نزدیک صفر دارد.

MSLE/RMSLE

برای:

Multiplicative / relative-scale errors

خصوصاً Targetهای non-negative و skewed.

42. Metric Selection بر اساس Business Objective

این مهم‌ترین قسمت این فصل است.

نباید بگویی:

«برای Classification همیشه F1 استفاده می‌کنم.»

یا:

«برای Regression همیشه RMSE.»

این پاسخ Senior نیست.

مثال 1 — Fraud Detection

فرض کن:

Fraud = rare

هدف:

Fraud واقعی را از دست ندهیم.

پس:

Recall PR-AUC Fβ with β>1

ممکن است مهم باشند.

اما اگر Block کردن Customer هزینه زیادی داشته باشد:

Precision Precision@Recall Expected Cost

مهم‌تر می‌شوند.

43. Cost Matrix

فرض کن:

False Positive = $5 False Negative = $500

آنگاه:

FN

100 برابر گران‌تر است.

پس چرا باید:

Accuracy

را Metric اصلی کنیم؟

منطقی نیست.

44. Expected Cost

می‌توانی هزینه را صریح تعریف کنی:

$$ExpectedCost = C_{FP} P(FP) + C_{FN} P(FN)$$

در عمل می‌توانی آن را روی تعداد نمونه‌ها محاسبه کنی:

$$TotalCost = C_{FP} \cdot FP + C_{FN} \cdot FN$$

این گاهی از F1 بسیار Business-relevantتر است.

45. Medical Screening

هدف:

بیماری واقعی را از دست نده.

پس:

Recall / Sensitivity

اهمیت بالایی دارد.

ولی بعداً:

Specificity

هم اهمیت دارد، چون False Positive زیاد باعث آزمایش‌های اضافی می‌شود.

46. Spam Detection

اگر False Positive خیلی بد باشد:

ایمیل سالم را Spam تلقی کنیم.

پس:

Precision

می‌تواند مهم‌تر از Recall باشد.

47. Search Engine

در Search:

Precision@K Recall@K MAP NDCG MRR

معمولاً مناسب‌ترند.

حتی اگر Classification Model داشته باشی، Accuracy معیار طبیعی Search نیست.

48. Recommendation System

مثلاً:

Top-10 recommendations

می‌خواهی بدانیم:

آیا آیتم‌های مرتبط در Top 10 قرار گرفته‌اند؟

پس:

Recall@K Precision@K NDCG@K MAP@K Hit Rate@K

مفیدند.

49. Regression — Business Choice

فرض کن قیمت را پیش‌بینی می‌کنی.

اگر:

همه خطاها تقریباً اهمیت مشابه دارند.

MAE مناسب است.

اگر:

خطاهای بزرگ خیلی پرهزینه‌اند.

RMSE مناسب‌تر است.

اگر:

Relative error مهم‌تر از Absolute error است.

MAPE/sMAPE یا Log-based metrics ممکن است مناسب‌تر باشند.

50. مثال Revenue Forecasting

اگر:

Revenue = $10,000

باشد، خطای:

$1,000

خیلی مهم است.

اما برای:

Revenue = $10,000,000

خطای:

$1,000

ممکن است ناچیز باشد.

پس Absolute Error شاید Metric مناسبی نباشد و Relative Error یا Log-based Evaluation بهتر باشد.

51. Metric و Threshold

Metrics مختلف به Threshold حساس‌اند.

مثلاً:

Precision, Recall, F1, Specificity, Balanced Accuracy

همگی می‌توانند با تغییر:

Threshold

تغییر کنند.

52. ROC-AUC و PR-AUC

بر خلاف Threshold Metrics:

ROC-AUC و PR-AUC

عملکرد را در طیف Thresholdهای مختلف خلاصه می‌کنند.

ولی در نهایت اگر سیستم یک تصمیم binary می‌گیرد:

باید Threshold را با Business Objective تعیین کنی.

53. مثلاً مدل Fraud

Model:

P(Fraud)

می‌دهد.

سه Threshold:

0.2 → Recall بالا 0.5 → balanced 0.8 → Precision بالا

هیچ Threshold جادویی وجود ندارد.

54. Precision-Recall Tradeoff

معمولاً:

Threshold ↓ → Positive predictions ↑ → Recall ↑ → Precision ممکن است ↓

و:

Threshold ↑ → Positive predictions ↓ → Precision ممکن است ↑ → Recall ↓

البته رفتار دقیق به Score Distribution وابسته است.

55. Metric و Calibration

فرض کن:

Model A: AUC = 0.95

و:

Model B: AUC = 0.93

ولی:

Model A: poor probability calibration

و:

Model B: excellent calibration

اگر از Probability برای:

Expected Loss, Risk Scoring, Pricing, Credit Decision

استفاده می‌کنی، AUC بالاتر الزاماً به معنی Model بهتر نیست.

56. Ranking Metrics

برای Search/Recommendation، Metrics بسیار مهم دیگری هم وجود دارند که در لیست فعلی نبودند:

Precision@K

از Top-K چند مورد Relevant هستند؟

$$Precision@K = \frac{\#Relevant in TopK}{K}$$
Recall@K

از تمام Relevantها، چند تا در Top-K آمده‌اند؟

$$Recall@K = \frac{\#Relevant in TopK}{\#AllRelevant}$$
NDCG@K

به ترتیب Ranking اهمیت می‌دهد.

Relevant item در Rank 1 ارزش بیشتری از Rank 10 دارد.

57. چرا Metric باید با Business Objective هماهنگ باشد؟

فرض کن دو مدل داریم:

MetricModel AModel B
Accuracy99.0%98.5%
Recall40%95%
Precision90%50%

کدام بهتر است؟

پاسخ:

بستگی به Business دارد.

اگر Miss کردن Positive فاجعه باشد:

Model B

ممکن است بهتر باشد.

اگر False Alarm خیلی پرهزینه باشد:

Model A

ممکن است بهتر باشد.

58. یک Framework حرفه‌ای برای انتخاب Metric

به جای حفظ کردن Metricها، این 5 سؤال را بپرس:

  1. چه چیزی را می‌خواهم درست پیدا کنم؟ (Positive؟ Negative؟ Ranking؟ Magnitude؟ Probability؟)
  2. کدام نوع خطا گران‌تر است؟ (\(C_{FP}\) یا \(C_{FN}\))
  3. آیا Class Imbalance دارم؟ (اگر بله: Accuracy معمولاً باید با احتیاط استفاده شود.)
  4. آیا Probability مهم است؟ (اگر بله: Log Loss, Calibration, Brier Score مهم‌تر می‌شوند.)
  5. آیا Ranking مهم است؟ (اگر بله: NDCG@K, MAP@K, MRR, Precision@K, Recall@K)

61. اشتباهات رایج Senior Interview

  • ❌ «Accuracy همیشه بهترین Metric است.» (غلط.)
  • ❌ «F1 همیشه برای Imbalanced Data بهترین است.» (غلط. گاهی PR-AUC, MCC, Balanced Accuracy, Recall, Expected Cost مناسب‌ترند.)
  • ❌ «AUC=0.95 یعنی مدل 95٪ درست پیش‌بینی می‌کند.» (غلط. AUC Accuracy نیست.)
  • ❌ «R²=0.8 یعنی مدل 80٪ داده را پیش‌بینی کرده.» (غلط. R² یک معیار مبتنی بر Reduction in Squared Error نسبت به Mean Baseline است.)
  • ❌ «MAPE همیشه بهترین Metric Forecasting است.» (غلط. Zero/near-zero و بعضی رفتارهای خاص آن مشکل‌سازند.)
  • ❌ «Macro F1 برای هر مسئله Multi-Class بهتر است.» (غلط. اگر Classهای بزرگ‌تر Business importance بیشتری دارند، Weighted یا حتی Metricهای Class-specific ممکن است مناسب‌تر باشند.)

Metric را از مدل انتخاب نکن؛ از تصمیم Business انتخاب کن.

«XGBoost دارم، چه Metricی بزنم؟»

68. اگر بخواهی جواب مصاحبه‌ای خیلی حرفه‌ای بدهی

اگر بپرسند:

How do you choose an evaluation metric for a machine learning model?

جواب Senior:

I don't choose the metric based only on the model type. I start from the business objective and the cost of different errors. Then I consider the target structure, class imbalance, whether ranking or calibrated probabilities are required, and whether a decision threshold will be applied. For imbalanced classification, I may prioritize PR-AUC, recall, precision, Fβ, MCC, or cost-based metrics rather than accuracy. For regression, I choose between MAE, RMSE, log-based or percentage metrics based on the error distribution, outlier sensitivity, and whether absolute or relative error matters. I also evaluate the metric on a validation or cross-validation setup that reflects the production data distribution.

🎯 خلاصه‌ی نهایی

برای Senior ML، این جدول را باید واقعاً مفهومی بلد باشی:

Classification │ ├── Accuracy │ ├── Precision ← FP مهم │ ├── Recall ← FN مهم │ ├── Specificity ← TN important │ ├── F1 ← Precision + Recall │ ├── Fβ ← قابل تنظیم │ ├── Macro/Micro/Weighted ← Multi-Class │ ├── ROC-AUC ← Ranking / TPR-FPR │ ├── PR-AUC ← Rare Positive │ ├── Log Loss ← Probability Quality │ ├── MCC ← Robust association / imbalance │ ├── Kappa ← Agreement beyond chance │ ├── Balanced Accuracy ← Class-balanced recall │ └── Top-K ← Correct label in top K
Regression │ ├── MAE ← Robust absolute error │ ├── MSE ← Strong penalty for large errors │ ├── RMSE ← Same unit + outlier sensitive │ ├── R² ← Relative improvement over mean baseline │ ├── Adjusted R² ← Penalize unnecessary predictors │ ├── MAPE ← Relative percentage error │ ├── sMAPE ← Relative error / symmetric denominator │ ├── MSLE ← Log-space error │ └── RMSLE ← RMSE in log-space

و در نهایت مهم‌ترین زنجیره:

$$Business Objective \rightarrow Error Costs \rightarrow Metric \rightarrow Threshold \rightarrow Model Selection \rightarrow Production Monitoring$$

یعنی Metric فقط یک عدد برای گزارش در پایان Training نیست؛ Metric باید نشان دهد مدل چقدر به هدف واقعی سیستم نزدیک شده است.
